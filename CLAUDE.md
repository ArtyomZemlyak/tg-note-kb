# tg-note-kb

База знаний (Obsidian-style), наполняемая через Telegram-заметки и агентные сессии. Заметки — markdown-файлы под `topics/`, со ссылками `[[wiki-links]]`, разделом `Связи с другими темами` и `Источники`/`Ссылки на источники`. Единый плоский индекс всех заметок — `index.md` в корне (формат: `- [Заголовок](путь) - YYYY-MM-DD - тег`, дописывается в конец файла). Навигация для mkdocs (`topics/nav.md`, `mkdocs.yml`) генерируется скриптом `topics/generate_nav.py` — у него захардкожен путь `/app/knowledge_base/tg-note-kb/topics`, при локальном запуске нужно временно переопределить `base_path` (см. пример ниже), а не редактировать сам скрипт.

```python
import importlib.util
from pathlib import Path
spec = importlib.util.spec_from_file_location("generate_nav", "topics/generate_nav.py")
mod = importlib.util.module_from_spec(spec); spec.loader.exec_module(mod)
base_path = Path("topics").resolve()
nav = mod.generate_nav_recursive(base_path, base_path)
# see topics/generate_nav.py:print_nav for rendering, then write to topics/nav.md
```

## Регулярный ИИ-дайджест (research digest routine)

Периодическая задача сканирует arXiv/новости/веб по темам: LLM, ИИ-агенты, агенты для дата-сайенс/научных исследований, LLM в рекомендательных системах, поиск и retrieval, Physical AI. Каждый запуск — свежий агент без памяти о предыдущих запусках, поэтому процесс должен опираться только на состояние репозитория:

1. **Перед поиском** — прочитать `topics/ai/research_advances/digest_sources_log.md` (и при необходимости пробежаться по `index.md`), чтобы не заводить повторную заметку на источник (URL/arXiv ID), который уже был обработан в один из предыдущих запусков, даже если он снова всплыл в поисковой выдаче.
2. **Значимые единичные находки** (breakthrough/значительный инцидент/крупный релиз) получают отдельную заметку в подходящей теме (`topics/ai/security/`, `topics/ai/agents/`, `topics/ai/llm/` и т.д.), по структуре как у существующих заметок (`Краткое описание`, `Основные положения`, `Связи с другими темами`, `Источники`).
3. **Остальные находки** сводятся в одну заметку-дайджест `topics/ai/research_advances/ai_digest_YYYY_MM_DD.md` (дата — день запуска), по образцу `neurodigest_91.md` и `ai_digest_2026_07_03.md`, со ссылками на отдельные заметки из п.2.
4. **После записи** — обязательно:
   - дописать в `topics/ai/research_advances/digest_sources_log.md` секцию `### YYYY-MM-DD` со списком всех рассмотренных источников (и добавленных, и отклонённых — с причиной), формат описан в самом файле;
   - дописать новые заметки в конец `index.md` в общем формате;
   - перегенерировать `topics/nav.md` (см. пример выше), чтобы новые файлы попали в навигацию mkdocs.
5. Если прямой fetch `arxiv.org` блокируется (403/сетевая политика), использовать зеркало **`export.arxiv.org`** (например `https://export.arxiv.org/abs/<id>`) — оно, как правило, доступно, когда основной домен заблокирован прокси.
6. Если за окно поиска не нашлось ничего значимого по теме — честно фиксировать это в дайджесте (и в логе источников), а не растягивать нерелевантные/старые находки, чтобы не засорять базу знаний.
