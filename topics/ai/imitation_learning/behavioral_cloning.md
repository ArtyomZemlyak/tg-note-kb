# Поведенческое клонирование (Behavioral Cloning)

## Краткое описание

Поведенческое клонирование (Behavioral Cloning, BC) — это метод обучения с подражанием (imitation learning), который обучает агентов воспроизводить действия эксперта, используя супервизированное обучение на парах состояние-действие. Это один из основных подходов для обучения нейронных сетей на реплеях людей в играх и других задачах последовательного принятия решений.

## Основное описание

Поведенческое клонирование представляет собой парадигму машинного обучения, в которой система обучается выполнять задачу, пытаясь имитировать поведение человека-эксперта, выполняющего эту задачу. Метод использует супервизированное обучение для тренировки политики (policy), которая отображает наблюдения (состояния среды) в действия, аналогичные действиям эксперта.

### Ключевые характеристики

- **Супервизированный подход**: BC формулируется как задача супервизированного обучения, где входные данные — это наблюдения (например, скриншоты экрана), а целевые метки — действия эксперта
- **Пары состояние-действие**: Обучающие данные состоят из пар (s, a), где s — состояние среды, a — действие эксперта в этом состоянии
- **Стационарная политика**: Обучается детерминированная или стохастическая политика π(s) → a, которая не меняется во времени
- **Прямое предсказание**: Модель напрямую предсказывает действия на основе текущих наблюдений

## Архитектура и методы обучения

### Входные данные

Для игр и симуляторов входные данные обычно включают:

1. **Визуальные наблюдения**:
   - Скриншоты игрового процесса (64 FPS и выше)
   - Обработанные изображения (края, оптический поток)
   - Частичные карты местности

2. **История действий**:
   - Последние N действий эксперта
   - Временные последовательности команд

3. **Дополнительные признаки**:
   - Скорость, позиция, ориентация
   - Состояние игровых объектов
   - Тактическая информация

### Архитектуры нейронных сетей

#### Сверточные сети (CNN)
Для обработки визуальных входов:
- Извлечение пространственных признаков из скриншотов
- Иерархическое представление визуальных паттернов
- Устойчивость к небольшим вариациям в изображениях

#### Рекуррентные сети (RNN/LSTM/GRU)
Для учета временной зависимости:
- Память о предыдущих действиях
- Контекстуальное понимание ситуации
- Предсказание последовательностей действий

#### Трансформеры
Современный подход:
- Attention механизмы для важных регионов
- Параллельная обработка последовательностей
- Долгосрочные зависимости

### Функции потерь

1. **Кросс-энтропия** (для дискретных действий):
   ```
   L = -Σ log P(a_expert | s)
   ```

2. **MSE/MAE** (для непрерывных действий):
   ```
   L = ||a_predicted - a_expert||²
   ```

3. **Регуляризация**:
   - Dropout для предотвращения переобучения
   - L2-регуляризация весов
   - Data augmentation для устойчивости

## Проблемы и ограничения

### Каскадное накопление ошибок

Основная проблема поведенческого клонирования — компounding errors (каскадное накопление ошибок):

- Ошибка классификатора с вероятностью ε под распределением состояний эксперта может привести к T²ε ошибкам на горизонте T шагов
- Как только обучающийся делает ошибку, он может столкнуться с совершенно другими наблюдениями, чем те, которые встречались в демонстрациях эксперта
- Это приводит к каскадному накоплению ошибок и резкому ухудшению производительности

### Нарушение предположения i.i.d.

Традиционное статистическое обучение предполагает независимые и одинаково распределенные (i.i.d.) данные. В поведенческом клонировании:

- Будущие наблюдения зависят от предыдущих предсказаний (действий)
- Распределение входных данных меняется в зависимости от политики обучающегося
- Это приводит к poor performance как в теории, так и на практике

### Ограниченное покрытие пространства состояний

- Модель обучается только на состояниях, посещенных экспертом
- Не может корректно реагировать на новые, невиданные ситуации
- Требует большого количества разнообразных демонстраций

## Продвинутые техники

### Data Augmentation

Для улучшения обобщающей способности:

- **Визуальные аугментации**: случайные кропы, повороты, изменения яркости/контраста
- **Временные аугментации**: изменение скорости воспроизведения
- **Шум**: добавление гауссовского шума к входам

### Ensemble Methods

Использование ансамблей моделей:

- Усреднение предсказаний нескольких моделей
- Снижение дисперсии предсказаний
- Оценка неопределенности через разброс предсказаний

### Confidence-based Filtering

Фильтрация предсказаний по уверенности:

- Отбраковка предсказаний с низкой уверенностью
- Переключение на безопасную политику в неопределенных ситуациях
- Комбинация с другими методами (RL, планирование)

## Применение в играх

### Trackmania

Для обучения на реплеях Trackmania:

1. **Сбор данных**:
   - Запись скриншотов с частотой 64 FPS
   - Логирование нажатий клавиш (газ, тормоз, повороты, дрифт)
   - Синхронизация кадров и действий

2. **Предобработка**:
   - Нормализация изображений
   - Извлечение ключевых регионов (трасса впереди)
   - Кодирование действий (one-hot или embedding)

3. **Архитектура**:
   - CNN для обработки изображений
   - LSTM для истории действий
   - Fully-connected слои для предсказания

4. **Дообучение**:
   - Fine-tuning для конкретной трассы
   - Transfer learning между похожими треками
   - Комбинация с RL для улучшения производительности

### Другие игры

- **Super Mario Bros**: Обучение прохождению уровней
- **Super Tux Kart**: Управление картингом в 3D
- **Minecraft**: Навигация и строительство
- **Atari игры**: Классический бенчмарк для RL

## Связь с другими методами

### Обучение с подкреплением (RL)

BC часто используется как этап инициализации для RL:

- **Предобучение**: BC для инициализации политики перед RL
- **Комбинирование**: BC loss + RL loss в многозадачном обучении
- **Дистилляция**: Извлечение политики из RL-агента через BC

### DAGGER (Dataset Aggregation)

Итеративный алгоритм для решения проблемы накопления ошибок:

- Агрегация данных из выполнений текущей политики
- Разметка состояний экспертом
- Переобучение политики на расширенном датасете
- Гарантирует линейный рост ошибок вместо квадратичного

### GAIL (Generative Adversarial Imitation Learning)

Состязательный подход:

- Генератор пытается обмануть дискриминатор
- Дискриминатор отличает эксперта от обучающегося
- Не требует явного извлечения функции вознаграждения

## Практические рекомендации

### Для обучения на реплеях Trackmania

1. **Подготовка данных**:
   - Соберите минимум 10-50 часов реплеев от сильных игроков
   - Обеспечьте разнообразие трасс и стилей вождения
   - Синхронизируйте кадры и действия с высокой точностью

2. **Архитектура модели**:
   - Используйте CNN (ResNet/EfficientNet backbone) для изображений
   - Добавьте LSTM/GRU для учета последовательности действий
   - Включите attention механизмы для важных регионов трассы

3. **Обучение**:
   - Начните с предобучения на больших датасетах (если доступны)
   - Используйте data augmentation для устойчивости
   - Применяйте early stopping для предотвращения переобучения

4. **Дообучение и интеграция**:
   - Fine-tuning на конкретных трассах
   - Комбинация с RL (PPO, SAC) для улучшения
   - Рассмотрите дистилляцию в более легкую модель для deployment
