# Обучение с подражанием (Imitation Learning)

## Краткое описание

Обучение с подражанием (Imitation Learning, IL) — это парадигма машинного обучения, в которой агент обучается выполнять задачи, наблюдая за демонстрациями эксперта. В отличие от обучения с подкреплением, где агент учится методом проб и ошибок, IL позволяет напрямую извлекать политику поведения из примеров оптимального поведения.

## Основное описание

Обучение с подражанием представляет собой общий класс методов, где цель состоит в том, чтобы научиться выполнять задачу, наблюдая за демонстрациями эксперта. Это особенно полезно в задачах, где:

- Функция вознаграждения неизвестна или сложна для определения
- Прямое обучение с подкреплением требует слишком много взаимодействий со средой
- Экспертные демонстрации легко доступны (например, реплеи людей в играх)

### Ключевые концепции

- **Экспертная политика (π*)**: Политика, которой следует эксперт (человек или оптимальный контроллер)
- **Обучающаяся политика (π)**: Политика, которую мы обучаем имитировать эксперта
- **Демонстрации**: Пары (состояние, действие) или траектории, записанные от эксперта
- **Суррогатная функция потерь**: Функция, измеряющая различие между политикой обучающегося и эксперта

## Основные подходы

### 1. Поведенческое клонирование (Behavioral Cloning)

Самый простой подход к IL:

- Формулируется как задача супервизированного обучения
- Обучает политику π(s) → a на парах состояние-действие от эксперта
- **Преимущества**: Простота реализации, эффективность
- **Недостатки**: Каскадное накопление ошибок, нарушение i.i.d. предположения

Подробнее: [[behavioral_cloning.md]]

### 2. DAGGER (Dataset Aggregation)

Итеративный алгоритм для решения проблемы накопления ошибок:

**Алгоритм**:
1. Инициализировать политику π₁ на демонстрациях эксперта
2. Для каждой итерации i:
   - Выполнить текущую политику πᵢ для сбора новых состояний
   - Получить действия эксперта для этих состояний
   - Добавить новые данные в обучающий набор
   - Переобучить политику на агрегированном наборе данных
3. Вернуть финальную политику

**Гарантии**:
- Гарантирует линейный рост ошибок O(Tε) вместо квадратичного O(T²ε)
- Обучает стационарную детерминированную политику
- Не имеет свободных параметров кроме базового алгоритма обучения

**Применение**:
- Обучение управлению автомобилем в 3D-гонках (Super Tux Kart)
- Обучение игре в Super Mario Bros по изображениям
- Задачи последовательной разметки (OCR, NER)

### 3. GAIL (Generative Adversarial Imitation Learning)

Состязательный подход к IL:

- Использует архитектуру Generative Adversarial Networks (GAN)
- **Генератор**: Политика обучающегося, пытающаяся обмануть дискриминатор
- **Дискриминатор**: Различает демонстрации эксперта и обучающегося
- Не требует явного извлечения функции вознаграждения

**Преимущества**:
- Может превзойти эксперта в некоторых задачах
- Не требует явного указания функции вознаграждения
- Хорошо работает с непрерывными пространствами действий

**Недостатки**:
- Сложнее в обучении (нестабильность GAN)
- Требует больше вычислительных ресурсов

### 4. Обратное обучение с подкреплением (Inverse Reinforcement Learning)

Извлечение функции вознаграждения из демонстраций:

- Наблюдает демонстрации эксперта
- Пытается восстановить функцию вознаграждения, которую оптимизирует эксперт
- Затем использует RL для обучения оптимальной политики

**Применение**:
- Робототехника: обучение сложным движениям
- Автономное вождение: извлечение предпочтений водителя
- Игры: понимание стратегии эксперта

## Сравнение подходов

| Метод | Тип политики | Итеративный | Покрытие состояний | Сложность |
|-------|--------------|-------------|-------------------|-----------|
| BC | Стационарная | Нет | Ограниченное | Низкая |
| DAGGER | Стационарная | Да | Широкое | Средняя |
| GAIL | Стационарная | Да | Широкое | Высокая |
| IRL | Зависит от RL | Да | Широкое | Очень высокая |

## Проблемы и решения

### Проблема компounding errors

**Описание**: Ошибки накапливаются экспоненциально с длиной горизонта

**Решения**:
- DAGGER: итеративное расширение датасета
- Data augmentation: увеличение покрытия пространства состояний
- Ensemble methods: усреднение предсказаний

### Проблема ограниченного покрытия

**Описание**: Эксперт посещает только часть пространства состояний

**Решения**:
- Сбор разнообразных демонстраций
- Активное обучение: запрос разметки для неопределенных состояний
- Комбинация с RL: дообучение через взаимодействие со средой

### Проблема мультимодальности

**Описание**: В одном состоянии может быть несколько правильных действий

**Решения**:
- Стохастические политики
- Conditional VAEs для моделирования распределения действий
- Mixture of Experts архитектуры

## Применение в играх и симуляторах

### Trackmania и гоночные симуляторы

**Специфика**:
- Непрерывное управление (газ, тормоз, руль)
- Визуальные входы (скриншоты 64+ FPS)
- Временные зависимости (последовательности действий)

**Подход**:
1. Сбор реплеев от сильных игроков
2. Предобработка: нормализация изображений, кодирование действий
3. Архитектура: CNN + LSTM для spatiotemporal признаков
4. Обучение: BC с MSE loss для непрерывных действий
5. Дообучение: Fine-tuning с RL (PPO, SAC)

### Другие применения

- **Супер Марио**: Прохождение уровней по демонстрациям
- **Minecraft**: Навигация, строительство, крафт
- **StarCraft II**: Стратегическое управление
- **Dota 2**: Командное взаимодействие

## Интеграция с обучением с подкреплением

### Предобучение через BC

Использование BC для инициализации RL:

```
1. Собрать демонстрации эксперта
2. Обучить политику через BC
3. Использовать BC политику как начальную для RL
4. Дообучить через PPO/SAC/другой RL алгоритм
```

**Преимущества**:
- Быстрая сходимость RL
- Избегание опасных действий на ранних этапах
- Лучшее исследование пространства

### Комбинированные потери

Одновременная оптимизация BC и RL потерь:

```
L_total = L_RL + λ * L_BC
```

**Преимущества**:
- Сохранение экспертного поведения
- Улучшение через RL
- Контролируемый баланс через λ

### Дистилляция политик

Извлечение политики из RL-агента:

```
1. Обучить сильного RL-агента
2. Собрать демонстрации от RL-агента
3. Обучить компактную модель через BC
4. Deploy дистиллированную модель
```

## Практические рекомендации

### Для обучения на реплеях Trackmania

1. **Сбор данных**:
   - Минимум 10-50 часов реплеев
   - Разнообразие трасс и игроков
   - Точная синхронизация кадров и действий

2. **Предобработка**:
   - Resize изображений до 84x84 или 128x128
   - Нормализация пикселей [0, 1] или [-1, 1]
   - Stack последних 4 кадров для temporal информации
   - One-hot encoding действий

3. **Архитектура**:
   ```
   Input: [84x84x4 image, 10-dim action history]
   ↓
   CNN: Conv2d(4, 32, 8, 4) → ReLU → Conv2d(32, 64, 4, 2) → ReLU → Conv2d(64, 64, 3, 1) → ReLU
   ↓
   Flatten + FC: 512 units → ReLU
   ↓
   LSTM: 256 hidden units (для action history)
   ↓
   Output: FC → Softmax (discrete) / Tanh (continuous)
   ```

4. **Обучение**:
   - Optimizer: Adam (lr=1e-4)
   - Batch size: 64-256
   - Gradient clipping: 1.0
   - Early stopping по validation loss

5. **Валидация**:
   - Hold-out набор реплеев (10-20%)
   - Метрики: accuracy действий, similarity траекторий
   - Визуальная инспекция предсказаний

6. **Дообучение**:
   - Заморозить CNN слои
   - Fine-tuning FC и LSTM на конкретных трассах
   - Постепенное размораживание при необходимости
