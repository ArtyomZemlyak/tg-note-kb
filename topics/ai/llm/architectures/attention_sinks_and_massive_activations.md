# Attention Sinks и Massive Activations в трансформерах

**Attention Sinks** и **Massive Activations** — два феномена, которые стабильно наблюдаются в decoder-only трансформерах по мере роста масштаба моделей. Долгое время они рассматривались как связанные явления, но недавние исследования показали, что их совместное появление — это архитектурный артефакт, а не функциональная необходимость.

## TL;DR

**Что сделали:** Исследователи из NYU механистически разделили два феномена:
- **Massive Activations** (массивные активации) — экстремальные выбросы в нескольких скрытых каналах
- **Attention Sinks** (поглотители внимания) — токены, забирающие непропорционально большую массу внимания

**Почему это важно:** Работа доказывает, что пересечение этих феноменов — случайный артефакт pre-norm архитектуры трансформера. Изменив логику нормализации или добавив динамический гейтинг, можно полностью устранить массивные активации без ущерба для качества, что открывает путь к инференсу в сверхнизком разрешении (FP4/INT4) и радикальному сокращению KV-кэша.

---

## 1. Что такое Massive Activations и Attention Sinks

### Massive Activations (Массивные активации)

**Массивные активации** — это экстремальные выбросы магнитуды в специфических скрытых каналах трансформера, которые превышают типичные значения в сотни раз.

**Характеристики:**
- Появляются только в **промежуточных слоях** сети
- Затрагивают **малое число каналов** (спайк-каналы)
-Affected каналы **всегда спайкуют вместе** с фиксированными межканальными соотношениями
- Появляются только в **малом числе токенов** (спайк-токены)

### Attention Sinks (Поглотители внимания)

**Attention Sinks** — это токены (часто первые токены последовательности или разделители), которые привлекают непропорционально большую массу внимания независимо от их семантической релевантности.

**Характеристики:**
- Наблюдаются во многих головах внимания и слоях
- Не зависят от семантики токена
- Критичны для стабильной генерации в streaming-режиме

## 2. Механизм возникновения Massive Activations

### 2.1. Квадратичный усилитель в SwiGLU

Основным источником массивных активаций является **feed-forward блок SwiGLU**. В режиме, близком к identity-гейтингу (когда SiLU ведёт себя почти линейно: `SiLU(x) ≈ x`), трансформацию можно аппроксимировать как **направленный квадратичный усилитель**.

Для нормализованного входа `h_norm` выход координаты `k`:

```
F_ffn(h_norm)_k ≈ h_norm^T * S_k * h_norm
```

где `S_k = 0.5 * (U_k + U_k^T)`, а `U_k` — матрица, собранная из внешних произведений весовых проекций (up, gate, down).

### 2.2. Жизненный цикл токена

**Ранние слои (Step-up блоки):**
- Первые токены могут обращать внимание только на себя
- Ранние слои внимания схлопываются в статичное линейное отображение
- Репрезентация первого токена выравнивается по триггерному направлению `s_*`
- Один-два ранних feed-forward блока **квадратично раздувают** выровненные каналы

**Промежуточные слои (Residual accumulation):**
- В pre-norm трансформере скрытая репрезентация на слое `i`:
  ```
  H_{i+1} = H_i + F_i(RMSNorm(H_i))
  ```
- Резидуальный стрим — **неограниченный аддитивный аккумулятор**
- Экстремальные значения, инжектированные ранними блоками, **персистируют** через все последующие блоки
- Промежуточные блоки вносят минимальную аддитивную дисперсию в спайк-каналы

**Поздние слои (Step-down блоки):**
- Ближе к концу сети один-два блока нейтрализуют спайки
- Инжектируют экстремальные значения с **противоположным знаком**

### 2.3. Спектральный анализ

Спектральный анализ каналов-выбросов показывает:
- В матрице `S_k` доминирует **одно гигантское собственное значение λ_***
- Соответствующий собственный вектор `s_*` — это **триггерное направление**
- Когда входной вектор выравнивается с `s_*`, блок усиливает **квадрат проекции** на λ_*
- Результат: совершенно неадекватные значения вбрасываются в residual stream

## 3. Механизм возникновения Attention Sinks

### 3.1. Роль RMSNorm

Превращение в attention sink происходит, когда раздутый вектор попадает в слой **RMSNorm** очередного блока внимания:

```
RMSNorm(h) = sqrt(d_model) * h / ||h||
```

**Что происходит:**
1. Магнитуда каналов со спайками **подавляет все остальные координаты**
2. Знаменатель L2-нормы `||h||` **улетает в космос**
3. Операция нормализации **сплющивает все "нормальные" каналы почти до нуля**
4. Нормализованное состояние **коллапсирует в разреженный, почти константный вектор**:
   ```
   h_norm ≈ Σ (h_norm_i * e_i)
   ```
5. Любая специфичная для токена семантика **полностью стирается**

### 3.2. Формирование sink-ключей

Когда почти константный вектор умножается на матрицу ключей `W_K`:
- Полученный ключ оказывается **заперт в тесном низкоразмерном подпространстве**
- Это подпространство **фиксировано** для всех sink-токенов

### 3.3. Sink-головы внимания

Определённые головы внимания (**sink-головы**) ориентируют своё query-подпространство так, чтобы оно всегда было **ближе к фиксированному подпространству sink-ключей**, чем к динамическим ключам других токенов.

**Результат:**
- Постоянная пространственная близость генерирует **гигантские стабильные разрывы в логитах**
- Это создаёт идеальную "мусорную корзину" для сброса избыточной массы внимания

## 4. Разделение феноменов: экспериментальные доказательства

Исследователи предобучили модель на **7B параметров** с нуля на датасете **DCLM** [[doc_1773720923_af8fc884_arxiv_2406.11794.pdf]](../../media/doc_1773720923_af8fc884_arxiv_2406.11794.pdf) с оптимизатором **AdamW** [[doc_1773720923_9d5af489_arxiv_1711.05101.pdf]](../../media/doc_1773720923_9d5af489_arxiv_1711.05101.pdf), проводя хирургические вмешательства в архитектуру.

### 4.1. Устранение Massive Activations при сохранении Attention Sinks

**Методы:**
1. **Изменение конфигурации нормализации** (например, post-block sandwich normalization)
2. **DynamicTanh (DyT)** — поэлементное отображение вместо нормализации [[doc_1773720923_406d285f_arxiv_2503.10622.pdf]](../../media/doc_1773720923_406d285f_arxiv_2503.10622.pdf)

**DynamicTanh формула:**
```
DyT(x) = γ * tanh(αx) + β
```
где `α` — обучаемый скаляр, `γ` и `β` — обучаемые поканальные параметры.

**Результат:**
- Сеть **физически теряет способность** бесконтрольно накапливать выбросы
- Массивные активации **исчезают как класс**
- Модель **успешно поддерживает высокую долю attention sinks**

**Вывод:** Массивные спайки — это лишь **один из возможных хаков** сети для получения константных репрезентаций, а не обязательное условие для синков.

### 4.2. Устранение Attention Sinks

**Метод:** Замена стандартного внимания на **динамический гейтинг**, обусловленный репрезентациями.

**Результат:**
- Модель учится **модулировать вклад каждой головы на лету**
- Доля синков **обваливается с 46.0% до 4.5%**
- Массивные активации тоже **испаряются** (приятный бонус)

**Вывод:** Модели больше не нужно искусственно сбрасывать внимание — она отказывается от стратегии синков.

## 5. Истинная роль Attention Sinks

### 5.1. Эксперимент с длиной последовательности

Авторы обнаружили ключевой инсайт, манипулируя длиной обучающей выборки:

**Условие:** Искусственное обрезание выборки так, чтобы модель **никогда не считала лосс на коротких текстах** (обучение строго на кусках >1024 токенов).

**Результат:** Доля синков **катастрофически падает до 13.0%**.

### 5.2. Функциональная суть

**Attention Sinks — это выученный inductive bias для отработки локальных зависимостей (short-range dependencies).**

**Механизм работы:**
- На **ранних слоях**, где дальний контекст ещё бесполезен, глобальному вниманию нужна **стабильная семантически пустая точка опоры**
- Sink работает как **локальный модулятор** для размазывания и разбавления влияния нерелевантных токенов
- Массивные активации — это просто **удачно подвернувшийся глобальный баг** (неявные параметры в residual stream), который сеть приспособила для создания стабильной точки

## 6. Влияние на индустрию

### 6.1. Квантизация

Массивные активации давно были **главным бутылочным горлышком для 8-битной квантизации** (LLM.int8() [[doc_1773720923_40da3ce2_arxiv_2208.07339.pdf]](../../media/doc_1773720923_40da3ce2_arxiv_2208.07339.pdf)).

**Новое понимание:**
- Проблема не в фундаментальных законах глубокого обучения
- Проблема в **конкретных неудачных архитектурных решениях**
- Переход на альтернативные нормализации (DynamicTanh) позволяет предобучать LLM **без массивных активаций by design**
- Прямой путь к инференсу в **FP4/INT4 без потери контекста**

### 6.2. StreamingLLM и KV-кэш

Симбиоз массивных активаций и attention sinks эксплуатировался фреймворками вроде **StreamingLLM** [[doc_1773720923_e8a7de67_arxiv_2309.17453.pdf]](../../media/doc_1773720923_e8a7de67_arxiv_2309.17453.pdf) для генерации бесконечного контекста.

**StreamingLLM подход:**
- Сохраняет **4 начальных токена** (attention sinks) + rolling KV cache для недавних токенов
- Позволяет обрабатывать до **4 миллионов токенов** без fine-tuning
- Работает с Llama-2, MPT, Falcon, Pythia

**Новые возможности:**
- Проекты типа **MiMo-V2-Flash** используют выучиваемые смещения (biases) для attention sinks
- **Радикальное сокращение размера KV-кэша** без потери качества

### 6.3. Теоретические основания

Старые теоретические работы [[doc_1773720923_804e29f1_arxiv_1911.07013.pdf]](../../media/doc_1773720923_804e29f1_arxiv_1911.07013.pdf) уже намекали, что ре-центрирование слоёв нормализации может плодить выбросы.

**Вклад текущей работы [[doc_1773720923_d58c589c_arxiv_2603.05498.pdf]](../../media/doc_1773720923_d58c589c_arxiv_2603.05498.pdf):**
- Первая **чёткая математическая модель** направленного квадратичного усилителя в SwiGLU
- **Окончательное доказательство**, что артефакты можно разделить на этапе предобучения без потери качества

## 7. Ограничения и открытые вопросы

### 7.1. Ограничения математической модели

- Вывод формул для квадратичного усилителя **жёстко завязан на допущении**, что блок SwiGLU работает в режиме, близком к identity
- На практике модели с **GeLU тоже выдают массивные спайки**
- Перенос математики на **безгейтовые архитектуры** потребует дополнительных выкладок

### 7.2. Непонятная магия градиентного спуска

Авторы блестяще расписали механику "повышающих" и "понижающих" блоков, но:
- **Почему оптимизатор всегда так надёжно расставляет** step-up блоки в начале сети?
- **Почему step-down блоки оказываются в самом конце?**
- Эта часть остаётся "слегка подёрнутой туманом"

---

## 8. Практические выводы для деплоя

### 8.1. Архитектурные рекомендации

**Для новых моделей:**
1. Рассмотреть **альтернативные нормализации** (DynamicTanh, sandwich normalization)
2. Исследовать **динамический гейтинг** вместо стандартного внимания
3. Использовать **выучиваемые смещения** для attention sinks

**Для существующих моделей:**
1. Использовать **StreamingLLM-подобные подходы** для длинного контекста
2. Применять **mixed-precision квантизацию** с учётом спайк-каналов
3. Реализовать **сложные алгоритмы вытеснения KV-кэша**

### 8.2. Ключевое послание

> **Проблема не в фундаментальных законах глубокого обучения, а в конкретных неудачных архитектурных решениях.**

Теперь мы точно знаем: можно предобучать LLM, в которых **массивных активаций не будет by design**. Это означает прямой путь к инференсу в сверхнизком разрешении без потери контекста.

**Пришло время перестать писать костыли для багов, которые можно просто не создавать.**

## Глоссарий

| Термин | Определение |
|--------|-------------|
| **Massive Activations** | Экстремальные выбросы магнитуды в специфических скрытых каналах трансформера |
| **Attention Sinks** | Токены, привлекающие непропорционально большую массу внимания независимо от семантики |
| **Spike Tokens** | Токены, проявляющие массивные активации |
| **Spike Channels** | Каналы, в которых наблюдаются экстремальные выбросы |
| **Sink Tokens** | Токены, работающие как поглотители внимания |
| **Sink Heads** | Головы внимания, ориентированные на sink-токены |
| **Step-up Blocks** | Ранние feed-forward блоки, генерирующие массивные активации |
| **Step-down Blocks** | Поздние блоки, нейтрализующие массивные активации |
| **Pre-norm** | Архитектурная конфигурация с нормализацией перед основным блоком |
| **Residual Stream** | Аддитивный поток, накапливающий выходы всех блоков трансформера |
| **DynamicTanh (DyT)** | Элемент-поэлементная операция `tanh(αx)` как замена нормализации |
