# Doc-to-LoRA: Мгновенная интернализация контекстов

## Краткое описание

**Doc-to-LoRA** — это система на основе гиперсетей, которая мгновенно преобразует документы в LoRA-адаптеры, позволяя LLM интернализировать фактологические знания без переобучения. Метод решает проблему долгосрочной памяти в LLM, позволяя моделям «запоминать» содержимое документов без удержания их в контекстном окне.

## Основная информация

### Архитектура: Амортизация стоимости обновлений

Doc-to-LoRA использует **двухфазный рабочий процесс**:

| Фаза | Стоимость | Частота | Что происходит |
|------|-----------|---------|----------------|
| **Мета-обучение** | Дорого | Один раз | Обучение гиперсети для генерации LoRA-обновлений из входов |
| **Развертывание** | Дешево | Часто | Вход → Гиперсеть → LoRA-адаптер (субсекундный прямой проход) |

### Конвейер Doc-to-LoRA

```
Документ → Замороженная LLM (кодирует активации) → Гиперсеть → LoRA-адаптер → Адаптированная LLM
```

**Процесс работы:**

1. Документ кодируется через **замороженную LLM** для извлечения послойных токенных активаций
2. **Perceiver-гиперсеть** (~309M параметров, 8 блоков кросс-внимания) отображает активации в LoRA-матрицы ранга 8
3. Сгенерированный LoRA применяется к базовой модели
4. Модель отвечает на запросы **без документа в контексте**

### Механизм чанкования (критичен для длинных документов)

- Документы разбиваются на непрерывные чанки
- Каждый чанк обрабатывается независимо одной и той же гиперсетью
- Каждый чанк производит LoRA ранга-r
- LoRA komponуются через **конкатенацию по размерности ранга**
- Эффективный ранг = r × K (где K = количество чанков)
- Позволяет обрабатывать документы **длиннее нативного контекстного окна модели**

## Технические детали

| Компонент | Спецификация |
|-----------|--------------|
| **Базовая модель** | Gemma-2-2b-it |
| **Гиперсеть** | Perceiver-based, ~309M параметров, 8 блоков кросс-внимания |
| **LoRA цель** | MLP слои, ранг 8 |
| **Режимы инференса** | Пакетный (быстрее) или Итеративный (меньше памяти) |
| **Время обновления** | < 1 секунды |
| **Контекст обучения** | 32-256 токенов (но обобщается на 32K+) |

## Ключевые возможности

### Обход контекстного окна

- Достижение почти идеальной точности на контекстах до **32K-40K токенов**
- Обучение только на последовательностях из **256 токенов**
- Zero-shot обобщение на документы длиннее обучающих примеров

### Эффективность памяти

| Метрика | Doc-to-LoRA | Традиционная контекстная дистилляция |
|---------|-------------|--------------------------------------|
| **Время обновления** | <1 секунды | 40-100+ секунд |
| **Память (SQuAD)** | ~1 GB | ~1 GB (oracle), 40+ GB (generated-query) |
| **Память (128K документ)** | <50 MB | 12+ GB |
| **Качество** | 83.5% от upper bound full-context | Выше, но намного медленнее |

### Поддержка визуальной информации

- Может кодировать визуальную информацию через VLM (Gemma-3-4b-it) в текстовую модель
- **75.03% точности** на Imagenette
- Текстовая модель отвечает на вопросы об изображениях через VLM-кодирование

## Применение

| Сценарий использования | Преимущество |
|------------------------|--------------|
| **Приватный Q&A по документам** | Интернализация один раз, многократные запросы без накладных расходов контекста |
| **Анализ политик/отчетов** | Не нужно перечитывать длинные документы для каждого запроса |
| **Долгоконтекстный retrieval** | Доступ к информации за пределами нативного контекстного окна |
| **Визуальный Q&A** | Текстовые модели могут отвечать на вопросы об изображениях через VLM |
| **Персистентная память** | Сохранение знаний между сессиями без переноса контекста |

## Преимущества

### Эффективность

- **Базовая модель остается замороженной** — никаких изменений весов ядра модели
- **Модульные адаптеры** — хранение, замена и потенциальная композиция нескольких адаптеров
- **Амортизированные затраты** — оплата мета-обучения один раз, дешевая генерация многих адаптеров
- **Низкая задержка развертывания** — субсекундная генерация адаптера

### Память

- Интернализированные знания используют **<50 MB** (константа независимо от длины документа)
- В сравнении с **12+ GB** для 128K-токенного контекста

## Ограничения

1. **Дорогое мета-обучение**: Требует дни или недели на нескольких GPU заранее
2. **Не бесплатный обед**: Существуют компромиссы между скоростью, качеством и обобщением
3. **Реконструкция vs. Обобщение**: Воспроизведение известных адаптеров ≠ робастное описание-в-LoRA отображение
4. **Компромисс VLM-кодирования**: Использование VLM как контекстного энкодера негативно влияет на текстовый QA
5. **Разрыв в качестве**: Не полностью соответствует качеству oracle контекстной дистилляции (83.5-85% vs. 90% относительной точности)
