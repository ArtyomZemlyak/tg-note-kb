# Neural Thickets: Нейронные Заросли и RandOpt

## Описание

**Neural Thickets** (Нейронные Заросли) - это концепция, описывающая феномен высокой плотности task-specific экспертов в окрестности весов хорошо предобученных больших языковых моделей. Концепция предложена в работе Gan & Isola (2026) и объясняет, почему случайное угадывание весов становится эффективным методом пост-обучения для крупных моделей.

**RandOpt** (Random Optimization) - полностью параллельный метод пост-обучения, основанный на случайной выборке пертурбаций весов и ансамблировании предсказаний через majority vote. Метод конкурентоспособен с PPO, GRPO и ES при значительно меньшем времени обучения.

## Ключевые концепции

### Режим "Иголка в стоге сена" vs Режим "Заросли"

**Малые модели** (до ~1B параметров):
- Живут в режиме **"игла в стоге сена"** (needle in a haystack)
- Хорошие решения для downstream задач занимают ничтожную долю объёма распределения весов
- Обнаружение решений требует структурированных методов оптимизации (градиентный спуск, итеративная оптимизация)
- Пространство вокруг весов - локальный максимум ландшафта точности

**Большие модели** (от ~7B параметров):
- Переходят в режим **"заросли"** (thicket regime)
- Плотность task-specific экспертов драматически возрастает
- Разнообразные task-improving специалисты населяют существенную долю окрестности вокруг pretrained весов
- Пространство вокруг весов - "долина" с множеством пиков точности nearby

### Solution Density (Плотность решений)

**Определение:** Плотность решений δ(m) - вероятность того, что случайная пертурбация улучшает базовую производительность модели на маржу m:

```
δ(m) = P[s(θ + ε) > s(θ) + m], где ε ~ N(0, σ²I)
```

**Scaling Law:** Плотность решений монотонно возрастает с размером модели:
- Необученные модели имеют крошечную плотность решений
- Предобученные модели 32B+ имеют высокую плотность решений
- Зависимость следует scaling law - более крупные и производительные модели имеют более высокую плотность

### Solution Diversity (Разнообразие решений)

**Spectral Discordance** - мера специализации решений:
- D → 1: ортогональные ранжирования задач (специалисты)
- D → 0: параллельные ранжирования (универсалы)

**Наблюдение:** С ростом размера модели спектральная дискордантность монотонно возрастает, что означает:
- Отдельные пертурбации - это **специалисты**, а не универсалы
- Пертурбации, улучшающие одну задачу, могут ухудшать другие
- Разные пертурбации имеют непересекающиеся области экспертизы

## Алгоритм RandOpt

### Фаза 1: Случайное угадывание (Training)

```
1. Сэмплировать N случайных seed {s₁, ..., sₙ}
2. Для каждого seed выбрать масштаб шума σᵢ из набора Σ
3. Создать N пертурбированных векторов: θᵢ = θ + σᵢ·ε(sᵢ)
4. Оценить каждую модель f_θᵢ на training/validation наборе D_train
5. Получить scores vᵢ для каждой пертурбации
6. Выбрать top-K моделей по производительности
```

### Фаза 2: Ансамблирование (Inference)

```
1. Для тестового входа x сгенерировать предсказания K выбранными моделями
2. Агрегировать предсказания через majority vote
3. Вернуть финальный прогноз ŷ
```

### Псевдокод (PyTorch-style)

```python
# Training: Select top-K seeds based on D_train performance
seeds = [sample_seed() for _ in range(N)]
sigmas_per_seed = [sigmas[i // (N // len(sigmas))] for i in range(N)]

# Evaluate all perturbed models
scores = [evaluate(theta + sigmas_per_seed[i] * eps(seed[i]), D_train) 
          for i in range(N)]
top_indices = topk(scores, K).indices

# Inference: Ensemble predictions on test input x
answers = [generate(theta + sigmas_per_seed[i] * eps(seed[i]), x) 
           for i in top_indices]
prediction = majority_vote(answers)
```

### Гиперпараметры

- **N** (population size): количество случайных пертурбаций (типично 2000-5000)
- **K** (ensemble size): количество моделей для ансамблирования (типично 50)
- **Σ** (noise scales): набор масштабов шума (типично σ ∈ {0.001, 0.002, 0.005})

## Сравнение с базовыми методами

### Преимущества RandOpt

| Характеристика | RandOpt | PPO/GRPO | ES |
|---------------|---------|----------|-----|
| Шаги оптимизации | O(1) | O(T) | O(T) |
| Параллелизм | Полный | Последовательный | Частичный |
| Wall-clock время | ~3 минуты | часы | часы |
| FLOPs | Конкурентно | Конкурентно | Конкурентно |
| Inference cost | K× выше | 1× | K× |

### Результаты на benchmarks

**LLM пост-обучение** (Qwen, Llama, OLMo3; 0.5B-8B):
- RandOpt (K=50) соответствует или превосходит PPO, GRPO, ES на большинстве задач
- Задачи: математика (Countdown, GSM8K, MATH-500, OlyBench), код (MBPP), writing (ROCStories), химия (USPTO)
- Все методы запущены с равными training FLOPs

**VLM пост-обучение** (Qwen2.5-VL-3B-Instruct):
- GQA dataset: улучшение с 56.6% до 69.0% (+12.4%)
- N=5000, K=50, замораживание visual encoder

### Пример производительности

**Olmo-3-7B-Instruct на Countdown:**
- Кластер: 200 GH200 GPU
- N=2000, K=50
- Время обучения: **3.2 минуты**
- Точность: **70%**
- Конкурентно с GRPO и ES

## Теоретические следствия

### Интерпретация результатов

1. **Пост-обучение становится лёгким** при наличии сильных pretrained репрезентаций
2. В режиме "зарослей" метод оптимизации не имеет значения:
   - Gradient-based search ✓
   - Evolutionary algorithms ✓
   - Brute-force parallel selection ✓
3. Успех RandOpt служит "зондом": показывает, что окрестность весов содержит обильные решения

### Связь с Bayesian Neural Nets

RandOpt связан с Bayesian подходами:
- **PEP (Perturbed Ensemble Propagation)**: особенно близок к RandOpt
- **Bayesian NN**: трактуют параметры как случайные переменные
- **Отличие**: RandOpt не требует явного байесовского обучения - pretrained веса уже неявно определяют распределение

### Минимальная модель возникновения "зарослей"

Эксперимент с 1D сигналами показывает необходимые условия:
1. **Слишком мало предобучения** → needle-in-haystack режим
2. **Предобучение на смеси сигналов** → thicket режим ✓
3. **Предобучение на одном типе сигналов** → plateau режим (потолок)

**Вывод:** Критично предобучение на разнообразных паттернах/задачах

## Ограничения RandOpt

1. **Inference cost**: K× выше из-за ансамблирования
   - Частично решается через distillation (proof of concept в Section 7)
2. **Зависимость от размера модели**: работает только для достаточно крупных моделей
3. **Форматирование**: часть улучшений может быть от стилистических изменений, а не от reasoning
4. **Не универсально**: K=1 значительно менее эффективно, требуется K=50 для полной конкурентоспособности

## Практические рекомендации

### Когда использовать RandOpt

✅ **Рекомендуется:**
- Большие модели (7B+ параметров)
- Доступен массовый параллельный compute (100+ GPU)
- Требуется быстрое пост-обучение (минуты, не часы)
- Задачи с чёткими метриками качества

❌ **Не рекомендуется:**
- Малые модели (<1B) - используйте градиентные методы
- Ограниченный compute для параллельной выборки
- Задачи, требующие итеративной адаптации

### Комбинация с другими методами

- **Distillation**: сжатие ансамбля в одну модель для снижения inference cost
- **LoRA**: применение пертурбаций только к адаптерам для снижения размерности
- **Model Merging**: комбинация с TIES/DARE для улучшения качества ансамбля

## Связь с другими концепциями

### Universal Weight Subspace Hypothesis

Гипотеза универсального весового подпространства [[../../../algorithms/neural_networks/universal_weight_subspace_hypothesis.md]] даёт теоретическое обоснование:
- Модели, обученные на разных задачах, сходятся к общему низкоразмерному подпространству
- Это объясняет, почему случайные пертурбации находят работающие решения
- RandOpt можно рассматривать как сэмплирование из этого подпространства

### Model Merging

Связь со слиянием моделей [[../../model_merging/index.md]]:
- RandOpt ансамблирует пертурбации вместо слияния весов
- TIES/DARE могут быть применены для слияния top-K пертурбаций
- Model Swarms использует похожую идею поиска в weight space

### Parameter-Efficient Fine-Tuning

Сравнение с LoRA [[../../llm/lora_optimization.md]]:
- LoRA: низкоранговые адаптеры обучаются градиентным спуском
- RandOpt: полные пертурбации весов выбираются случайно
- Комбинация: пертурбации только LoRA-параметров для снижения размерности

### Reinforcement Learning

Альтернатива RLHF методам:
- **PPO**: последовательная оптимизация с critic model
- **GRPO**: group-relative advantages без critic
- **RandOpt**: безградиентная параллельная выборка
