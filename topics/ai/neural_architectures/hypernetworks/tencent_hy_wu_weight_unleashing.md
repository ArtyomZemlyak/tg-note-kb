# Tencent HY-WU: Динамические LoRA через гиперсети для редактирования изображений

## Краткое описание

**Tencent HY-WU (Weight Unleashing)** — это метод условной генерации LoRA-адаптеров через гиперсеть для редактирования изображений. Вместо фиксированных весов адаптера, модель-генератор синтезирует LoRA отдельно под каждый входной пример прямо во время инференса, без дополнительной оптимизации на тест-тайме.

## Основная информация

### Проблема: Конфликт градиентов при дообучении

Когда задачи противоречат друг другу (например, "размыть" против "убрать размытие" или "состарить лицо" против "восстановить"), общий адаптер вынужден идти на компромисс. Градиенты конфликтуют, и результат оказывается хуже, чем если бы задачи обучались раздельно.

**Измерения Tencent:**
- Косинусное сходство градиентов между разнородными задачами устойчиво **отрицательно**
- Среднее значение: **≈ -0.30**
- Задачи буквально тянут веса в противоположные стороны

### Архитектура HY-WU: Условная генерация параметров

```
Изображение + Текстовый запрос → SigLIP2 энкодер → Совместное представление → 
Генератор (8B) → LoRA-матрицы (~0.72B) → Базовая модель (HY-Image-3.0-Instruct)
```

**Ключевые компоненты:**

| Компонент | Спецификация |
|-----------|--------------|
| **Модель-генератор** | 8B параметров |
| **Генерируемые LoRA** | ~0.72B параметров |
| **Энкодер** | SigLIP2 (совместное изображение-текст представление) |
| **Базовая модель** | HY-Image-3.0-Instruct |
| **Обучение** | Сквозное, только через downstream-loss |
| **Предварительные чекпойнты** | Не используются |

### Ключевая инновация: Функциональная память

HY-WU представляет **первую часть серии исследований по функциональной памяти** для генеративных моделей:

- **Традиционный подход:** Один фиксированный набор весов для всех задач
- **HY-WU подход:** Динамическая генерация весов под каждый пример
- **Преимущество:** Избегание компромиссов между конфликтующими задачами

## Результаты и тесты

### Задача тестирования
Редактирование изображения текстовым запросом — конфликты неизбежны и визуально очевидны.

### Попарное human evaluation (GSB)

**Против open-source редакторов:**
- **67–78%** побед против Step1X, Qwen, LongCat и FLUX

**Против закрытых систем:**
- **55.6%** против Seedream 4.5
- **55.5%** против GPT Image 1.5

**Лидеры рынка:**
- Единственные, кто впереди HY-WU: **Nano Banana 2** и **Nano Banana Pro**

### Валидация подхода

Tencent проверили, что прирост качества достигается именно **условной маршрутизацией**, а не просто увеличением числа параметров:

| Эксперимент | Результат |
|-------------|-----------|
| Перемешанные условия | Результат проваливается до уровня базовой модели |
| Усредненные условия | Результат проваливается до уровня базовой модели |
| Полный SFT (больше параметров) | Сопоставимо с обычным Shared LoRA |

**Вывод:** В обоих случаях (SFT и Shared LoRA) в инференсе применяется одна фиксированная точка в пространстве весов, что подтверждает преимущество динамической генерации.

## Технические требования

Для запуска связки модели-генератора и базовой модели HY-Image-3.0-Instruct:
- **8×40 GB VRAM** или
- **4×80 GB VRAM**

## Планы исследований

Tencent анонсировали серию будущих исследований:

1. **Сравнение с retrieval-подходами** — понять, когда функциональная память уместна, а когда retrieval-подходы
2. **Протоколы онлайн-обучения** — усвоение новых задач без деградации на старых
3. **Масштабирование модели-генератора** — отдельно от базовой модели
4. **Выход за пределы LoRA** — другие операторные интерфейсы
5. **Распространение на видео** — применение к видео-задачам
6. **Агентные системы** — интеграция с агентными архитектурами
7. **Точечное удаление поведения** — управление состоянием генератора для удаления нежелательного поведения

## Связь с другими подходами

### Сравнение с гиперсетями для LoRA

| Метод | Вход | Выход | Применение |
|-------|------|-------|------------|
| **Doc-to-LoRA** [[../../llm/doc_to_lora.md]] | Документ | LoRA для фактологических знаний | Долгосрочная память в LLM |
| **Text-to-LoRA** [[../../llm/text_to_lora.md]] | Описание задачи | LoRA для поведения/навыка | Адаптация к задачам |
| **HY-WU** | Изображение + запрос | LoRA для редактирования | Редактирование изображений |

**Общая философия:** Амортизация стоимости — дорогое мета-обучение один раз, дешевая генерация адаптеров при инференсе.

### Отличие от model merging

HY-WU решает проблему **интерференции градиентов** на уровне архитектуры, а не пост-фактум слияния:

- **Model Merging** [[../../model_merging/methods.md]] — объединяет уже обученные модели
- **HY-WU** — предотвращает конфликт через динамическую генерацию под каждый пример

## Применение

| Сценарий | Преимущество HY-WU |
|----------|-------------------|
| **Редактирование с конфликтами** | Избегание компромиссов между противоречивыми запросами |
| **Мульти-задачное редактирование** | Каждый пример получает оптимальный адаптер |
| **Персонализация** | Динамическая адаптация под пользователя/контекст |

## Ограничения

1. **Высокие требования к VRAM** — 320-320 GB для полного запуска

3. **Первая часть серии** — дополнительные возможности в будущих работах
