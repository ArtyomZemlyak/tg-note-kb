# Reinforcement Learning для научных открытий

## Описание

Использование методов обучения с подкреплением (Reinforcement Learning, RL) для поиска и открытия новых решений в научных и инженерных задачах. В отличие от традиционного применения RL для оптимизации поведения агента в среде, здесь RL используется для поиска инновационных решений в сложных пространствах решений.

## Основные подходы

### TTT-Discover
Метод, который адаптирует политику LLM во время инференса для задач открытия. Отличительной чертой является оптимизация *максимальной* награды (max R(s)) вместо *ожидаемой* (E[R]), что делает его эффективным для поиска аутлаерных решений. Использует энтропийную цель J_β(θ) = log E[exp(β * R(s, a))] и PUCT-подобную стратегию повторного использования. Алгоритм включает два ключевых этапа: Reuse (исследование) и Train (эксплуатация).

### AlphaEvolve
Подход, использующий эволюционные стратегии для навигации в пространстве решений при замороженной модели. Сохраняет предыдущие попытки в буфере и использует их для генерации новых подсказок с помощью доменно-специфичных эвристик. Сравнивается с TTT-Discover как метод, основанный на поиске, а не на обучении во время инференса.

### ThetaEvolve
Метод, также исследующий RL во время инференса, который использует OpenEvolve (вариант AlphaEvolve) для повторного использования состояний и действий. Использует варианты GRPO для обучения.

### Tree of Thoughts (ToT)
Метод, который формализует рассуждение как поиск дерева, где каждый узел представляет частичное решение. В отличие от TTT-Discover, ToT не адаптирует параметры модели в процессе решения.

### MiGrATe (Mixed-Policy GRPO for Adaptation at Test-Time)
Метод для онлайн-обучения во время тестирования, который использует GRPO как алгоритм поиска для адаптации LLM во время инференса без необходимости внешних данных для обучения.

## Ключевые особенности задач открытия

### Смещение распределения
Задачи открытия почти всегда являются OOD (out-of-distribution), поскольку истинные открытия происходят в областях, где модель не проходила предобучение.

### Цель оптимизации
В задачах на открытие нас интересует не среднее качество решения, а *максимальная* награда, полученная в одной из траекторий. Политика, которая генерирует мусор в 99% случаев, но выдает результат Нобелевского уровня в 1% — провал для обычного RL, но триумф для discovery.

### Формулировка как MDP
Задачи открытия можно формализовать как марковский процесс принятия решений (MDP):
- Среда: определение задачи (например, "Напиши Triton-ядро для перемножения матриц")
- Состояние: кандидат решения (например, код)
- Действие: генерация токенов
- Награда: непрерывная функция (например, обратная величина времени выполнения)

## Методы оптимизации

### Энтропийная цель
```
J_β(θ) = log E[exp(β * R(s, a))]
```

Параметр β действует как температура. При β → ∞ функция фокусируется исключительно на максимальной награде. В TTT-Discover используется адаптивный β(s), ограниченный через KL-дивергенцию.

### PUCT (Predictor + UCB) для исследований
Используется для выбора стартовых точек в пространстве решений. Q-оценки отслеживают *максимальную* награду потомков, а не среднюю, что согласуется с природой задач "best-of-N". Формула: score(s) = Q(s) + c · P(s) · √(T/(1 + n(s))).

### LoRA-адаптация
Низкоранговая адаптация позволяет обновлять только часть параметров модели, оставляя основной бэкбон замороженным, что делает онлайн-обучение осуществимым. В TTT-Discover используется LoRA с рангом 32.

## Практические применения

### Математические открытия
- Решение задач в теории чисел
- Конструкция новых математических объектов
- Доказательство теорем
- Задача Эрдёша о минимальном перекрытии (улучшение верхней границы до 0.380876)
- Автокорреляционные неравенства

### Инженерные задачи
- Оптимизация GPU-ядер
- Алгоритмические улучшения
- Системная инженерия
- Тригонометрическое умножение матриц (TriMul) - улучшение до 1161 мкс против 1371 мкс у лучшего человеческого решения

### Алгоритмическая инженерия
- Соревнования по программированию (например, AtCoder Heuristic Contests)
- Оптимизация производственного планирования (Apple Incremental Game)
- Компьютерная геометрия (Purse Seine Fishing)

### Биологические исследования
- Протеин-фолдинг
- Дизайн молекул
- Генетические исследования
- Одноклеточный анализ, задача денойзинга (улучшение до 0.71 против 0.64 у лучшего человеческого решения)

## Сравнение с классическим RL

| Аспект | Классический RL | RL для открытий (TTT-Discover) |
|--------|----------------|-----------------|
| Цель | E[R] - ожидаемая награда | max R(s) - максимальная награда |
| Политика | Робастный генералист | "Удачливый" специалист |
| Обучение | На фиксированном наборе | Во время инференса |
| Пространство решений | Ограниченное | Большое, часто непрерывное |
| Среда | Статичная | Одна задача во время инференса |
| Основная задача | Обобщение | Решение конкретной задачи |

## Ограничения

1. Требует верифицируемый, непрерывный сигнал награды
2. Высокая вычислительная стоимость (~$500 на задачу)
3. Ограничен применимостью к задачам с четкой функцией оценки
4. Сложности с интерпретацией найденных решений
5. Этические вопросы при автоматических открытиях
6. Применимо только к задачам с детерминированной оценкой решений
7. Неприменимо к задачам с разреженными или бинарными наградами

## Перспективы развития

- Интеграция с символическими методами
- Улучшение эффективности вычислений
- Разработка новых целевых функций для различных типов задач
- Методы проверки и валидации автоматических открытий
- Расширение на задачи с разреженными наградами
- Исследование возможностей для не-верифицируемых областей

## Экспертные обзоры

### Математика
Экспертный обзор подтверждает, что верхние границы, полученные с помощью TTT-Discover для задачи Эрдёша и автокорреляционных неравенств, легко проверить. Предоставленные функции дают границы, улучшающие состояние дел, путем оценки интересующей величины и максимизации по дискретному набору точек.

### Инженерия
Экспертный обзор от организаторов GPUMode подтверждает, что TTT-Discover правильно определил, что проблема вычисления TriMul является ограниченной по памяти из-за окружающих поэлементных операций, поэтому агент сосредоточился на максимальном объединении операций, снижая трафик памяти и накладные расходы на запуск ядра.
