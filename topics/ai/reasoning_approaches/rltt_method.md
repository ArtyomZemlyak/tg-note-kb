# RLTT: Метод Обучения с Подкреплением для Петлевых Языковых Моделей

## Краткое описание

**RLTT (Reward Latent Thought Trajectories)** — метод обучения с подкреплением для петлевых языковых моделей (LoopLMs), который распределяет вознаграждение по всей траектории латентных рассуждений модели, а не только по финальному результату. Разработан Williams & Tureč (2026) для решения проблемы credit assignment в латентном пространстве петлевых моделей.

## Проблема Credit Assignment в LoopLMs

Петлевые языковые модели выполняют многократные итерации в латентном пространстве перед генерацией токена. Это создаёт проблему распределения вознаграждения:

- **Традиционный подход (GRPO)**: вознаграждение назначается только за финальный результат
- **Проблема**: градиенты не распространяются эффективно по всем итерациям латентных рассуждений
- **Следствие**: модель не обучается оптимальным стратегиям латентных вычислений

## Методология RLTT

### Основная идея

RLTT распределяет вознаграждение по **всей траектории латентных мыслей**, позволяя модели обучаться эффективным стратегиям итеративных рассуждений.

### Формула RLTT

```
∇J_RLTT = Σᵢ Σₜ Σₖ wₖ · Aᵢ · ∇log pᵏ(yₜ|x, траекторияᵢ)
```

где:
- `i` — индекс траектории
- `t` — индекс токена
- `k` — индекс итерации латентных рассуждений
- `wₖ` — вес для k-й итерации (Σwₖ = 1)
- `Aᵢ` — advantage для траектории i
- `pᵏ` — распределение вероятностей на k-й итерации

### Стратегии взвешивания итераций

| Стратегия | Формула | Логика |
|-----------|---------|--------|
| **Exit-probability** | пропорционально вероятности остановки | Информированный выбор итерации |
| **Progressive** | wₖ ∝ k | Поздние итерации важнее ранних |
| **Uniform** | wₖ = 1/K | Все итерации равнозначны |

## Архитектура LoopLM с RLTT

### Процесс генерации токена

Для каждого токена y_t:
1. h⁰ = эмбеддинг промпта
2. Для k = 1...K итераций:
   - hᵏ = Transformer(hᵏ⁻¹) — общие веса для всех итераций
   - pᵏ = языковая голова(hᵏ) — промежуточное распределение
3. Использовать только p^K для генерации токена

### Латентные рассуждения

Модель «думает молча» в латентном пространстве:
- Уточняет внутренние представления итеративно
- Не декодирует промежуточные мысли в текст
- Экономит токены на промежуточных рассуждениях

## Результаты экспериментов

### Бенчмарки (RLTT vs GRPO)

| Бенчмарк | GRPO | RLTT | Улучшение |
|----------|------|------|-----------|
| **GSM8K** | ~85% | ~95% | +10 п.п. |
| **MATH-500** (1024 токена) | 42.4% | 78.4% | +36 п.п. |
| **AIME24** | низкий | высокий | значительное |
| **GPQA** | 19.7% | 38.4% | ~2× |

### Ключевые наблюдения

1. **Длина ответов падает**: RLTT генерирует более короткие ответы (эмерджентный эффект)
2. **Энтропия снижается быстрее**: без коллапса разнообразия (подтверждено Pass@k анализом)
3. **Робастность**: RLTT лучше при любом бюджете токенов и числе итераций
4. **Переносимость**: улучшение на не-математических задачах при обучении на математике

### Примеры поведения

**RLTT-модель:**
- Быстро формулирует правильный подход
- Аккуратно реализует и останавливается

**GRPO-модель:**
- Приходит к тому же решению
- Начинает перепроверять формулы разными способами
- Проверяет частные случаи, сомневается
- Тратит в 2-3 раза больше токенов
- Часто исчерпывает лимит без ответа

## Вычислительная стоимость

- **Память**: увеличивается в K раз (нужно хранить логарифмы для каждой итерации)
- **Скорость**: быстрее GRPO (если не учитывать память)
- **Практика**: авторам пришлось уменьшить max tokens с 16384 до 8192

## Преимущества RLTT

1. **Вычислительная эффективность** — не тратятся токены на промежуточный текст
2. **Более мощная выразительность** — петлевые трансформеры строго мощнее обычных (Saunshi et al., 2025)
3. **Борьба с overthinking** — модель учится сходиться к ответу быстрее
4. **Улучшенное распределение градиента** — RLTT решает проблему credit assignment в латентном пространстве

## Проблемы и риски

### AI Safety Concerns

1. **Потеря прозрачности**: невозможно мониторить рассуждения через текст
2. **CoT-мониторинг бесполезен**: один из немногих работающих инструментов AI safety не применим
3. **Оптимизация «скрытых мыслей»**: RLTT усугубляет проблему непрозрачности

### Дилемма прозрачности

```
Латентное рассуждение: эффективно, но непрозрачно
    ↓
Текстовое рассуждение: прозрачнее, но менее эффективно
```

### Возможные решения

- Механистическая интерпретируемость (probing, sparse autoencoders)
- Декодирование промежуточных состояний (дорого, неинформативно)
- Адаптивный RLTT с варьируемым числом итераций

## Перспективы развития

### Направления будущей работы

- **Адаптивный RLTT**: вариация числа итераций от токена к токену
- **Интеграция adaptive halting**: механизмы адаптивной остановки
- **Механистическая интерпретируемость**: развитие методов анализа латентных представлений
- **Баланс capability vs safety**: поиск компромисса между эффективностью и прозрачностью

## Выводы

1. **RLTT — элегантное техническое решение** реальной проблемы credit assignment в LoopLMs
2. **Результаты впечатляют** — особенно на сложных задачах (AIME24, BeyondAIME)
3. **Но есть серьёзная цена** — потеря прозрачности рассуждений
4. **Capability vs Safety** — ещё один пример движения в противоположных направлениях

> *«Чем лучше мы научимся обучать модели, которые думают молча, тем острее станет вопрос: а как нам за ними следить?»*
