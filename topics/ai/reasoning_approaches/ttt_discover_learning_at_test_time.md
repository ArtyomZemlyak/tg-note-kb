# TTT-Discover: Обучение прямо во время тестирования (Learning at Test Time)

## Краткое описание

TTT-Discover — это метод, который тонко настраивает большие языковые модели (LLM) с помощью обучения с подкреплением (RL) прямо во время инференса на конкретной тестовой задаче. В отличие от традиционного подхода, где модель остается замороженной и используется только для поиска решений, TTT-Discover обновляет параметры модели динамически, чтобы она "научилась" структуре текущей проблемы.

## Ключевые инновации

### Парадигма Test-Time Learning

TTT-Discover меняет подход от "test-time compute" (чистого поиска) к "test-time learning". Вместо того чтобы использовать замороженную модель для поиска решения, веса модели обновляются динамически в процессе инференса, создавая "эфемерного специалиста", который адаптируется к конкретной задаче.

### Энтропийная цель для максимизации аутлаеров

Традиционные методы RL стремятся максимизировать *ожидаемую* суммарную награду E[R]. В задачах открытия (discovery) важна не средняя производительность, а *максимальная* награда среди всех возможных траекторий: max R(s). 

Формулировка оптимизации:
```
J_β(θ) = log E[exp(β * R(s, a))]
```

Где β действует как температурный параметр. При β → ∞ функция фокусируется исключительно на максимальной награде, что идеально подходит для задач, где требуется найти "удачливую" политику, способную генерировать высококачественные решения в редких случаях, даже если в остальных случаях качество низкое.

### Механизмы: Reuse (Exploration) и Train (Exploitation)

#### Stage Train (Обучение)
- Использует энтропийную целевую функцию, ориентированную на приоритет аутлаеров
- Максимизирует вероятность действий, приводящих к высокой экспоненциальной награде
- Использует адаптивный β(s), ограниченный через KL-дивергенцию между обновленной и исходной замороженной политикой
- Градиент обновления: ∇θ J_β(θ) = E[w_β(s)(a) · ∇θ log πθ(a|s)], где w_β(s)(a) - экспоненциальные веса

#### Stage Reuse (Исследование)
- Решает проблему исследования траектории, предотвращая коллапс в локальный оптимум
- Поддерживает буфер прошлых состояний и выбирает стартовые точки, используя вариацию PUCT (Predictor + UCB)
- Q-оценки отслеживают *максимальную* награду потомков, а не среднюю, что согласуется с природой задач "best-of-N"
- Формула PUCT: score(s) = Q(s) + c · P(s) · √(T/(1 + n(s))), где:
  - Q(s) - максимальная награда среди состояний, сгенерированных когда начальное состояние было s
  - P(s) - пропорционально рангу s в буфере, отсортированному по награде
  - n(s) - счетчик, сколько раз s или его потомки были расширены
  - T - общее количество расширений
  - c - коэффициент исследования

## Алгоритм и реализация

### Алгоритм TTT-Discover
1. Инициализация буфера H₀ с пустым решением
2. Для каждого шага i от 0 до N-1:
   - sᵢ, cᵢ ∼ reuse(Hᵢ) - выбор начального состояния и контекста
   - aᵢ ∼ πθᵢ(·|d, sᵢ, cᵢ) - генерация действия
   - s'ᵢ = T(aᵢ) - переход к следующему состоянию
   - rᵢ = R(s'ᵢ) - оценка награды
   - Hᵢ₊₁ = Hᵢ ∪ {(sᵢ, aᵢ, s'ᵢ, rᵢ)} - добавление в буфер
   - θᵢ₊₁ = train(θᵢ, (d, sᵢ, cᵢ, aᵢ, rᵢ)) - обновление параметров модели
3. Возврат состояния с максимальной наградой

### Использование LoRA
- Обновления через Low-Rank Adaptation (LoRA) с рангом 32
- Массивный бэкбон модели остается замороженным
- Обновляется только небольшая часть параметров
- Практически осуществимо на кластерах H100/H200

### Вычислительные характеристики
- Модель: gpt-oss-120b (117B параметров, MoE архитектура)
- Цикл обучения: 50 шагов
- Размер батча: 512 роллаутов на шаг (8 групп по 64)
- Контекст окно: 32,768 токенов
- Температура сэмплирования: 1.0
- LoRA ранг: 32
- Вычислительные затраты: ~$500 на задачу
- Подходит для задач "Системы 2": медленных, вдумчивых, с высокой ценностью решения

## Результаты

### Математика: Erdős' Minimum Overlap Problem
- Улучшение верхней границы константы c до 0.380876 (против предыдущего 0.380876)
- Найдена асимметричная ступенчатая функция из 600 частей (в сравнении с 95 частями у AlphaEvolve и 51 у человеческих экспертов)
- Использование FFT-ускоренного градиентного спуска, случайного восхождения по холмам и имитации отжига
- Решение оказалось асимметричным, в отличие от симметричного у AlphaEvolve

### Инженерия: Тригонометрическое умножение матриц (TriMul)
- Ядро для TriMul (компонента AlphaFold) на NVIDIA H100: 1161 мкс
- Превышение лучшего ручного решения (1371 мкс) с соревнования GPUMode
- Использование сложных возможностей слияния (LayerNorm, гейтинг, проекции)
- Основные оптимизации:
  - Слияние операций во входном LayerNorm
  - Слияние сигмоиды и поэлементного умножения во входном гейтинге
  - Слияние операций в выходном LayerNorm и гейтинге
  - Преобразование входов в FP16 и делегирование вычислений cuBLAS для эффективного использования TensorCores

### Алгоритмическая инженерия: AtCoder Heuristic Contests
- В контесте ahc039 ("Purse Seine Fishing"): результат TTT-Discover (567,062) превзошел лучшего человека (566,997)
- В контесте ahc058 ("Apple Incremental Game"): результат (848,414,228) превзошел лучший человеческий (847,674,723)
- Для ahc039: решение строит большой пул многообещающих прямоугольников, используя префиксные суммы, затем жадно инициализирует объединение и использует имитацию отжига с движениями добавления, удаления, замены, расширения, сжатия и скольжения
- Для ahc058: решение строит несколько разумных планов с помощью жадных правил, затем улучшает лучший план с помощью имитации отжига

### Биология: Одноклеточный анализ (Single-cell Analysis)
- Задача денойзинга в OpenProblems: улучшение метрики до 0.71 против 0.64 у лучшего человеческого решения (MAGIC)
- Добавлены: генно-адаптивные преобразования, низкоранговая SVD-рефинация и лог-пространственные полировки
- Алгоритм начинается с кода MAGIC и добавляет:
  - Генно-адаптивные преобразования
  - Низкоранговую SVD-рефинацию
  - Лог-пространственные полировки, которые напрямую оптимизируют метрику бенчмарка

## Контекст и значение

### OOD природа открытий
Настоящие открытия всегда находятся вне распределения (Out-Of-Distribution, OOD). Если искать новое доказательство или алгоритм, решение, скорее всего, находится в области, где модель не проходила предобучение. TTT-Discover решает эту проблему, позволяя модели "учиться" прямо во время решения задачи, рассматривая траектории поиска как датасет, генерируемый на лету.

### Связь с другими методами
- Параллельно с ThetaEvolve и MiGrATe, которые тоже исследуют RL во время инференса
- Выделяется комбинацией энтропийной цели (фокус на макс. награде) и стратегии PUCT
- Показывает превосходство над эволюционными эвристиками и методами Best-of-N

### Абляции
- Постоянный β: улучшения уменьшаются позже в тренировке
- Ожидаемая награда (без энтропийной цели): улучшения медленнее
- Без TTT (только reuse): как средняя, так и максимальная награда стагнируют
- ϵ-greedy reuse: работает разумно, особенно с ранним удачным решением
- Навивный RL и отсутствие reuse: минимальные улучшения

## Ограничения

1. Требует верифицируемого, непрерывного сигнала награды
2. Применимо только к задачам с детерминированной оценкой решений
3. Высокая стоимость вычислений (~$500 за задачу)
4. Неприменимо к задачам с разреженными или бинарными наградами
5. Высокая задержка, делает невозможным реал-тайм взаимодействие

## Влияние на будущее ИИ

TTT-Discover демонстрирует, что граница между "обучением" и "инференсом" становится всё более искусственной для задач высокой ценности. Сдвиг вычислений в фазу онлайн-обучения позволяет использовать открытые веса, чтобы превосходить замороженные frontier-модели в узких задачах. Это намекает на будущее, где "модели-генералисты" служат лишь априори для "эфемерных специалистов", которые обучаются, делают одно открытие и затем выбрасываются.
