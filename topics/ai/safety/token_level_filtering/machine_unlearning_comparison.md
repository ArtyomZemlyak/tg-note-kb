# Сравнение фильтрации на уровне токенов с методами машинного "забвения" (Machine Unlearning)

## Краткое описание

Этот файл сравнивает подход фильтрации данных на уровне токенов с традиционными методами машинного "забвения" (machine unlearning). В то время как большинство подходов к безопасности ИИ пытаются удалить нежелательные способности из уже обученных моделей, фильтрация данных на уровне токенов предотвращает формирование этих способностей на этапе предобучения.

## Основная информация

### Основные различия подходов

#### Машинное "забвение" (Post-hoc подход)
- **Принцип**: Попытки удалить или подавить уже сформированные нежелательные способности из обученной модели
- **Методы**: 
  - RLHF (Reinforcement Learning from Human Feedback) для подавления нежелательных ответов
  - RMU (Representation Misdirection for Unlearning) - изменение внутренних представлений модели
  - Fine-tuning с негативными примерами
  - Прямое изменение весов модели
- **Ограничения**:
  - Знания уже существуют в весах модели
  - Атаки (джейлбрейки) часто успешно извлекают подавленную информацию
  - Модели могут быть уязвимы к небольшим изменениям в инструкциях или контексте
  - Могут возникать неожиданные побочные эффекты, влияющие на полезные способности

#### Фильтрация данных на уровне токенов (Ab initio подход)
- **Принцип**: Профилактическое удаление нежелательных способностей на этапе предобучения
- **Методы**:
  - Использование SAE-ориентированных классификаторов для обнаружения нежелательных токенов
  - Маскировка потерь (loss masking) для предотвращения обновления весов на основе нежелательных токенов
  - Обучение моделей на заранее отфильтрованных данных
- **Преимущества**:
  - Нежелательные знания никогда не формируются в весах модели
  - Более устойчивые к атакам и обходу
  - Устойчивость к адверсариальному дообучению
  - Лучшее масштабирование с размером модели

### Экспериментальные сравнения

#### Устойчивость к атакам
- **Машинное "забвение"**: Методы "анлернинга", такие как RMU, быстро "сыплются" при минимальном адверсариальном дообучении
- **Фильтрация токенов**: Модели с токенной фильтрацией сохраняют свое "невежество" намного дольше, требуя на порядки больше данных для восстановления способностей

#### Эффективность масштабирования
- **Машинное "забвение"**: Эффективность методов "забвения" не улучшается пропорционально увеличению размера модели
- **Фильтрация токенов**: Эффективность фильтрации увеличивается с размером модели, достигая 7000-кратного замедления вычислений в области "забвения" для моделей с 1.8 млрд. параметров

#### Воздействие на полезные способности
- **Машинное "забвение"**: Часто влияет на связанные полезные способности из-за общих представлений
- **Фильтрация токенов**: Позволяет более точно удалить нежелательные способности, сохраняя при этом полезные знания благодаря сохранению контекста

## Технические аспекты

### Механизмы "анлернинга"
- **RMU (Representation Misdirection for Unlearning)**: Метод, основанный на контроле внутренних представлений модели для "забвения" нежелательных знаний
- **Direct weight modification**: Прямое изменение весов модели для удаления нежелательных знаний
- **Negative prompt tuning**: Дообучение модели на негативных примерах для подавления нежелательного поведения

### Механизмы фильтрации токенов
- **SAE-ориентированный подход**: Использование разреженных автоэнкодеров для идентификации признаков, связанных с нежелательными доменами
- **BiLM-классификаторы**: Обучение бидирекционных языковых моделей для точной классификации токенов
- **Loss masking**: Математическая формула `L = -∑(m_t * log P(x_t | x_<t))`, где `m_t = 0` для нежелательных токенов

## Практические соображения

### Для разработчиков
- **Машинное "забвение"**: Может быть применено к уже обученным моделям, но с ограниченной эффективностью
- **Фильтрация токенов**: Требует планирования на этапе предобучения, но обеспечивает более надежные результаты

### Для пользователей
- **Машинное "забвение"**: Возможна видимость безопасности, но с риском обхода через джейлбрейки
- **Фильтрация токенов**: Более надежная защита, которая не зависит от форматирования запросов или хитрых инструкций
