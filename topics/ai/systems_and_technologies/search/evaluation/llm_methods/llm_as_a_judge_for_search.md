# Использование LLM-as-a-Judge для оценки качества поиска

## Краткое описание

Статья описывает подход к использованию больших языковых моделей для автоматической оценки релевантности поисковой выдачи. Метод позволяет масштабировать асессорскую оценку с помощью LLM, размечая большее количество пар запрос-ответ.

## Обоснование подхода

Ручная разметка поисковых запросов и их релевантности для товаров является трудоемкой и ограниченной в объеме. Поскольку бюджет на асессорскую разметку не бесконечен, команда решила смотреть в сторону популярного подхода LLM-as-a-judge. Задача состояла в том, чтобы масштабировать асессорскую оценку с помощью LLM, размечая большее количество пар запрос-ответ.

## Выбор LLM-модели

Первой задачей был выбор LLM, оптимальной по трем показателям — скорости, цене и качеству разметки. Поскольку критически важно, чтобы модель разбиралась в домене fashion, используется дообученные в компании LLM-модели. Ранее это была LLM Mistral, а сейчас это дообученная модель QWEN. Она постоянно улучшается и поддерживается для многих задач в домене fashion, поэтому есть возможность дообучить ее в том числе на задачу разметки.

## Разработка промпта для оценки

Для более качественной разметки много дорабатывался промпт. В итоге он состоит из следующих частей:

1. **Контекст и задача** - описание цели разметки
2. **Пошаговая инструкция** - как оценивать релевантность
3. **Шкала оценки** - при оценке качества модель выставляла оценку по следующей шкале:
   - 2 — релевантно
   - 1 — частично релевантно
   - 0 — нерелевантно
4. **Дополнительные факторы** - неправильная раскладка, учет гендера, сезона, наличие бренда в запросе и так далее
5. **Ограничения разметки** - рамки, в которых должна работать модель
6. **Примеры «запрос-товар с правильной разметкой»** - обучающие примеры
7. **Примеры на разметку** - по товару LLM получает информацию о названии, описании, бренде и других атрибутах

## Golden Set - корзинка проверочных запросов

Чтобы оценить качество LLM-разметки и проверять модель на стабильность, создана отдельная корзинка проверочных запросов - Golden Set. Эта корзинка содержит около 500 запросов, которые меняются не чаще чем раз в квартал и отбираются равномерно из трех групп поисковых запросов:

- **высокочастотных** — запросы с частотой выше 99.9 персентиля
- **среднечастотных** — запросы с частотой выше 99 персентиля
- **низкочастотных** — запросы с частотой ниже 99 персентиля (менее 50 запросов за месяц)

Эти запросы размечаются параллельно двумя способами:
- отправляются внешним асессорам
- прогоняются через LLM

Если разметка не совпадает, запрос уходит на внутреннюю ручную проверку, где определяется финальная оценка. Таким образом, можно объективно измерять, насколько LLM сохраняет качество разметки во времени.

## Результаты качества

На текущий момент точность LLM-модели составляет:
- **Accuracy: 0.90**
- **F1-score: 0.89**

Это качество улучшается комплексно: дообучением LLM-модели на сложных примерах и изменением самой инструкции-промпта, чтобы сделать разметку точнее. В планах переход на VLM-разметку (визуальные языковые модели), потому что часть запросов сложно разметить без фото товара.

## Работа с разметкой

После проверки качества LLM-разметки она внедрена в регулярный процесс оценки качества поиска. LLM позволяет разметить больше запросов, чем способны асессоры, но все равно далеко не все. Поэтому решено сэмплировать запросы для разметки из корзинок, о которых рассказывалось ранее.

Каждую неделю отбираются поисковые запросы из каждой корзинки. Чем популярнее запрос, тем выше вероятность, что он попадет в разметку на этой неделе. В среднем отбирается суммарно 2200-2500 запросов. Для каждого из них идут в логи системы каталога и достают топ-60 товаров, которые показывались живым пользователям в поисковой выдаче, с учетом персонализации.

Далее данные обогащаются контентом: из таблиц с описаниями добавляются к каждому товару его бренд, категория, материал, страна происхождения, сезонность, тип посадки (оверсайз или нет), текстовое описание и так далее. После этого собранный датасет сохраняется в FeatureStorage, чтобы хранить историю и отслеживать изменения во времени.

## Основные метрики качества

После разметки моделью вычисляются основные метрики:

- **NDCG (Normalized Discounted Cumulative Gain)** — отражает качество ранжирования (наиболее релевантные товары находятся на самом верху выдачи)
- **Precision@K** — показывает долю релевантных товаров в топе выдачи

Полученные результаты отображаются в отдельном дашборде для каждой корзинки: можно видеть по каждому запросу, насколько хорошо работает поиск, и отмечать те, где метрики ниже заданного порога. Это помогает быстро находить проблемные запросы и чинить их — будь то неправильный словарь, опечаточник или неправильно выставленные атрибуты у товара.

## Сравнение с ручной разметкой

Чтобы оценить качество LLM-разметки, часть запросов отправляли живым асессорам, где они по той же шкале оценивали релевантность товаров. Однако одноразовая проверка не подходит, потому что со временем меняется поток запросов, и модель может начать галлюцинировать. Поэтому используется систематическая проверка с помощью Golden Set.

## Потенциальные улучшения

Планируется:
- Дообучение LLM-модели на сложных примерах
- Улучшение промпта для более точной разметки
- Переход на VLM-разметку для учета визуальных характеристик товаров
- Постоянная проверка качества через Golden Set
