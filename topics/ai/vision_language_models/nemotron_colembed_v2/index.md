# Nemotron ColEmbed V2: Семейство моделей для визуального документооборота

## Краткое описание

Nemotron ColEmbed V2 — семейство современных моделей для визуального документооборота (visual document retrieval), разработанных NVIDIA. Эти модели используют архитектуру late-interaction для повышения точности поиска по сравнению с традиционными подходами pool-встраивания. Модель 8B показывает лидерские результаты на бенчмарке ViDoRe V3 с NDCG@10 равным 63.42.

## Основные достижения

- **State-of-the-art результаты**: Модель nemotron-colembed-vl-8b-v2 занимает первое место в таблице лидеров ViDoRe V3 с NDCG@10 63.42 (на февраль 03, 2026)
- **Семейство моделей**: Выпущены три варианта — 3B, 4B и 8B параметров
- **Многоязычность**: Поддержка кросс-лингвальных задач благодаря расширенным методам обучения

## Архитектура моделей

- **3B модель** (nvidia/llama-nemotron-colembed-3b-v2): Основана на NVIDIA Eagle 2 с Llama 3.2 3B LLM бэкбоном
- **4B модель** (nvidia/nemotron-colembed-vl-4b-v2): Основана на Qwen3-VL-4B-Instruct
- **8B модель** (nvidia/nemotron-colembed-vl-8b-v2): Основана на Qwen3-VL-8B-Instruct

Все модели используют динамическое разбиение изображений на фрагменты и late-interaction архитектуру для fine-grained взаимодействия между запросом и документом.

## Ключевые техники

### 1. Изменение каузального внимания на бидирекциональное
LLM и VLM декодеры обычно используют каузальное (однонаправленное) внимание. Для адаптации этих моделей как эмбеддинговых, используется бидирекциональное внимание, позволяющее каждому токену интегрировать информацию как из предыдущих, так и из последующих токенов.

### 2. Hard-negative mining
Используется метод top-k с процентным порогом от NV-Retriever для отбора сложных отрицательных примеров, фильтруя потенциальные hard-negatives с помощью ограничения максимального сходства с пороговым значением 95% от сходства запроса с положительным образцом.

### 3. Кластеризация данных
Для балансировки доменов обучения используется кластеризация контекста, затем производится выборка положительных примеров из каждого кластера совместно с ассоциированными запросами и отрицательными образцами.

### 4. Кросс-лингвальная трансляция
Для поддержки кросс-лингвального поиска данные обучения были дополнены переводами запросов с использованием внутренней модели Qwen3-235B-A22.

### 5. Двухэтапное обучение
Для 3B модели используется двухстадийное обучение:
- Стадия 1: Обучение на текстовом корпусе (query-positives-negatives)
- Стадия 2: Дообучение на корпусе изображений

### 6. Модельное слияние (Model Merging)
Веса нескольких моделей (разделяющих архитектуру, но обученных на разных данных или гиперпараметрах) объединяются простым взвешенным средним для повышения обобщающей способности.

## Результаты

| Модель | Параметры | Размер эмбеддинга | ViDoRe V3 NDCG@10 | ViDoRe V1&V2 NDCG@5 |
|--------|-----------|------------------|--------------------|----------------------|
| nemotron-colembed-vl-8b-v2 | 8.14B | 4096 | 63.42 | 84.80 |
| nemotron-colembed-vl-4b-v2 | 4.43B | 2560 | 61.54 | 83.87 |
| llama-nemotron-colembed-vl-3b-v2 | 3.99B | 3072 | 59.79 | 83.64 |

## Проблемы развертывания Late-interaction

### Хранилище
Модели Late-interaction требуют значительно больше места для хранения по сравнению с простыми pooling-подходами, поскольку каждый документ требует множества эмбеддингов токенов:

- nemotron-colembed-vl-8b-v2: ~5897.5 ГБ для 1 млн изображений документов
- nemotron-colembed-vl-4b-v2: ~3686 ГБ для 1 млн изображений документов
- llama-nemotron-colembed-vl-3b-v2: ~13183.6 ГБ для 1 млн изображений документов

### Абляция размерности эмбеддингов
Для баланса между точностью и требованиями к памяти были протестированы уменьшенные размеры эмбеддингов:
- nemotron-colembed-vl-8b-v2 с 512-мерными эмбеддингами: 96.02% от оригинальной точности, требует на 87.5% меньше хранилища
- nemotron-colembed-vl-8b-v2 с 128-мерными эмбеддингами: 95.36% от оригинальной точности, требует только 3% от оригинального хранилища

## Новые концепции и термины

- **Late Interaction**: Механизм, при котором взаимодействие между запросом и документом происходит на более поздней стадии, позволяя fine-grained сравнению токенов запроса с токенами документа
- **MaxSim оператор**: Оператор, используемый в late-interaction архитектуре для выбора максимального сходства по каждому токену запроса и суммирования этих сходств
- **Dynamic Image Tiling**: Подход к обработке изображений переменного разрешения путем разбиения на тайлы
- **Hard-negative Mining**: Техника выборки сложных отрицательных примеров для обучения точных эмбеддингов

## Примеры применения

- Визуальный поиск документов в RAG-системах
- Поиск PDF-файлов и изображений документов без необходимости в OCR
- Многоязычный поиск документов
