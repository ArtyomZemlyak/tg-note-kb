# FlashOptim: Оптимизаторы для память-эффективного обучения

## Краткое описание

**FlashOptim** - это набор оптимизаций для оптимизаторов глубокого обучения, который сокращает потребление памяти на параметр более чем на 50% при сохранении качества модели и совместимости API. FlashOptim уменьшает память для AdamW с 16 до 7 байт на параметр (или 5 байт с освобождением градиентов), а для SGD - с 12 до 6 байт (или 4 байт с освобождением градиентов).

## Основная информация

### Проблема

Стандартное смешанное обучение нейронных сетей требует значительного объема памяти ускорителя для каждого параметра модели. Эти байты отражают не только сам параметр, но и его градиент, а также одну или несколько переменных состояния оптимизатора. При типичных 4 байтах на каждое значение, обучение даже 7-миллиардной модели требует более 100 ГБ памяти ускорителя, что делает её непрактичной для исследователей с ограниченными ресурсами.

### Таблица памяти на параметр

| Тензор              | SGD  | FlashSGD | Adam | FlashAdam |
|---------------------|------|----------|------|-----------|
| Мастер-веса         | 4    | 2        | 4    | 2         |
| Коррекция веса      | -    | 1        | -    | 1         |
| Градиенты           | 4    | 2 (0*)   | 4    | 2 (0*)    |
| Момент              | 4    | 1        | 4    | 1         |

При тонкой настройке Llama-3.1-8B:

- **FlashAdam**: 113 ГиБ пиковой памяти
- **Экономия**: 62 ГиБ (~35%)

## Ключевые техники

### 1. Улучшенное разделение весов (Improved Float Splitting)

Вместо материализации как 32-битного мастер-веса, так и 16-битного пониженного веса для прямого и обратного проходов, FlashOptim разделяет каждый мастер-вес на:
- **Низкоточный вес (θ')** - хранится в BF16 (2 байта)
- **Термин коррекции (ρ)** - хранится в INT8 (1 байт)

#### Алгоритм сжатия

```python
def compress(θ):
    θ' = Downcast(θ)  # BF16
    e = θ - Float32(θ')  # ошибка округления
    ℓ = floor(log2(ULP(θ'))) - 1  # единица последнего разряда
    h = floor(-ℓ / 2)  # для численной стабильности
    e_norm = (e * 2^h) * 2^(-ℓ-h)
    ρ = Int(Round(Clamp(e_norm, -1, 1) * N))  # N=127 для INT8
    return θ', ρ
```

#### Алгоритм восстановления

```python
def decompress(θ', ρ):
    ℓ = floor(log2(ULP(θ'))) - 1
    h = floor(ℓ / 2)
    e = ((Float32(ρ) / N) * 2^h) * 2^(ℓ-h)
    return Float32(θ') + e
```

#### Ключевое наблюдение

Все биты экспоненты в схеме разделения весов **потрачены впустую**. Экспонента ошибки e = θ - θ' всегда может быть выведена из θ':
- При округлении к ближайшему, θ должен находиться в пределах [θ' - u/2, θ' + u/2], где u = ULP(θ')
- Если бы θ был вне этого интервала, он бы округлился к другому значению
- Поэтому достаточно закодировать, где e находится в этом крошечном интервале, а не во всём диапазоне FP32

#### Эффективная точность

При использовании BF16 для θ' и INT8 для ρ, сжатое представление обеспечивает приблизительно **24 бита эффективной точности** (16 от BF16 + 8 от термина коррекции). Это аналогично формату PXR24, используемому в HDR-изображениях.

### 2. Квантование состояния оптимизатора с компандированием (Companded Optimizer State Quantization)

FlashOptim применяет нелинейные функции компандирования перед квантованием для улучшения использования бинов квантования и уменьшения ошибки квантования.

#### Для моментов (SGD, Adam, Lion)

Нормализация по absmax + функция типа softsign:

```python
def quantize_momentum(m):
    for each group g of 32 elements:
        s_g = max(|m_g|)  # масштаб
        m'_g = m_g / s_g  # нормализация
        m''_g = 2 * m'_g / (1 + |m'_g|)  # компандирование
        m_q_g = Round(m''_g * 127, INT8)
    return m_q, s
```

Функция сжимает экстремальные значения: входы около ±1 pushed toward the center, распределяя распределение момента более равномерно по бинам квантования.

#### Для дисперсии (Adam)

Сначала применяется квадратный корень, затем нормализация:

```python
def quantize_variance(v):
    v' = sqrt(v)  # квадратный корень для heavy-tailed распределений
    for each group g of 32 elements:
        s_g = max(v'_g)
        v_q_g = Round((v'_g / s_g) * 255, UINT8)
    return v_q, s
```

Квадратный корень мотивирован обновлением дисперсии Adam: v_t = β₂v_{t-1} + (1-β₂)g²_t, которое накапливает квадраты градиентов, создавая heavy-tailed распределения с большим динамическим диапазоном.

#### Накладные расходы

Для обеих техник:
- Размер группы: G = 32 элемента
- Масштаб FP16 на группу: 2 байта
- Накладные расходы: 2/G = 1/16 байт на параметр

### 3. Слитые оптимизированные ядра (Fused Optimized Kernels)

FlashOptim реализует шаг оптимизатора как единое слитое Triton-ядро, которое объединяет все операции сжатия и квантования, уменьшая память при сохранении пропускной способности во время обучения.

## Алгоритм FlashAdamW

```python
# Инициализация
m_q, m_s = quantize_momentum(0)
v_q, v_s = quantize_variance(0)
θ', ρ = compress(θ_0)

# На каждом шаге обучения
g = градиент(θ')  # вычисление градиента

# Восстановление состояния оптимизатора и мастер-веса
m = dequantize_momentum(m_q, m_s)
v = dequantize_variance(v_q, v_s)
θ = decompress(θ', ρ)

# Стандартное обновление оптимизатора
m = β₁ * m + (1-β₁) * g
v = β₂ * v + (1-β₂) * g²
m̂ = m / (1-β₁^t)
v̂ = v / (1-β₂^t)
θ_new = θ - η * (m̂ / (sqrt(v̂) + ε) + λθ)

# Квантование состояния и разделение веса
m_q, m_s = quantize_momentum(m)
v_q, v_s = quantize_variance(v)
θ', ρ = compress(θ_new)
```

## Варианты оптимизаторов

FlashOptim поддерживает три оптимизатора:

| Оптимизатор | Описание |
|-------------|----------|
| **FlashSGD** | SGD с моментом + компандированное квантование момента |
| **FlashAdamW** | AdamW + разделение весов + компандированное квантование момента и дисперсии |
| **FlashLion** | Lion + компандированное квантование момента |

## Совместимость

FlashOptim совместим с:
- **FSDP (Fully Sharded Data Parallel)** - только 16-битные θ' передаются через all-gather; термин коррекции ρ остаётся локальным с состояниями оптимизатора
- **Activation Checkpointing** - ортогональная техника, может использоваться совместно
- **Gradient Release** - при отключенном накоплении градиентов
- **CPU Offloading** - системная оптимизация, не конфликтует

## Реализация

- **Язык**: Python + Triton для слитых ядер
- **Фреймворк**: PyTorch
- **Доступность**: Открытая библиотека на GitHub

## Преимущества

1. **Экономия памяти >50%** - без потери качества модели
2. **Drop-in замена** - совместимость API с существующими оптимизаторами
3. **Без накладных расходов** - слитые Triton-ядра сохраняют пропускную способность
4. **Композиционность** - работает с FSDP, activation checkpointing, gradient release
5. **Уменьшение размера чекпоинтов** - более чем в 2 раза

## Ограничения

- Требуется поддержка BF16 на GPU
- Triton-ядра могут потребовать дополнительной настройки для специфичных hardware

## Новые концепции и термины

- **Weight Splitting (Разделение весов)** - техника хранения низкоточного веса + термина коррекции вместо полноточного мастер-веса
- **Companding (Компандирование)** - нелинейное преобразование перед квантованием для улучшения распределения значений по бинам
- **ULP (Unit in the Last Place)** - единица последнего разряда, минимальное различие между соседними числами с плавающей точкой
- **Absmax Normalization** - нормализация по максимальному абсолютному значению в группе
- **Group-wise Quantization** - квантование тензоров группами с отдельным масштабом на группу

## Примеры применения

- **Тонкая настройка LLM на ограниченном hardware** - обучение 7B моделей на <100 ГБ памяти
- **Исследования с ограниченным бюджетом** - доступ к обучению больших моделей без множественных GPU
- **Экономия места для чекпоинтов** - уменьшение хранилища для сохранённых моделей
