# Flash-KMeans: Быстрая и энергоэффективная точная K-Means кластеризация

## Общее описание

**Flash-KMeans** — это оптимизированная реализация алгоритма K-Means для современных GPU, разработанная исследователями из UC Berkeley. Алгоритм достигает ускорения до **17.9×** по сравнению с лучшими базовыми реализациями и до **200×** по сравнению с индустриальными библиотеками вроде FAISS и cuML, при этом сохраняя математическую точность (без аппроксимаций).

## Проблема: почему K-Means медленный на GPU

Несмотря на то что K-Means считается «решённой» задачей, стандартные реализации на GPU имеют фундаментальные ограничения:

### 1. IO-ограничение на этапе назначения (Assignment)
При работе с N=65536 точек, K=1024 центроидов, d=128 измерений:
- **Вычисление расстояний:** 2.6 мс
- **Запись/чтение матрицы расстояний N×K в HBM:** 23 мс
- Материализация промежуточной матрицы D ∈ R^(N×K) создаёт огромный трафик памяти

### 2. Конкуренция атомарных операций на этапе обновления
- Scatter-обновления с атомарными операциями вызывают серьёзную конкуренцию
- Множество потоков обновляют одни и те же «горячие» центроиды
- Измеренная пропускная способность: только 50 GB/s на NVIDIA H200 (значительно ниже теоретического предела)

### 3. Системные ограничения
- Chunk-wise выполнение для больших данных вводит накладные расходы PCIe
- Динамические формы данных увеличивают время компиляции и настройки

## Решение: Flash-KMeans

Flash-KMeans не изменяет математическую формулировку K-Means и не вносит аппроксимаций. Вместо этого алгоритм реструктурирует выполнение вокруг аппаратных ограничений GPU.

### Ключевые техники

#### 1. FlashAssign: Материализация-фри назначение

**Проблема:** Стандартные реализации явно материализуют матрицу расстояний D ∈ R^(N×K) в HBM.

**Решение:** FlashAssign объединяет вычисление расстояний с онлайн argmin процедурой в единый streaming-процесс.

**Как работает:**
- Для каждой точки x_i поддерживаются два состояния в регистрах:
  - m_i — текущее минимальное расстояние (инициализируется +∞)
  - a_i — соответствующий индекс центроида (инициализируется -1)
- Центроиды сканируются тайлами
- Для каждого тайла вычисляются локальные расстояния на чипе
- Состояния (m, a) обновляются через онлайн argmin
- Полная матрица N×K никогда не материализуется в памяти

**Результат:**
- IO-сложность снижается с O(NK) до O(Nd + Kd)
- Устраняется 2·Θ(NK) трафик HBM
- **Ускорение ядра назначения: до 21.2×**

#### 2. Sort-Inverse Update: Обновление с низкой конкуренцией

**Проблема:** Scatter-обновления вызывают атомарную конкуренцию на уровне токенов.

**Решение:** Явное построение обратного отображения через argsort для трансформации irregular scatter в regular segmented reductions.

**Как работает:**
1. Применяется argsort к вектору назначений a для получения permutation index sorted_idx
2. Формируется отсортированная последовательность cluster-id a_sorted
3. Идентичные cluster-id группируются в contiguous cluster-id segments
4. Каждый CTA обрабатывает contiguous chunk отсортированной последовательности
5. Частичные суммы накапливаются полностью в on-chip памяти (регистры или shared memory)
6. Глобальные atomic_add в HBM выполняются только на границах сегментов

**Результат:**
- Scatter-обновления трансформируются в gather-операции
- Атомарная конкуренция устраняется
- **Ускорение ядра обновления: до 6.3×**

#### 3. Алгоритм-система co-design оптимизации

**Chunked Stream Overlap:**
- Асинхронный pipeline для out-of-core выполнения
- Перекрывает PCIe коммуникацию с вычислениями
- Масштабируется до 1 миллиарда точек
- **Ускорение: до 10.5×** для extreme large-scale settings

**Cache-Aware Compile Heuristic:**
- Надёжно подбирает near-optimal конфигурации без дорогой настройки
- **Снижение накладных расходов настройки: до 175×**
- Деградация производительности: всего 0.3%

```
┌─────────────────────────────────────────────────────────────┐
│                    Flash-KMeans Pipeline                     │
├─────────────────────────────────────────────────────────────┤
│  Input: X ∈ R^(N×d), C ∈ R^(K×d)                            │
├─────────────────────────────────────────────────────────────┤
│  Stage 1: FlashAssign                                        │
│  ├─ Streaming distance computation                          │
│  ├─ Online argmin (без материализации N×K)                  │
│  └─ Output: assignments a ∈ {1,...,K}^N                     │
├─────────────────────────────────────────────────────────────┤
│  Stage 2: Sort-Inverse Update                                │
│  ├─ Argsort assignments                                     │
│  ├─ Segment-level localized reductions                      │
│  └─ Output: updated centroids C_new                         │
├─────────────────────────────────────────────────────────────┤
│  System Optimizations:                                       │
│  ├─ Chunked stream overlap (PCIe hide)                      │
│  └─ Cache-aware compile heuristic                           │
└─────────────────────────────────────────────────────────────┘
```

## Применение в современных AI workload

Flash-KMeans позволяет использовать K-Means как онлайн-примитив в:

1. **LLM training/inference**:
   - Динамическая маршрутизация токенов для sparse attention (MoE)
   - Семантическое слияние состояний для KV cache компрессии

2. **Генеративные модели**:
   - Семантически-осознанная перестановка токенов в Diffusion Transformers
   - Экстремальное низкоразрядное квантование

3. **Поисковые системы**:
   - Веб-масштабная семантическая дедупликация
   - Квантование эмбеддингов для late-interaction поиска

## Связь с FlashAttention

Flash-KMeans вдохновлён философией FlashAttention:
- Оба метода оптимизируют dataflow памяти, а не изменяют математику
- Оба используют tiling и kernel fusion для устранения промежуточных чтений/записей
- Оба достигают ускорения через устранение IO-бутылочных горлышек
