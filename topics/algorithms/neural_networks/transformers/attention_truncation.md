# Attention Truncation

## Описание

Attention Truncation - это техника оптимизации глубины обработки в трансформерных архитектурах, разработанная Meta для ULTRA-HSTU. Вместо применения одинакового количества слоёв внимания ко всей последовательности, Attention Truncation использует **двухфазную обработку**: полные слои для всей последовательности + дополнительные слои только для важного сегмента.

## Проблема

Даже с оптимизациями типа Semi-Local Attention (SLA), каждый слой внимания остаётся вычислительно дорогим для:
- Длинных последовательностей (16,000+ токенов в ULTRA-HSTU)
- Глубоких моделей (18+ слоёв в ULTRA-HSTU)
- Высокой нагрузки в продакшене

**Квадратичная сложность** (или линейная с SLA) умножается на **глубину модели**, создавая значительные вычислительные затраты.

## Архитектурное Решение

Attention Truncation предлагает **иерархическую глубину обработки**:

### Двухфазная Архитектура

```
Фаза 1: N слоёв по всей последовательности
        ↓
Фаза 2: Выбор сегмента L' (свежие события)
        ↓
Фаза 3: M слоёв только по сегменту L'
```

### Детали Фаз

**Фаза 1: Глобальная Обработка**
- Применяется **N слоёв** Semi-Local Attention
- Обрабатывается **вся последовательность** длины L
- Извлекаются глобальные паттерны и зависимости
- Результат: контекстуализированные представления для всех токенов

**Фаза 2: Сегментация**
- Выбирается сегмент длины **L'** из полной истории
- **Критерий выбора**: самые свежие события (recent interactions)
- Обоснование: недавние взаимодействия наиболее релевантны для предсказания

**Фаза 3: Локальная Углублённая Обработка**
- Применяется **M дополнительных слоёв**
- Только по сегменту длины **L'** (L' << L)
- Глубокая обработка недавних событий
- Результат: уточнённые представления для критичных токенов

## Пример Конфигурации

В ULTRA-HSTU используется схема **3 + 6 слоёв**:

| Параметр | Значение |
|----------|----------|
| N (глобальные слои) | 3 |
| M (локальные слои) | 6 |
| L (полная длина) | 16,000 |
| L' (сегмент) | ~1,000-2,000 (оценка) |
| **Всего слоёв** | **9** (эффективных) |

### Сравнение с Базовой Архитектурой

| Архитектура | Слои | FLOPs (инференс) | Относительная стоимость |
|-------------|------|------------------|------------------------|
| HSTU (базовая) | 6 слоёв × полная длина | Базовые | 1.0× |
| **ULTRA-HSTU с Attention Truncation** | **3 + 6 слоёв** | **↓ в 1.5 раза** | **0.67×** |

## Результаты в ULTRA-HSTU

| Метрика | Значение |
|---------|----------|
| Уменьшение FLOPs (инференс) | **↓ в 1.5 раза** (относительно HSTU с 6 слоями) |
| Конфигурация | 3 + 6 слоёв |
| Сохранение качества | ✅ Да (неявно из контекста) |

## Обоснование Подхода

### Почему Это Работает

1. **Принцип Парето для последовательностей**: 80% сигнала содержится в 20% недавних событий
2. **Иерархия зависимостей**:
   - Глобальные слои захватывают долгосрочные паттерны
   - Локальные слои углубляют понимание текущих интересов
3. **Вычислительная эффективность**:
   - Дорогие глубокие слои применяются только к малой части данных
   - Дешёвые мелкие слои обрабатывают весь контекст

### Связь с Природой Рекомендаций

В рекомендательных системах:
- **Недавние взаимодействия** сильнее предсказывают следующее действие
- **Долгосрочные паттерны** важны для общего контекста
- Attention Truncation балансирует оба аспекта

## Сравнение с Другими Техниками Оптимизации

### vs. Adaptive Computation Time

- **ACT**: Динамически определяет количество вычислений на токен
- **Attention Truncation**: Фиксированная двухфазная структура
- **Преимущество AT**: Предсказуемое время выполнения, проще для продакшена

### vs. Early Exiting

- **Early Exiting**: Позволяет некоторым токенам выходить раньше
- **Attention Truncation**: Все токены проходят Фазу 1, избранные → Фазу 3
- **Разница**: AT не имеет "раннего выхода", имеет "позднее углубление"

### vs. Hierarchical Transformers

- **Hierarchical**: Иерархия по структуре данных (предложения, абзацы, документы)
- **Attention Truncation**: Иерархия по важности сегментов последовательности
- **Применение**: AT специализирован для temporal sequences

## Интеграция с Другими Оптимизациями ULTRA-HSTU

Attention Truncation работает в синергии с:

1. **Semi-Local Attention (SLA)**
   - SLA уменьшает сложность каждого слоя
   - AT уменьшает количество "полных" слоёв
   - **Комбинированный эффект**: мультипликативное ускорение

2. **Mixed Precision (BF16/FP8)**
   - Уменьшает стоимость каждой операции
   - AT уменьшает количество операций
   - **Комбинированный эффект**: аддитивное ускорение

3. **Отказ от interleaved представления**
   - Уменьшает FLOPs на вход
   - AT уменьшает FLOPs на слои
   - **Комбинированный эффект**: полное ускорение пайплайна

## Потенциальные Применения за Пределами RecSys

Attention Truncation может быть полезен в:

1. **Языковое Моделирование**
   - N слоёв на весь документ
   - M слоёв на текущий абзац/предложение

2. **Временные Ряды**
   - N слоёв на всю историю
   - M слоёв на недавний период

3. **Видео Анализ**
   - N слоёв на всё видео
   - M слоёв на текущие кадры

4. **Диалоговые Системы**
   - N слоёв на всю историю диалога
   - M слоёв на последние реплики

## Гиперпараметры и Настройка

### Критичные Параметры

| Параметр | Описание | Влияние |
|----------|----------|---------|
| N | Количество глобальных слоёв | Захват долгосрочных зависимостей |
| M | Количество локальных слоёв | Глубина обработки недавних событий |
| L' | Длина сегмента | Баланс скорость/качество |
| Критерий сегментации | Как выбирать L' | Релевантность для задачи |

### Рекомендации по Настройке

- **N**: 2-4 слоя обычно достаточно для глобального контекста
- **M**: 4-8 слоёв для глубокой локальной обработки
- **L'**: 5-15% от полной длины последовательности
- **Критерий**: Recent-first для temporal данных

## Преимущества

1. **Вычислительная эффективность**: Значительное уменьшение FLOPs
2. **Сохранение качества**: Глобальный контекст не теряется
3. **Гибкость**: Можно настраивать N, M, L' под задачу
4. **Совместимость**: Работает с другими оптимизациями внимания

## Ограничения

1. **Гиперпараметры**: Требует настройки N, M, L'
2. **Специфичность**: Лучше работает для temporal/recent-relevant данных
3. **Сложность**: Дополнительная логика сегментации
