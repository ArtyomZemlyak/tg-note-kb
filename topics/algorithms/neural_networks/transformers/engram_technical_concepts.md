# Технические концепции Engram: Углубленный анализ

## Архитектурные инновации

### Модуль условной памяти (Conditional Memory Module)

Engram представляет собой специфическую архитектурную инновацию, которая внедряет massive статические таблицы эмбеддингов N-грамм прямо в слои трансформера. Фундаментальное предположение: значительная часть лингвистических сигналов — именованные сущности, шаблонные фразы и идиомы — подчиняется закону Ципфа и достаточно статична, чтобы быть выгруженной в таблицу поиска.

### Разделение памяти и вычислений

Парадигма Engram основывается на четком разделении:
- **Хранение знаний**: Реализуется через статические таблицы эмбеддингов (O(1).lookup)
- **Нейронные вычисления**: Осуществляются через традиционные слои трансформера
- **Интеграция**: Через механизм контекстно-зависимого гейтинга

## Механизмы извлечения и управления памятью

### Многоголовое хэширование (Multi-Head Hashing)

Процесс извлечения данных через хэширование:

1. **Tokenizer Compression**: Перед построением n-грамм применяются **детерминированные преобразования** для приведения токенов к canonical ID. Это аналог стемминга или лемматизации, но для токенов — нормализация регистра, пробелов и поверхностных форм.

2. **Извлечение суффиксных N-грамм**: Для токена в позиции t извлекаются 2- и 3-граммы

3. **Hash Embeddings подход**: Напрямую индексировать n-граммы нельзя (их слишком много), поэтому используется вариация **multiplicative-XOR хэширования** для уменьшения коллизий в рамках небольшого словаря. Для каждой n-граммы получают хеш — одно число.

4. **Многоголовое хэширование**: Используется несколько голов, поэтому на выходе получается **несколько хешей-чисел** для каждой n-граммы. Это буквально индексы, по которым получают вектора из `nn.Embedding`, где у каждой головы и n-граммы независимые вектора — и дальше их конкатенируют.

### Контекстно-зависимое гейтинг (Context-Aware Gating)

Критически важный механизм фильтрации шума, вдохновленный dot product attention:

- **Запрос (Query)**: Текущее скрытое состояние слоя (hidden state) служит как Query
- **Ключ/Значение (Key/Value)**: К извлеченным эмбеддингам применяются линейные преобразования, аналогичные `W_K` и `W_V` в attention
- **Branch-specific fusion**: В mHC-архитектуре для каждой ветки используется **свой W_K** — это один из самых важных компонентов по результатам абляций
- **Вычисление шлюза**: В отличие от attention здесь **нет софтмакса**, вместо него используется **сигмоида**, а полученные скоры поэлементно перемножаются с V
- **Функция**: Определяет, релевантна ли извлеченная память текущему семантическому контексту
- **Результат**: Если паттерн совпадает с контекстом, накопленным в h_t, шлюз открывается, и память вливается в residual stream

### Суръективная функция P:V→V'

Для максимизации семантической плотности памяти:
- **Назначение**: Схлопывает сырые ID токенов в канонические идентификаторы
- **Нормализация**: Обработка регистра и пробелов
- **Результат**: Ключ памяти представляет собой семантический концепт, а не поверхностную форму записи

## Закон разреженности (Sparsity Allocation Law)

### Эмпирическое открытие

Исследование распределения параметров между MoE и Engram:
- **Методология**: Изучение, как разделить фиксированный бюджет "неактивных" параметров
- **Результат**: Четкая U-образная кривая на валидационном лоссе
- **Оптимум**: Перераспределение ~20-25% бюджета разреженных параметров в Engram

### Подходы к распределению

| Тип распределения | Процент параметров | Назначение | Эффект |
|-------------------|--------------------|------------|--------|
| Чистый MoE | 100% на экспертов | Условные вычисления | Субоптимально (тратит вычисления на статичные паттерны) |
| Чистый Engram | 100% на память | Условная память | Проваливается (недостаток динамической способности к рассуждению) |
| Гибридный | ~20-25% на Engram | Комбинация | "Золотая середина" |

## Инженерные особенности эффективности

### Стратегия Prefetch-and-Overlap

Критическое преимущество Engram:
- **Детерминизм**: Индексы зависят исключительно от входной последовательности токенов
- **Время известности**: Последовательность известна до начала прямого прохода
- **Параллелизация**: Возможность загружать эмбеддинги из Host RAM пока GPU считает предыдущие слои

### Обход ограничений HBM

- **Масштабируемость**: Параметры памяти могут масштабироваться линейно с дешёвой системной RAM
- **Ограничения**: Не связаны с объемом HBM видеокарт
- **Эффективность**: Вынос массивной таблицы эмбеддингов на 100B параметров в память CPU даёт <3% оверхед на инференсе

## Анализ эффективности

### Ранняя готовность к предсказанию

Использование LogitLens и CKA показало:
- **Результат**: Модель достигает "состояний готовности к предсказанию" намного раньше в сети
- **Механизм**: Модуль Engram действует как шорткат
- **Эффект**: Избавляет ранние слои трансформера от необходимости конструировать фичи для статических сущностей

### Выравнивание представлений

Тепловые карты CKA подтвердили:
- **Наблюдение**: Представления в неглубоких слоях Engram выравниваются с гораздо более глубокими слоями базовой MoE модели
- **Интерпретация**: Ранние слои получают предварительно вычисленные представления для статических паттернов

### Улучшение производительности

Преимущества особенно выражены в задачах с длинным контекстом:
- **Разделение обязанностей**: Локальное моделирование зависимостей (например, отслеживание имени "Alexander" рядом с "Great") делегируется таблице поиска
- **Сохранение ёмкости**: Механизм внимания сохраняет свою ёмкость для глобального контекста
- **Результат**: Радикальные улучшения в бенчмарках Needle In A Haystack (Multi-Query NIAH прыгнул с 84.2 до 97.0)

## Ограничения и жесткости

### Врожденные ограничения статических лукапов

- **Тип памяти**: Только для чтения во время инференса
- **Адаптивность**: Невозможность адаптации к новым знаниям без переобучения
- **Зависимость от фильтрации**: Работоспособность зависит от способности модели фильтровать нерелевантную выдачу

### Обучение-инференс несоответствие

- **Проблема**: Бэкбон становится зависимым от наличия модуля памяти
- **Последствия**: Возможная деградация на задачах знаний, если модуль становится "костылем", а не дополнением

## Практические наблюдения

### Развитие архитектурных парадигм

Engram представляет собой архитектурный сдвиг в подходе к памяти:
- **До**: Память как эмерджентное свойство вычислений
- **После**: Память как отдельный, оптимизируемый примитив
- **Итог**: Верифицированный метод расширения ёмкости моделей за пределы физических ограничений GPU кластеров

### Применение в масштабировании моделей

- **Стратегия**: Разделение модели на "умные" (рассуждения) и "ёмкие" (память) компоненты
- **Результат**: Одновременно умнее (выделение вычислений на рассуждения) и масштабнее (выделение памяти в RAM хоста)
- **Перспективы**: Путь к масштабированию моделей за пределы HBM видеокарт

### Важные компоненты по результатам абляций

Самыми важными компонентами Engram-модуля оказываются:
1. **Branch-specific fusion** — свой W_K для каждой ветки в mHC-архитектуре
2. **Context-aware gating** — механизм фильтрации на основе сигмоиды
3. **Tokenizer compression** — детерминированные преобразования для canonical ID

Меньше влияют:
- Свёртка по seq_len
- Добавление 4-граммы (при условии, что будут делить общий бюджет параметров с 2- и 3-граммами)

### Sensitivity анализ

Исследователи проводят sensitivity-анализ, зануляя выход Engram-модуля, и видят, что **сильнее всего это бьёт по задачам, требующих factual knowledge**.

Так получается, потому что у модели увеличивается **effective depth**: ранним слоям не нужно заниматься knowledge lookup (имитировать его), и больше слоёв теперь могут «думать».
