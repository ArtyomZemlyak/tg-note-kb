# Оптимизация FP4 кернелов для MoE на NVIDIA Blackwell

## Описание

Недавний блог-пост от Hugging Face (https://huggingface.co/blog/apsys/blackwell-nvfp4-comparison) представляет детальный анализ оптимизации FP4 кернелов для Mixture-of-Experts (MoE) моделей на архитектуре NVIDIA Blackwell. Анализ сравнивает подходы к оптимизации в различных фреймворках: vLLM, SGLang и FlashInfer.

## Основные результаты производительности

### Сравнение фреймворков
- **SGLang**: 1262 TFLOPS при размере батча 4096
- **FlashInfer CuteDSL**: 1225 TFLOPS при размере батча 4096
- **vLLM**: 1117 TFLOPS при размере батча 4096
- **Разница**: 145 TFLOPS между SGLang и vLLM

### Производительность при малых батчах
- **Преимущество SGLang**: 1.32x ускорение над vLLM при размере батча 1
- **Интерактивный инференс**: Особенно выгоден для вариантов BS=1-16

## Оптимизации по фреймворкам

### Оптимизации в SGLang
1. **Слияние кернелов (Kernel Fusion)**: Сокращает 7 запусков кернелов до 5, устраняя накладные расходы на перестановку
2. **CUTLASS для Blackwell**: Использует специфическую конфигурацию `KernelPtrArrayTmaWarpSpecialized1SmNvf4Sm100`
3. **Адаптивное масштабирование сетки (Adaptive Grid Sizing)**: Максимизирует занятость SM при малых батчах
4. **Слитый кернел редукции**: Комбинирует переупорядочивание токенов, умножение весов маршрутизации и редукцию top-K в одном кернеле

#### Реализация слияния кернелов
Слитый кернел редукции SGLang объединяет три операции в одном кернеле:

```cuda
template <typename T, typename scalar_t>
__global__ void apply_shuffle_mul_sum_kernel(
    const T* __restrict__ input,           // [m*topk, k]
    const int* __restrict__ permutation,   // [m*topk] mapping
    const scalar_t* __restrict__ weights,  // [m, topk] routing weights
    T* __restrict__ output,                // [m, k]
    int m, int k, int topk
)
```

#### Конфигурация CUTLASS для Blackwell
SGLang использует специфическую конфигурацию для Blackwell:

```cuda
using ThreadBlockShape = Shape<_128, _128, _128>;
using ClusterShape = Shape<_1, _1, _1>;
using AlignmentA = 32;
using AlignmentB = 32;
using KernelSchedule = cutlass::gemm::KernelPtrArrayTmaWarpSpecialized1SmNvf4Sm100;
```

Особенности:
- Специализация варпов для FP4
- Интеграция TMA (Tensor Memory Accelerator)
- Нативная поддержка NvFP4
- Принудительное выравнивание 128 байт с паддингом

### Подход vLLM
1. **Последовательная обработка**: Использует 7 отдельных CUDA кернелов для прямого прохода MoE:
   - Переупорядочивание токенов
   - Квантование активаций в FP4
   - Первое GEMM (проекция gate_up)
   - Активация SiLU
   - Промежуточное квантование
   - Второе GEMM (проекция down)
   - Переупорядочивание вывода обратно в исходный порядок

### Подход FlashInfer
1. **Layout по экспертам**: Преобразует формат из токен-первый в эксперт-первый
2. **Накладные расходы на предварительную обработку**: Операции сортировки и разброса, которые ухудшают производительность при малых батчах
3. **Маскированное GEMM**: Поддерживает паддированные выходы экспертов для лучшего объединения памяти

#### Адаптивное масштабирование сетки
SGLang динамически регулирует конфигурацию запуска кернелов:

```cuda
// Динамическая настройка: уменьшение размера блока вдвое, удвоение размера сетки
while (grid.x <= multiProcessorCount && block.x > 64) {
    grid.x *= 2;
    block.x = (block.x + 1) / 2;
}
```

## Анализ пропускной способности памяти

- **vLLM**: 26.5 MB трафика активационной памяти на слой
- **SGLang**: 20.7 MB трафика активационной памяти на слой
- **Экономия**: 21.9% снижение трафика активационной памяти за счет слияния

## Сравнение фреймворков

| Аспект | SGLang | vLLM | FlashInfer |
|--------|--------|------|------------|
| **Пик TFLOPS** | 1262 | 1117 | 1225 |
| **Производительность при батче 1** | 206.9μs/слой | 369.5μs/слой | 481.9μs/слой |
| **Оптимизация малых батчей** | Отличная | Хорошая | Плохая |
| **Слияние кернелов** | 5 кернелов (слившиеся) | 7 кернелов (отдельные) | Переменное |
| **Эффективность памяти** | Высокая | Низкая | Средняя |
| **Производительность при больших батчах** | Отличная | Хорошая | Отличная* |

*FlashInfer показывает лучший результат с 256+ экспертами благодаря преимуществам layout'а по экспертам.

## Характеристики инференса MoE

- **Интерактивный инференс** (BS=1-16) получает наибольшую пользу от оптимизаций SGLang
- **Оптимальная точка для декодирования** (BS=128) показывает 28.3% ускорение для SGLang по сравнению с vLLM
- **Большие батчи** (BS=4096) показывают сходимость производительности, так как становятся compute-bound
- **Влияние количества экспертов**: При 256 экспертах разрыв производительности сужается из-за увеличенной параллелизма

## Рекомендации для разработчиков фреймворков

1. **Агрессивное слияние**: Направленность на 3-4 запусков кернелов для минимизации задержки токен-к-токену
2. **Оптимизированные расписания для железа**: Использование архитектурно-оптимизированных конфигураций CUTLASS
3. **Адаптивные эвристики запуска**: Оптимизация для разных режимов размера батча
4. **TMA выравнивание**: Паддинг тензоров до границ 128 байт
5. **Бенчмаркинг малых батчей**: Фокус на оптимизации BS=1-16 для интерактивных сценариев использования

Анализ показывает, что одной аппаратной поддержки FP4 недостаточно; системная инженерия кернелов необходима для раскрытия потенциала Blackwell для инференса MoE.
