# Looped Transformers

## Общее описание

Looped Transformers (петлевые трансформеры) — инновационная архитектура трансформеров, в которой один и тот же блок трансформера с общими весами применяется рекурсивно несколько раз перед генерацией токена. Архитектура позволяет выполнять многократные итерации в латентном пространстве, обеспечивая более глубокие рассуждения без пропорционального увеличения числа параметров.

Ключевая идея: модель «думает молча» в латентном пространстве, уточняя внутренние представления итеративно, без декодирования промежуточных мыслей в текст.

## Ключевые особенности

### 1. Отдельная голова для выхода из итераций (Loop Head)
- Архитектура включает специализированную голову, определяющую, когда завершить итеративный процесс
- Позволяет модели решать, когда достигнуто достаточное качество решения
- Улучшает эффективность за счет предотвращения избыточных вычислений

### 2. Оптимизация через ELBO
- Использует Evidence Lower BOund (нижнюю оценку доказательства) для оптимизации
- Применяет вариационные оценки для обучения итерационных процессов
- Эта методика может стать важной тенденцией в будущих моделях

### 3. Адаптивные вычисления
- Модель может использовать различное количество вычислений в зависимости от сложности задачи
- Для простых задач требуется меньше итераций, для сложных - больше
- Повышает общую эффективность использования вычислительных ресурсов

### 4. Латентные рассуждения (Latent Reasoning)
- Модель выполняет многократные итерации в латентном пространстве перед генерацией токена
- Промежуточные представления не декодируются в текст («мышление молча»)
- Экономия токенов на промежуточных рассуждениях по сравнению с Chain-of-Thought

### 5. Обучение с подкреплением (RLTT)
- **RLTT (Reward Latent Thought Trajectories)** — метод RL для петлевых моделей (Williams & Tureč, 2026)
- Распределяет вознаграждение по всей траектории латентных рассуждений
- Решает проблему credit assignment в латентном пространстве
- Показывает значительные улучшения на бенчмарках (GSM8K +10 п.п., MATH-500 +36 п.п., GPQA ~2×)

## Архитектурные компоненты

### Loop Head Mechanism
Специализированная компонента, отвечающая за принятие решения о выходе из итерационного процесса. Она оценивает текущее состояние и решает, продолжать ли итерации или завершить процесс.

### Iterative Processing Units
Модифицированные блоки трансформера, способные выполнять многократные итерации над входными данными, уточняя представления с каждой итерацией.

### Формула петлевого процесса

Для каждого токена y_t:
```
h⁰ = эмбеддинг промпта
Для k = 1...K итераций:
  hᵏ = Transformer(hᵏ⁻¹)  # общие веса
  pᵏ = языковая голова(hᵏ)  # промежуточное распределение
Использовать только p^K для генерации
```

### Обозначения
- `(k ⊗ L)` — k-слойная модель, зацикленная L раз
- `(k ⊗ 1)` — базовая модель с k слоями (iso-param)
- `(kL ⊗ 1)` — kL-слойная модель без зацикливания (iso-flop)

## Преимущества

- **Адаптивная сложность вычислений**: Модель использует столько вычислительных ресурсов, сколько действительно необходимо
- **Повышенная эффективность**: Избегание избыточных вычислений для простых задач
- **Лучшее качество решений**: Возможность дополнительных итераций для сложных задач
- **Гибкость**: Адаптация к различным уровням сложности задач в реальном времени
- **Параметрическая эффективность**: Петлевые модели достигают производительности более глубоких моделей с меньшим числом параметров
- **Выразительность**: Петлевые трансформеры строго мощнее обычных (Saunshi et al., 2025)
- **Борьба с overthinking**: Модель учится сходиться к ответу быстрее при обучении с RLTT

## Проблемы и вызовы

### AI Safety Concerns
- **Потеря прозрачности**: невозможно мониторить рассуждения через текст
- **CoT-мониторинг бесполезен**: один из работающих инструментов AI safety не применим
- **Оптимизация «скрытых мыслей»**: RLTT усугубляет проблему непрозрачности

### Вычислительная стоимость
- **Память**: увеличивается в K раз (нужно хранить логарифмы для каждой итерации)
- **Скорость**: быстрее GRPO (если не учитывать память)
