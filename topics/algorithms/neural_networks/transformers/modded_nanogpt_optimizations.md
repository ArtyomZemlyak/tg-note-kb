# Оптимизации в проекте Modded-nanogpt: Современные методы ускорения обучения трансформеров

## Краткое описание

Проект KellerJordan/modded-nanogpt представляет собой коллаборативный "спидран" по поиску наиболее эффективных алгоритмов для обучения языковых моделей, достигающих 3.28 кросс-энтропийной потери на валидационном наборе FineWeb. За счет применения множества техник обучения, архитектурных улучшений и системных оптимизаций, время обучения было сокращено с 45 минут (базовая реализация GPT-2 от Andrej Karpathy в llm.c) до 2 минут при использовании 8 NVIDIA H100 GPU.

## История улучшений

Изначально проект достиг следующих результатов:
- **2 минуты** на 8xH100 (вместо 45 минут в базовом случае)
- **0.73B токенов** вместо 10B (улучшение в 13.7 раз по эффективности использования данных)

## Архитектурные улучшения

### Современная архитектура

- **Вращательные эмбеддинги (Rotary embeddings)**: Заменяет позиционные эмбеддинги для лучшего представления позиционной информации
- **QK-нормализация (QK-Norm)**: Нормализация векторов запросов (Q) и ключей (K) в механизме внимания для стабилизации обучения
- **ReLU²**: Использование квадратичной активации ReLU² вместо обычного ReLU для улучшения свойств активаций

### Инициализация и параметризация

- **Нулевая инициализация проекций**: Инициализация проекционных слоев нулями (аналогично подходу muP - magnitude-aware parameterization) для стабилизации обучения
- **Раздельная инициализация эмбеддингов и головы выхода**: Отвязка (untie) эмбеддингов и головы выхода (lm_head) на 2/3 обучения

### Skip-соединения

- **Skip-соединения от эмбеддингов ко всем блокам**: Прямые соединения от начальных эмбеддингов ко всем слоям трансформера
- **Skip-соединения от блока 3 к блокам 6**: Дополнительные skip-соединения между конкретными слоями для улучшения потока градиентов

## Оптимизаторы и методы оптимизации

### Muon Optimizer

Muon - это оптимизатор для 2D параметров скрытых слоев нейронных сетей, который использует:
- **SGD с моментом** для генерации обновлений параметров
- **Итерацию Ньютона-Шульца (Newton-Schulz)** для ортогонализации обновлений
- **Нестеровский момент** внутри обновления с ортогонализацией после момента
- **Пятую итерацию Ньютона-Шульца** для приближенной замены G на U @ V.T, где U, S, V = G.svd()

```python
@torch.compile
def zeroth_power_via_newtonschulz5(G, steps=5, eps=1e-7):
    assert len(G.shape) == 2
    a, b, c = (3.4445, -4.7750,  2.0315)
    X = G.bfloat16() / (G.norm() + eps)
    if G.size(0) > G.size(1):
        X = X.T 
    for _ in range(steps):
        A = X @ X.T
        B = b * A + c * A @ A
        X = a * X + B @ X
    if G.size(0) > G.size(1):
        X = X.T 
    return X.to(G.dtype)
```

**Преимущества Muon:**
- Более низкое потребление памяти по сравнению с Adam
- Примерно в 1.5 раза лучшая эффективность по выборкам
- Менее 2% накладных расходов по времени работы

### NorMuon

Улучшенная версия Muon optimizer, которая делает его более эффективным и масштабируемым.

### Polar Express

Реализация Polar Express в Muon - альтернатива для Newton-Schulz, улучшающая вычисления.

### Cautious Weight Decay

Особый подход к весовому затуханию (weight decay) с расписанием, связанным с расписанием скорости обучения (LR).

## Техники внимания и эмбеддингов

### Внимание и Flash Attention

- **Flash Attention 3** с использованием long-short sliding window attention pattern (вдохновленный Gemma 2)
- **Window size warmup с YaRN** (Yet Another RoPE) для динамического изменения размера окна во время обучения
- **Длинно-короткая скользящая оконная схема внимания** для эффективности при длинных последовательностях
- **Разреженный шлюз внимания (Sparse attention gate)** для фильтрации ненужных вычислений

### Значения и дополнительные эмбеддинги

- **Дополнительные эмбеддинги**, смешиваемые в значения в слоях внимания (вдохновлено Zhou et al. 2024)
- **Value Residual Learning**: Техника для смягчения концентрации внимания в трансформерах
- **Смазывание эмбеддингов (Smear module)** для возможности заглядывания на 1 токен назад

## Инициализация и архитектурные схемы

- **Multi-token prediction**: Предсказание нескольких токенов за один шаг
- **Partial model freezing** во время переходов размера батча и размера скользящего окна
- **Exponential decay of residual stream** для улучшения потока информации
- **Partial Key Offset** для оптимизации вычислений

## Системные оптимизации

- **Accumulate gradients** для эмбеддингов и lm_head за 2 шага перед обновлением параметров
- **Enable model to back out contributions** из первых 2/3 слоев перед предсказанием
- **Compute cross entropy in BF16** во время обучения
- **Batch size schedule** для адаптивного изменения размера батча
- **Asymmetric rescale and softcap logits** для стабилизации обучения
- **Use FP8 matmul** для головы (head) и асимметрическое масштабирование

## Обработка данных и последовательностей

- **Align training batch starts** с EoS (End of Sequence) и установка максимальной длины документа
- **Asynchronously fetch and index data batches** для улучшения загрузки данных
- **Extend all long windows for validation** для улучшения качества оценки

## История рекордов

Проект имеет подробную историю улучшений, начиная с 45 минут (базовый llm.c) до 1.94 минут (последний рекорд), включающую более 50 различных улучшений, включая:
- Оптимизации архитектуры
- Улучшения оптимизатора
- Системные оптимизации
- Улучшения внимания
- Оптимизации данных

## Масштабируемость на большие модели

### Что масштабируется:
- **Muon optimizer**: Показывает улучшения при масштабировании до 774M и 1.5B параметров
- **Архитектурные улучшения**: Ряд техник показывает преимущества и на больших моделях
- **Flash Attention 3**: Техники внимания, полезные для моделей с длинными контекстами
- **Оптимизации памяти**: FP8 и другие техники снижают требования к памяти

### Что может не масштабироваться:
- Некоторые структурные ограничения, вводимые специфичными методами (например, logit softcapping)
- Определенные архитектурные предположения, специфичные для этих задач

## Связываемость с другими техниками

- Связан с **Shampoo optimizer** через анализ Бернстайна и Ньюхауса
- Использует **Newton-Schulz итерации** для эффективной ортогонализации (вместо полного SVD)
- Вдохновлен подходами из **Gemma 2** (long-short sliding window attention)
- Основан на **FineWeb** датасете для устойчивой оценки
