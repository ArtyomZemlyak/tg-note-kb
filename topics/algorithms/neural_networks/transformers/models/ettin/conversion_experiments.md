# Эксперименты по конвертации архитектур Ettin

## Цель экспериментов

Целью экспериментов было изучить возможность конвертации между энкодерными и декодерными архитектурами через изменение задачи обучения и дообучение. Исследование рассматривало возможность конвертации:
- CLM (Causal Language Modeling) -> MLM (Masked Language Modeling)
- MLM (Masked Language Modeling) -> CLM (Causal Language Modeling)

## Методология конвертации

### Подход к конвертации
- Взятие предобученной модели одной архитектуры
- Изменение задачи обучения на противоположную (CLM <-> MLM)
- Дообучение на 50B токенов с новой задачей
- Тестирование на задачах, характерных для новой архитектуры

### Основные этапы
1. Обучение оригинальной модели (CLM для декодера, MLM для энкодера)
2. Изменение задачи обучения на противоположную
3. Continued pretraining на 50B токенов с новой задачей
4. Тестирование на новых задачах

## Задачи для тестирования

### Классификация (MNLI)
- **Для всех моделей**: Добавление классификационной головы
- **Тонировка**: На тренировочных данных бенчмарка
- **Оценка**: Сравнение результатов энкодеров и декодеров

### Retrieval (MSMarco)
- **Для всех моделей**: Добавление heads для задачи retrieval
- **Тонировка**: На тренировочных данных бенчмарка
- **Оценка**: Сравнение результатов энкодеров и декодеров

### Генерация (ARC, HS, PIQA и другие)
- **Для декодеров**: Прямая генерация
- **Для энкодеров**: Использование рецепта из "BERTs are Generative In-Context Learners"
- **Оценка**: Качество генерации и способность к рассуждению

## Результаты конвертации

### Общие наблюдения
- **Родные задачи**: Качество падает при добавлении второго шага обучения
- **Неродные задачи**: Небольшое улучшение качества
- **Отсутствие четкого тренда**: Результат зависит от масштаба моделей

### Enc-from-Dec (энкодер из декодера)
- **Преимущества**: Возможность получения энкодерной модели из сильного декодера
- **Ограничения**: Результаты обычно хуже, чем у собственного энкодера
- **Зависимость от масштаба**: В разных масштабах показывает разные результаты

### Dec-from-Enc (декодер из энкодера)
- **Преимущества**: Возможность получения декодерной модели из сильного энкодера
- **Ограничения**: Результаты обычно хуже, чем у собственного декодера
- **Зависимость от масштаба**: В разных масштабах показывает разные результаты

## Анализ результатов

### Почему родные задачи страдают
- Модель "забывает" навыки, полученные при оригинальном обучении
- Конфликт между разными режимами внимания (каузальное vs двунаправленное)
- Переобучение новой задаче влияет на сохранение знаний из первой задачи

### Почему неродные задачи улучшаются
- Модель приобретает новые навыки, полезные для другой задачи
- Некоторые архитектурные особенности остаются полезными
- Частичный перенос знаний между архитектурами

## Практические выводы

### Когда использовать конвертацию
- При недоступности модели нужной архитектуры
- При наличии сильной модели одной архитектуры и потребности в другой
- Для исследовательских целей и понимания архитектурных различий

### Ограничения конвертации
- Конвертированные модели уступают собственным моделям той же архитектуры
- Не является полноценной заменой разработке моделей под конкретную задачу
- Может быть полезна как промежуточное решение при ограниченных ресурсах

## Сравнение с другими подходами

### Отношение к T5Gemma
- T5Gemma: конвертация декодера в энкодер-декодер
- Ettin: конвертация между энкодером и декодером
- Оба подхода изучают гибкость архитектурных преобразований

### Отношение к RedLLM исследованиям
- Исследование "Encoder-Decoder or Decoder-Only?" изучает прямые архитектуры
- Ettin исследует возможность конвертации между ними
- Оба подхода дополняют понимание архитектурной гибкости
