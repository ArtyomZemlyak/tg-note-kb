# NVIDIA Nemotron-ColeEmbed-VL-4B-V2: Сбалансированная модель для визуального поиска документов

## Краткое описание

NVIDIA Nemotron-ColeEmbed-VL-4B-V2 - это сбалансированная модель в семействе ColeEmbed-V2 с 4.8 миллиардами параметров, предназначенная для задач визуального поиска документов. Модель предлагает оптимальное соотношение между производительностью и вычислительными затратами, занимая третье место в бенчмарке ViDoRe V3.

## Архитектура

Модель построена на базе архитектуры Qwen3-VL-4B-Instruct и следует той же трехкомпонентной структуре:

- **Визуальный энкодер**: Архитектура SigLIP-2 для обработки визуальных данных
- **Модуль слияния визуального и языкового**: MLP (Multi-Layer Perceptron) для объединения двух модальностей
- **Большая языковая модель (LLM)**: Qwen3-VL-4B для обработки текстовой информации

Архитектура использует подход late interaction (позднее взаимодействие), что позволяет модели эффективно сопоставлять визуальные и текстовые представления на этапе формирования эмбеддингов.

## Технические характеристики

- **Общее количество параметров**: ~4.8B (5B общий размер модели в BF16 формате)
- **Тип архитектуры**: Transformer-based мультимодальная эмбеддинговая модель
- **Тип взаимодействия**: late interaction (позднее взаимодействие) для задач поиска документов
- **Формат ввода**: Изображение (RGB) и текст (строка)
- **Максимальная длина контекста**: 10,240 токенов
- **Обработка изображений**: 
  - Изображения масштабируются до тайлов 512x512 пикселей
  - Каждый тайл потребляет 256 токенов
  - Поддержка до 8 тайлов + 1 миниатюра (максимум 9 тайлов на изображение)
- **Размерность эмбеддинга**: 2560-мерные векторы для каждого входного токена
- **Формат вывода**: ColBERT-style многовекторные численные представления в формате [batchsize x seq length x embedding_dim]
- **Формат изображений**: Требуется PIL формат

## Производительность

### Рейтинг ViDoRe (Visual Document Retrieval)

Модель занимает **#3 место** в ViDoRe V3 бенчмарке на момент 26 января 2026 года:

#### ViDoRe V3 (NDCG@10):
- **Общий балл**: 61.42 среднее значение по 8 публичным задачам

#### ViDoRe V2 (NDCG@5):
- **Средний балл**: 64.49

#### ViDoRe V1 (NDCG@5):
- **Средний балл**: 91.62

Эти результаты делают модель сильным выбором для приложений, где требуется высокая точность, но с меньшими вычислительными ресурсами по сравнению с 8B версией.

## Методология обучения

- **Тип тонкой настройки**: Fine-tuning для задачи поиска запрос-документ
- **Объем данных для обучения**: Примерно 500k изображений
- **Наборы данных для тренировки**: DocMatix-IR, VDR, Vidore-ColPali-Training, VisRAG-Ret-Train-Synthetic-data, VisRAG-Ret-Train-In-domain-data, Wiki-SS-NQ
- **Метод сбора данных**: Гибридный метод (Автоматический, Человеческий, Синтетический)
- **Ключевые техники**: Fine-tuning на наборах данных, ориентированных на визуальный поиск документов

## Целевые применения

- **Поиск по визуальным документам**: Средний уровень сложности задач поиска визуальных документов
- **Мультимодальные RAG-системы**: Текстовые запросы с изображениями документов в корпоративных приложениях
- **Мультимедийные поисковые движки**: Системы, понимающие как текст, так и визуальные элементы
- **Системы межмодального поиска**: Средства для поиска между текстовыми запросами и изображениями документов
- **Конверсационный ИИ с богатым пониманием ввода**: Приложения с умеренными требованиями к вычислительным ресурсам

## Технические требования и зависимости

- **Требуемые зависимости**: transformers 5.0.0rc0, flash attention 2.6.3
- **Поддерживаемое оборудование**: NVIDIA Ampere (A100 40GB/80GB), Hopper (H100 80GB)
- **Операционные системы**: Linux
- **Тип точности**: BF16 (Brain Floating Point 16)
- **Интеграция ПО**: Совместимость с библиотекой MTEB 2 для оценки

## Сравнение с другими моделями семейства

- **Меньше параметров чем 8B версия**: 4.8B vs 8.8B, что снижает требования к ресурсам
- **Меньше размерность эмбеддинга**: 2560 vs 4096, что снижает требования к памяти
- **Немного ниже производительность**: 61.42 в ViDoRe V3 vs 63.54 у 8B версии
- **Более эффективна для массового использования**: Баланс между точностью и вычислительными затратами
