# Оптимизация KV-кэша через локальность внимания: Подходы и ShadowKV

## Введение

Оптимизация KV-кэша (Key-Value cache) является критически важной задачей для повышения эффективности инференса больших языковых моделей (LLM), особенно при работе с длинными контекстами. Один из современных подходов к этой проблеме основывается на концепции "локальности внимания" (attention locality) - наблюдении, что post-RoPE key cache обладает высокой cosine similarity между соседними токенами, и только небольшая часть токенов выбивается из этого паттерна.

## Локальность внимания в KV-кешировании

Основное наблюдение, лежащее в основе ряда современных методов оптимизации KV-кэша, состоит в том, что post-RoPE key cache обладает свойством attention locality. Это означает, что соседние токены часто имеют высокую cosine similarity, и лишь небольшая часть токенов образует исключения из этого паттерна. Это свойство позволяет использовать различные подходы сжатия и оптимизации доступа к кэшу.

### Ключевые особенности локальности внимания:

1. **Cosine similarity между соседними токенами**: Векторы ключей для близко расположенных токенов в последовательности имеют высокую степень схожести
2. **Небольшой процент "выбросов"**: Только небольшая часть токенов отклоняется от паттерна локальности
3. **Эффективность сжатия**: Благодаря локальности можно применять методы сжатия, такие как chunking (разбиение на чанки по 8 токенов) и построение "landmarks" - репрезентативных средних ключей для чанка

## Подходы к оптимизации KV-кэша

Существует множество подходов к оптимизации KV-кэша:

### Pre-train методы
- Архитектурные решения (GQA/MQA/MLA)
- Смешивание глобального и локального внимания
- Другие модификации архитектуры, требующие дообучения модели

### Post-train методы
- Sparse-стратегии (методы, использующие разреженность для снижения объема KV)
- Pruning (вырезание наименее важных элементов)
- Удаление повторов токенов
- Другие техники, уменьшающие объем KV или сокращающие число обращений к нему

## ShadowKV: Революционный подход к оптимизации KV-кэша

ShadowKV - один из сильнейших post-train методов оптимизации KV-кэша, позволяющий получать минимальные просадки на бенчмарках без дообучения и увеличивать throughput до трёх раз.

### Ключевые идеи ShadowKV:

1. **Разбиение на чанки**: Последовательность токенов разбивается на чанки по 8 токенов
2. **Landmarks**: Для каждого чанка создаются репрезентативные средние ключи (landmarks)
3. **Эффективная выборка**: На этапе декодирования происходит выборка не по всем токенам, а по landmarks каждого чанка
4. **Оптимизация процесса выбора**: Это значительно ускоряет этап выбора ключей на шаге декодирования, а также улучшает доступ к памяти и позволяет лучше насыщать шину

### Архитектурные особенности ShadowKV:

1. **Сжатие pre-RoPE Key**: Ключевой момент - именно pre-RoPE K (до применения RoPE) сжимается через SVD, поскольку он хорошо раскладывается в низкий ранг с минимальной ошибкой, заметно лучше, чем V (Values)
2. **Перемещение V в CPU**: Values не сжимаются, а перемещаются в CPU (RAM), чтобы экономить GPU память и bandwidth
3. **Outliers (выбросы)**: Небольшое число токенов, которые плохо объясняются landmark'ами, выделяется как outliers и сохраняется полноценно. Среди них часто встречаются sink tokens - особый тип токенов, которые играют важную роль в механизме внимания трансформеров

### Бюджет на выбросы:

- Достаточно порядка 0,049% бюджета на выбросы, чтобы достичь точки убывающей отдачи (diminishing returns)
- Это минимальное количество outliers, которое почти полностью закрывает деградацию качества
- Дальнейшее увеличение бюджета дает лишь пренебрежимо малый дополнительный вклад

## Этапы работы ShadowKV

### Prefill-пайплайн:

1. **Параллельная обработка**: Параллельно с основным префиллом быстро вычисляются landmarks и outliers
2. **Перекрытие вычислений**: Вычисление перекрывается с отгрузкой V на CPU
3. **Минимизация критического пути**: Результат - дополнительные шаги минимально увеличивают critical path, потому что большая часть работы делается в overlap-режиме

### Decode-этап:

1. **Выборка по landmarks**: Query (Q) на декодировании скачивается не по всем токенам, а по landmarks каждого чанка
2. **Выбор лучших чанков**: Затем выбираются лучшие чанки, и все токены из выбранных чанков отправляются в kernel attention
3. **Восстановление K**: K восстанавливаются обратно из low-rank пространства
4. **Загрузка V**: Соответствующие V подгружаются из CPU

### Оптимизация через кэширование:

ShadowKV использует дополнительную оптимизацию в духе branch prediction или speculative-подходов:

1. **Стабильность набора токенов**: Между двумя соседними шагами декодирования выбранный набор токенов обычно меняется незначительно, потому что запросы на соседних шагах похожи
2. **Кэширование токенов**: Можно кэшировать уже подгруженные токены для каждого слоя
3. **Разностное вычисление**: На следующем шаге считается разность множеств, догружаются только те токены, которых ещё нет в рабочем наборе
4. **Lossless оптимизация**: Эта оптимизация является lossless относительно ShadowKV, потому что сохраняется инвариант: на каждом шаге в аттеншн всё равно попадает актуальный набор токенов - просто часть из них переиспользуется без повторной загрузки

## Производительность ShadowKV

### На бенчмарках:
- Деградация остается минимальной при бюджете около 1,56% от полного объема KV
- В практических сценариях ShadowKV обеспечивает заметный прирост скорости
- Позволяет поддерживать существенно больший размер батча за счёт снижения нагрузки на VRAM

### Улучшение масштабирования:
- Снижение стоимости attention на длинных контекстах
- Возможность работы с более длинными последовательностями

## Почему оптимизация внимания важна

Вычислительная стоимость attention растёт с длиной последовательности, и на длинных контекстах он начинает доминировать по времени, тогда как FFN (Feed-Forward Network) от длины контекста почти не зависит. 

- На коротких последовательностях в профиле часто доминирует FFN, и ускорение attention даёт небольшой выигрыш
- На длинных контекстах бутылочным горлышком становится attention, и тогда по закону Амдала даже частичное ускорение этой части даёт заметную экономию общего E2E-времени инференса

## Сравнение с другими методами

ShadowKV представляет собой важный прорыв среди методов оптимизации KV-кэша, особенно в сравнении с:

- KVZap (Fast, Adaptive, and Faithful KV Cache Pruning)
- CALM Efficieny Approach
- Другими методами sparse attention

В отличие от этих методов, ShadowKV использует уникальную комбинацию сжатия pre-RoPE K через SVD, перемещения V в CPU и эффективной системы landmarks для быстрой выборки, что обеспечивает более высокую эффективность и меньшую потерю качества.

## Заключение

ShadowKV представляет собой передовой метод оптимизации KV-кэша, использующий концепцию attention locality. Его комбинация сжатия pre-RoPE K, перемещения V в CPU и эффективного механизма landmarks позволяет достичь значительного ускорения инференса с минимальной потерей качества, что делает его особенно ценным для приложений, требующих обработки длинных контекстов.
