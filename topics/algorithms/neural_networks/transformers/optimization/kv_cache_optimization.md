# Оптимизация KV-кеширования (KV Cache Optimization)

[[../attention/online_vector_quantized_attention_ovqa.md|Online Vector-Quantized Attention (OVQA)]] представляет собой современный метод оптимизации использования памяти при обработке длинных контекстов, использующий адаптивное векторное квантование для эффективного управления KV-состоянием.

## Введение

KV-кеширование (Key-Value кеширование) играет ключевую роль в эффективности инференса больших языковых моделей (LLM). Оптимизация KV-кэша направлена на снижение потребления памяти и ускорение процесса генерации текста за счёт уменьшения объема хранения и числа обращений к кэшу. Это особенно важно при работе с длинными контекстами, где квадратичная сложность механизма внимания становится критическим фактором производительности.

## Классификация методов оптимизации KV-кэша

Методы оптимизации KV-кэша можно разделить на две основные категории:

### Pre-train методы
- Требуют изменений до обучения модели
- Архитектурные решения (GQA/MQA/MLA, grouped-query attention, multi-query attention, mixture-of-allignment)
- Смешивание глобального и локального внимания
- Другие модификации архитектуры, обычно требующие переобучения

### Post-train методы
- Могут применяться к уже готовой модели
- Различные sparse-стратегии
- Pruning (сжатие и удаление наименее важных элементов)
- Удаление повторов токенов
- Другие техники, уменьшающие объём KV или сокращающие число обращений к нему во время инференса

## Типы KV-бюджетов

KV-бюджеты удобно делить на dense и sparse, отдельно для prefill и отдельно для decode:

### Dense prefill + Dense decode (обычный KV-кэш)
- Каждый новый Query взаимодействует со всеми Key и Value до него
- Включает токены промпта и все ранее сгенерированные токены
- KV-бюджет равен сумме длины промпта и длины генерации

### Sparse prefill + Dense decode
- Query перестает смотреть на весь промпт, а только на его часть
- Общий выигрыш заметен в основном в сценариях "длинный промпт — короткий ответ"

### Dense prefill + Sparse decode
- Часто релевантно reasoning/CoT (chain-of-thought) сценариям
- Уменьшает объем вычислений при генерации

### Sparse prefill + Sparse decode
- Даёт максимальную экономию бюджета
- Обычно сильнее всего ухудшает качество

## Sparse стратегии

Sparse можно строить по-разному:

### Динамическая пересчетка
- Пересчитываются важные токены на каждом шаге декодирования
- Качество становится выше, но скорость падает

### Периодическая пересчетка
- Пересчитываются раз в несколько токенов
- Получается быстрее, но нужно удерживать локальный контекст между пересчётами
- Иначе модель начинает терять связность

## Основные подходы к оптимизации KV-кэша

### 1. KVZip (KV Cache Compression via Attention-based Importance)
- Оценка важности токенов через attention при реконструкции промпта (teacher-forcing)
- Дублирует входной промпт для оценки важности: `user: <prompt>`, `Repeat the previous context exactly.`, `assistant: <prompt>`
- Требует дополнительный прогон по сети (двухпроходный метод)
- Подходит только для сжатия префикса
- Хорошее качество, но низкая скорость

### 2. KVZap (Fast, Adaptive, and Faithful KV Cache Pruning)
- Метод сжатия KV-кэшей в языковых моделях через предсказание важности токенов
- Использует крошечную модель-суррогат (линейная проекция или MLP) для предсказания важности по hidden state
- **KVZap-Linear**: простейшая линейная проекция, сложность ~0.02% FLOPs
- **KVZap-MLP**: двухслойный перцептрон со скрытым слоем 1/8 от размерности модели, сложность ~1.1% FLOPs
- Порог важности на инференсе: токены выше порога принимаются, ниже — выбрасываются
- Всегда оставляется скользящее окно из последних 128 токенов для сохранения локального контекста
- Сжатие в 2-4 раза без просадки качества на бенчмарках RULER/LongBench и AIME25
- **Ограничение**: нет хорошей реализации, совместимой с Paged Attention (неравномерная длина кэша для голов требует кастомных CUDA-ядер)
- [[kvzap_kv_cache_pruning.md]] — подробное описание метода

### 3. CALM (Control Attention via Latency Monitoring)
- Подход, который контролирует процесс внимания через мониторинг задержек
- Позволяет прервать вычисления внимания заранее, если они не дают значимого улучшения

### 4. Attention Locality-Based Approaches
- Используют наблюдение, что соседние токены часто имеют высокую cosine similarity
- Пример: ShadowKV, который разбивает токены на чанки и создает landmarks

### 5. ShadowKV
- Один из сильных post-train методов оптимизации KV-кэша
- Позволяет получать минимальные просадки на бенчмарках без дообучения
- Увеличивает throughput до трёх раз

#### Особенности ShadowKV:
- Pre-RoPE K (до применения RoPE) сжимается через SVD
- V (Value) не сжимается, а перемещается в CPU (RAM) для экономии GPU памяти
- Использует "landmarks" - репрезентативные средние ключи для чанков
- Ключи разбиваются на чанки по 8 токенов
- Выбросы (outliers) сохраняются полнорангово
- Помогает особенно эффективно на длинных контекстах
- [[attention_locality_kv_cache_optimization.md]] — подробное описание локальности внимания и подхода ShadowKV

## Системы управления KV-кэшем

Для эффективного управления памятью KV-кэша в продакшене используются специализированные системы:

### vLLM
- Цельный inference-движок вокруг Paged Attention
- Зрелая реализация paged-подхода, multi-GPU поддержка через tensor parallel
- Open-source, широкая поддержка моделей
- **Ограничения**: сложнее вклинивать кастомные политики работы с KV, KV-кэш локален узлу

### LMCache
- KV-кэш как отдельный многоуровневый слой (GPU, CPU, SSD, распределённый)
- Поддержка распределённого хранения KV, кросс-сессийное переиспользование
- Фокус на расширяемости и интеграции
- **Ограничения**: сочетание с оптимизациями внутри узла зависит от конкретной интеграции

[[kv_cache_management_systems.md]] — подробное сравнение vLLM и LMCache, архитектуры и особенности управления памятью

## Архитектурные решения

Эти решения уменьшают объем KV-кэша на уровне архитектуры модели (pre-train методы):

### Grouped-Query Attention (GQA)
- Уменьшает объем KV-кэша за счёт группировки ключей и значений
- Меньше K/V-голов при том же числе Q-голов
- Компромисс между эффективностью и качеством

### Multi-Query Attention (MQA)
- Использует один и тот же Key и Value для всех heads
- Наиболее эффективный по памяти, но может ухудшить качество

### Multi Latent Attention
- Подходы с латентными представлениями для сокращения head_dim
- Сокращение размерности представлений ключей и значений

### Mixture-of-Attention (MOA)
- Адаптивный подход, комбинирующий разные типы внимания
- Позволяет балансировать между эффективностью и качеством

## Влияние на производительность

### Память
- KV-кеши занимают значительную часть памяти при генерации
- Для модели с N параметрами, при генерации T токенов, размер KV-кэша составляет ~2×4×N×T байт (в fp16)

### Скорость
- На длинных контекстах операции внимания становятся основным ограничивающим фактором
- Оптимизация KV-кэша позволяет увеличить пропускную способность

### Batch-обработка
- Эффективные методы KV-оптимизации позволяют увеличить размер батча
- Это особенно важно для серверных инференсов

## Сравнение методов

| Метод | Потеря качества | Экономия памяти | Сложность имплементации | Тип |
|-------|----------------|------------------|------------------------|------|
| GQA | Низкая | Умеренная | Низкая | Pre-train |
| MQA | Средняя | Высокая | Низкая | Pre-train |
| KVZap | Низкая | Умеренная | Средняя | Post-train |
| CALM | Низкая | Зависит от порога | Средняя | Post-train |
| ShadowKV | Минимальная | Высокая | Высокая | Post-train |

## Применение в различных сценариях

### Длинные контексты
- KV-оптимизация особенно важна при работе с длинными входными данными
- ShadowKV и аналогичные методы помогают эффективно работать с контекстами в десятки тысяч токенов

### Real-time генерация
- Методы оптимизации позволяют уменьшить задержку (latency)
- Критично для интерактивных приложений

### Edge устройства
- Ограничения по памяти делают KV-оптимизацию обязательной
- GQA и MQA предпочтительны в таких сценариях

## Будущие направления

### Адаптивные методы
- Использование информации о модели для адаптивного выбора стратегии кеширования
- Dynamic cache eviction на основе важности токенов

### Гибридные подходы
- Комбинация нескольких методов для максимальной эффективности
- Использование разных стратегий для разных слоев модели

### Hardware-специфические оптимизации
- Учет специфики GPU/TPU архитектур
- Оптимизация под конкретные устройства
