# Pre-RoPE и Post-RoPE оптимизация в KV-кешировании

## Введение

Rotary Positional Embeddings (RoPE) стали стандартной техникой для кодирования позиционной информации в современных архитектурах трансформеров, поскольку они обеспечивают лучшую экстраполяцию длины последовательности по сравнению с абсолютными позиционными эмбеддингами. Однако использование RoPE создает интересные возможности для оптимизации KV-кеширования, особенно в разработке эффективных методов сжатия, таких как ShadowKV.

## Понимание Pre-RoPE и Post-RoPE представлений

### Pre-RoPE (до применения RoPE)
- Это внутреннее представление ключей (Keys) до применения позиционного кодирования
- Векторы ключей в этом пространстве могут быть проанализированы независимо от их позиции
- Наиболее подходящие для сжатия, так как они хорошо аппроксимируются в низкоранговом пространстве
- Имеют меньше вариативности, вызванной позиционным кодированием, что облегчает сжатие

### Post-RoPE (после применения RoPE)
- Это финальное представление ключей после применения позиционного кодирования
- Используется для фактических вычислений внимания
- Включает в себя позиционную информацию, что делает его более специфичным для каждой конкретной позиции
- Обладает свойством attention locality - соседние токены часто имеют высокую cosine similarity

## Особенности Pre-RoPE представления

### Хорошая сжимаемость
Pre-RoPE K (ключевые векторы до применения RoPE) обладает следующими свойствами:

1. **Хорошо раскладывается в низкий ранг**: Это позволяет использовать SVD (сингулярное разложение) для эффективного сжатия
2. **Минимальная ошибка при сжатии**: В сравнении с V (Value) или другими компонентами, потеря информации минимальна
3. **Стабильная структура**: Не зависит от конкретной позиции, что упрощает анализ и сжатие
4. **Высокая устойчивость к потере информации**: Даже при значительном сжатии сохраняются ключевые характеристики

### Сравнение с V (Value) представлением
В ShadowKV делается наблюдение, что:
- Pre-RoPE K сжимается лучше всего с минимальной ошибкой
- V (Value) сжимается хуже, чем сжатие K через SVD
- Поэтому в ShadowKV используется комбинация: K сжимается, а V перемещается в CPU RAM

## Особенности Post-RoPE представления

### Attention Locality
Post-RoPE K обладает важным свойством attention locality:

1. **Высокая cosine similarity между соседними токенами**: Токены, находящиеся близко друг к другу в последовательности, имеют схожие ключевые векторы
2. **Небольшое количество "выбросов"**: Только определенное количество токенов отклоняется от этого паттерна
3. **Эффективность chunk-based подходов**: Позволяет разбивать последовательности на чанки и создавать "ландмарки"

### Chunking и Landmarks
- Последовательность токенов разбивается на чанки (обычно по 8 токенов)
- Для каждого чанка строятся landmarks - репрезентативные усредненные ключи
- Это значительно ускоряет этап выбора ключей на декодировании
- Улучшает доступ к памяти и позволяет лучше насыщать шину

## Применение в ShadowKV

### Архитектурные решения

1. **Сжатие Pre-RoPE K через SVD**:
   - Pre-RoPE K сжимается с использованием сингулярного разложения
   - Это позволяет значительно уменьшить объем хранимой информации
   - Сохраняется минимальная потеря качества

2. **Перемещение V в CPU (RAM)**:
   - Values не сжимаются, а перемещаются в оперативную память CPU
   - Это позволяет экономить GPU память и пропускную способность
   - V быстро подгружается по мере необходимости

3. **Идентификация Outliers**:
   - Небольшое количество токенов, которые плохо объясняются landmarks
   - Эти токены сохраняются полноразмерно (полнорангово)
   - Часто включает "sink tokens" - токены с особым поведением в механизмах внимания

### Эффективность бюджета Outliers
- Достаточно порядка 0,049% бюджета на выбросы для достижения точки убывающей отдачи
- Это минимальное количество outliers, которое почти полностью закрывает деградацию качества
- Дальнейшее увеличение бюджета дает лишь пренебрежимо малый дополнительный вклад

## Сравнительный анализ

| Представление | Сжимаемость | Потеря качества при сжатии | Применение в оптимизации |
|---------------|-------------|---------------------------|--------------------------|
| Pre-RoPE K | Очень высокая | Минимальная | Основное место сжатия в ShadowKV |
| Post-RoPE K | Умеренная | Умеренная | Используется для locality-based методов |
| V (Values) | Ниже | Значительная при сжатии | Перемещение в CPU RAM |
| Q (Queries) | Не сжимается | N/A | Подвергается тем же позиционным преобразованиям |

## Этапы процесса в ShadowKV

### Prefill-пайплайн
- Параллельно с основным префиллом быстро вычисляются landmarks и outliers
- Процесс вычисления перекрывается с отгрузкой V на CPU
- Дополнительные шаги минимально увеличивают critical path

### Decode-процесс
- Query (Q) на декодировании скачет не по всем токенам, а по landmarks каждого чанка
- Выбираются лучшие чанки, и все токены из выбранных чанков отправляются в kernel attention
- K восстанавливаются обратно из low-rank пространства
- Соответствующие V подгружаются из CPU

### Оптимизация через кэширование
- Между соседними шагами декодирования выбранный набор токенов обычно меняется незначительно
- Кэширование уже подгруженных токенов для каждого слоя
- На следующем шаге считается разность множеств, догружаются только новые токены

## Применение в других методах

### Другие методы, использующие Pre-RoPE/Post-RoPE разницу:
- Attention sink research - изучает особое поведение токенов в KV-кешировании
- Sparse attention методы - используют структуру post-RoPE представлений
- Memory-efficient attention - оптимизируют разные этапы процесса внимания

## Заключение

Различие между Pre-RoPE и Post-RoPE представлениями открывает важные возможности для оптимизации KV-кеширования. ShadowKV ярко демонстрирует, как понимание этих различий может привести к эффективным методам сжатия и ускорения инференса. Основная идея - использовать лучшие свойства каждого представления: сжимаемость Pre-RoPE для уменьшения объема данных и locality Post-RoPE для эффективного выбора релевантных токенов.

Это позволяет достичь минимальной деградации качества при бюджете около 1,56% от полного объема KV, обеспечивая заметный прирост скорости и возможность поддерживать существенно больший размер батча.
