# Улучшения вызова инструментов (Tool Calling) в современных LLM

## Определение

Вызов инструментов (Tool Calling) - это способность LLM распознавать, когда необходимо использовать внешние инструменты, и корректно генерировать вызовы этих инструментов с правильными аргументами. Это ключевой навык для агентских систем, взаимодействующих с внешним миром.

## Подходы к улучшению

### Синтетические цепочки генерации данных для вызова инструментов

#### Синтетическая генерация инструментов

- Применение подхода, основанного на self-instruct
- Сбор всех доступных инструментов из открытых источников и кластеризация их описаний
- Итерационный цикл: генерация новых тем → кластеризация → обновление набора тем
- Генерация функционально связанных наборов инструментов, имитирующих реальные инструменты (например, те, которые доступны в MCP)
- Этап объединения (merge stage), как в статье ByteDance - объединение похожих инструментов через расширение описаний и сигнатур с последующей донастройкой для уточнения аргументов и типов
- Каждый инструмент дополнительно генеративно сжимался для контроля длины описания JSON
- Каждый инструмент имел несколько вариаций: до и после донастройки, разной длины

#### Двухфазная генерация диалога

**Фаза 1: Планирование**
- Вход: несколько наборов инструментов, сгруппированных по темам
- Для каждой группы генерируется контекст и, на основе всех инструментов, создается пользовательская персона
- Создание локальных траекторий - структурированных планов, описывающих цели пользователя, ожидаемые вызовы инструментов и предполагаемые ответы
- Каждая траектория проходит итеративную проверку судьями-LLM на основе логической корректности, полноты завершения цели, реализма и креативности
- Траектории донастраиваются и объединяются в глобальную траекторию с финальной проверкой

**Фаза 2: Многоагентная симуляция**
На основе траектории происходит взаимодействие трех агентов:
- Агент пользователя генерирует реплики в соответствии с целями и персоной, предлагает несколько вариантов - судьи-LLM выбирают лучший
- Агент-ассистент (целевая модель для дистилляции) имеет доступ к инструментам, одновременно генерирует варианты действий: финальный ответ, уточняющий вопрос или вызовы инструментов, выбор делается голосованием судей с дополнительными проверками формата и соответствия траектории
- Агент инструментов симулирует выполнение вызванных инструментов на основе траектории

Когда ассистент ошибается, диалог не прекращается - реплика помечается флагом ошибки, взаимодействие продолжается. Это улучшает способности модели к обобщению в ответе на ошибки.

Каждый диалог разбивается по репликам ассистента: предшествующие сообщения служат контекстом, потери вычисляются только для целевой реплики. Некорректные реплики исключаются из обучения, но остаются в контексте - модель фокусируется на правильных действиях, сохраняя способность распознавать ошибки.

### RL-обучение для вызова инструментов

Для RL-стадии использовалось бинарное вознаграждение (tool-n1), сравнивающее JSON-ответ модели с эталонным. Функция вознаграждения учитывала:

- Формат - структура тегов и порядок элементов
- Корректность JSON для вызовов и полное соответствие эталонным вызовам

### Балансировка RL-датасета

После первых экспериментов наблюдался рост по всем подмножествам BFCL, кроме Irrelevance и Multi Turn. Анализ показал: модель "взломала" вознаграждение - тренировочный датасет не содержал примеров с финальной репликой ассистента, завершающей вызовы инструментов, поэтому они перестали учиться отвечать чем-то другим, кроме вызовов инструментов.

После экспериментов с балансировкой датасета, изменением пропорции Irrelevance (сценарии, где ни один инструмент не релевантен запросу) и пропорции ответа ассистента, был достигнут финальный баланс RL-датасета:
- Язык: 30% русский, 70% английский
- Тип цели: 80% инструменты, 20% текстовый ответ
- Irrelevance: 10% текстовых ответов

## Применение в T-Pro 2.1

В T-Pro 2.1 улучшения вызова инструментов были достигнуты с помощью:
- Синтетических цепочек генерации данных с двухфазной методологией
- Многоагентной симуляции на основе траекторий
- RL-обучения с бинарным вознаграждением
- Балансировки датасета для предотвращения перекосов

## Оценка

Оценка способностей вызова инструментов осуществляется с помощью бенчмарков, таких как:
- ruBFCL
- BFCL v3
- ACEBench (фокус на более сложных вызовах инструментов)
- tau² бенчмарк

## Значение

Улучшения вызова инструментов особенно важны для:
- Агентских систем, взаимодействующих с внешними API
- Приложений, требующих сложной логики на основе внешней информации
- Систем, требующих многократных последовательных вызовов инструментов
