# X-Coder-SFT-376k: Синтетический датасет для соревновательного программирования

## Краткое описание

**X-Coder-SFT-376k** — это крупнейший полностью синтетический датасет для развития соревновательного программирования в ИИ-моделях. Создан командой Tsinghua II Group (IIGroup) в сотрудничестве с Microsoft. Датасет содержит **887,321 синтетических записей** across **423,883 уникальных запросов** и используется для supervised fine-tuning (SFT) кодовых моделей [[x_coder_synthetic_code_model.md]].

## Структура датасета

### 4 подмножества (splits)

| Подмножество | Записей | Уникальных запросов | Ответов/запрос | Теги рассуждений | Размер |
|--------------|---------|---------------------|----------------|------------------|--------|
| **Hybrid** (Hybrid-SFT-376k) | 376,491 | 176,935 | 2.13 (avg) | ✅ Да | 24.3 GB |
| **Unique-Prompt** (SFT-unique-prompt-202k) | 202,128 | 202,125 | 1.00 | ❌ Нет | 13.1 GB |
| **Multiple-Solution** (SFT-multiple-solution-218k) | 218,686 | 33,571 | 6.51 (avg) | ✅ Да | 13.6 GB |
| **Verified** (SFT-verified-90k) | 90,016 | 11,252 | 8.00 | ✅ Да | 5.2 GB |

### Детали подмножеств

#### 1. Hybrid (376k)
**Назначение:** Масштабное SFT обучение

**Состав:**
- 80.48% запросов с одним ответом
- 7.89% запросов с 8 верифицированными ответами
- 11.63% запросов с 2-16 ответами

**Особенности:**
- Содержит всё подмножество verified
- ~55% перекрытие с multiple-solution

**Распределение ответов:**

| Ответов | Запросов | Процент |
|---------|----------|---------|
| 1 | 142,404 | 80.48% |
| 2-7 | 17,329 | 9.79% |
| 8 | 13,968 | 7.89% |
| 9-16 | 3,234 | 1.83% |

#### 2. Unique-Prompt (202k)
**Назначение:** Разнообразие запросов

**Особенности:**
- Каждый запрос имеет ровно 1 ответ
- **Полностью независим** от других splits (нет перекрытий)
- Идеально для обучения без дублирования

#### 3. Multiple-Solution (218k)
**Назначение:** Обучение генерации разнообразных решений

**Распределение ответов:**

| Ответов | Запросов | Процент |
|---------|----------|---------|
| 1 | 89 | 0.27% |
| 6-7 | 12,391 | 36.91% |
| 8 | 12,729 | 37.92% |

**Особенности:**
- 37.92% запросов имеют ровно 8 ответов
- Среднее: 6.51 ответов на запрос

#### 4. Verified (90k)
**Назначение:** Высококачественные верифицированные решения

**Особенности:**
- Ровно 8 верифицированных ответов на запрос
- **100% содержится в hybrid split**
- Наивысшее качество данных

### Отношения между подмножествами

```
unique-prompt (202k) — Независимое (нет перекрытий)

multiple-solution (218k)
        ↓ (~55% перекрытие)
    hybrid (376k)
        ↓ (100% содержится)
    verified (90k)
```

**Рекомендации по дедупликации:**
- ✅ unique-prompt + любой другой: Дедупликация не нужна
- ⚠️ multiple-solution + hybrid: Требуется дедупликация (~55% перекрытие)
- ⚠️ verified + hybrid: Использовать только hybrid (verified полностью содержится)

## Методология генерации

### Конвейер SynthSmith

| Компонент | Модель |
|-----------|--------|
| **Синтез запросов** | OpenAI GPT-o3-mini |
| **Генерация решений** | DeepSeek-R1-0528, Qwen3-235B-A22B-Thinking-2507 |

### Четырехэтапный процесс

**Этап 1: Извлечение и эволюция признаков**
- Извлечение программных признаков из 10,000 существующих примеров
- Эволюция: алгоритмы, структуры данных, техники оптимизации
- Расширение с **27,400 до ~177,000** записей алгоритмов

**Этап 2: Создание задач и решений**
- Генерация задач с помощью LLM на основе извлеченных признаков
- Генерация решений с использованием мощных кодовых моделей

**Этап 3: Генерация тестовых случаев**
- Создание тестов для валидации решений
- Использование LLM для генерации разнообразных тестов

**Этап 4: Двухэтапная валидация**
- **Stage 1:** Majority voting across множественных кандидатных решений
- **Stage 2:** Валидация на holdout тестовом наборе для предотвращения переобучения

### Ключевые особенности

- **100% синтетические** — никаких человеческих данных
- Включает **процесс рассуждений** (теги <think>...</think>) для большинства splits
- Полный пайплайн доступен на GitHub для генерации пользовательских артефактов

## Масштабирование и производительность

### Scaling Laws

Производительность оценивалась на **LiveCodebench v5**:

| Синтетических задач | Pass Rate |
|---------------------|-----------|
| 32,000 | 43.7% |
| 64,000 | 51.3% |
| 128,000 | 57.2% |
| 192,000 | 62.7% |

**Ключевой вывод:** Производительность продолжает улучшаться с ростом датасета — плато не наблюдается.

### Ключевые находки

1. **Разнообразие задач > Количество решений:** 64k задач × 1 ответ превосходит 16k задач × 4 ответа
2. **Long-CoT эффективен:** +17.4% прироста, но требует 8-10 эпох для сходимости
3. **Сложные задачи лучше:** Reasoning-intensive задачи дают лучшие градиенты
4. **RL устойчив к шуму:** 5-8% неправильных тестов всё ещё дают прирост
5. **Длина ≠ Точность:** Цепи >20k токенов имеют 14.3% pass rate
