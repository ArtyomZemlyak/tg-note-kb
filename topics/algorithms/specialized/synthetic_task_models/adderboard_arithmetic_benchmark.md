# AdderBoard: Бенчмарк для оценки арифметических способностей трансформеров

## Краткое описание

**AdderBoard** — это исследовательский челлендж по созданию **наименьшей трансформер-нейросети, способной складывать два 10-значных числа** с точностью ≥99% на тестовой выборке из 10K примеров. Проект исследует фундаментальный вопрос: *какой минимальный трансформер может представлять операцию целочисленного сложения?*

Проект поддерживается **Dimitris Papailiopoulos** (@dimitrispapail).

**Репозиторий:** [GitHub - anadim/AdderBoard](https://github.com/anadim/AdderBoard)

## Основные характеристики

### Формат задачи

| Параметр | Значение |
|----------|----------|
| **Вход** | Два целых числа в диапазоне [0, 9 999 999 999] |
| **Выход** | Их сумма в виде целого числа |
| **Точность** | ≥99% на 10 000 случайных парах (seed=2025) |
| **Токенизация** | Фиксированная (реверсированные цифры, разделители разрешены) |

### Требования к архитектуре

Модель должна быть **настоящим авторегрессионным трансформером**:

- **Self-attention** — хотя бы один слой самовнимания обязателен
- **Авторегрессия** — предсказание следующего токена по одному; распространение переноса должно возникать из авторегрессии
- **Стандартный forward pass** — тензор на входе, логиты на выходе; никакой специфичной для задачи логики управления внутри `forward()`
- **Модель выполняет работу** — код инференса должен быть общим (не специфичная для сложения Python-логика)

### Правила подсчёта параметров

- Считаются **уникальные параметры** (после связывания весов/дедупликации)
- **Фиксированные/синусоидальные позиционные кодировки** НЕ считаются (по оригинальной статье Transformer)
- **Обучаемые позиционные кодировки** СЧИТАЮТСЯ

## Ключевые технические находки

| Находка | Описание |
|---------|----------|
| **Параметрический обрыв ~800** | Резкий переход точности, наблюдаемый несколькими исследователями |
| **Один слой лучше двух** | При эквивалентном бюджете параметров (для обученных моделей) |
| **d=7 — оптимальная точка** | Ранние обученные модели сходились к этой размерности |
| **d=4 теперь работает** | С rank-3 факторизацией + grokking (311 параметров) |
| **Ручные ≪ обученные** | 36 параметров (ручные) против 311 параметров (обученные) — SGD не может найти оптимум |
| **Rank-3 факторизация** | Ключевой трюк для обученных моделей |
| **ALiBi позволяет экстремальное сжатие** | Лидер с 36 параметрами использует ALiBi с slope=log(10) для взвешивания по основанию 10 |

## Ключевые используемые техники

| Техника | Назначение |
|---------|------------|
| **ALiBi с slope=log(10)** | Взвешивание позиций по основанию 10 |
| **RoPE (Rotary Position Embedding)** | Маршрутизация цифр, кодирование на основе периода |
| **Rank-3 факторизация** | Драматическое сокращение параметров |
| **Tied embeddings** | Разделение весов встраивания/декодирования |
| **Parabolic decode head** | Нелинейный проекционный слой вывода |
| **Sparse projections** | Сокращение параметров при сохранении функциональности |
| **Grokking** |_extended training для внезапной генерализации |
| **Curriculum learning** | Обучение на более простых примерах сначала |

## Три основные способности для сложения

Сложение требует трёх основных способностей:

1. **Выравнивание цифр (digit alignment)** — сопоставление соответствующих цифр из двух чисел
2. **Поразрядная арифметика (per-digit arithmetic)** — вычисление суммы и переноса для каждой пары
3. **Распространение переноса (carry propagation)** — передача информации о переносе across позиций

Это **минимальный бенчмарк рассуждения** для понимания того, что могут представлять и изучать трансформеры.

## Результаты

| Категория | Лучшие параметры | Точность | Примечание |
|-----------|------------------|----------|------------|
| **Ручные веса** | 36 | 100% | Конструктивное доказательство |
| **Обученные веса** | 311 | 99,999% | Обучаемо из данных |

**Ключевой инсайт:** Ручные модели **~9× меньше** обученных, показывая, что оптимальные решения существуют, но SGD не может их легко найти.

## История происхождения

Этот челлендж начался с **"Addition Under Pressure"**, где:
- **Claude Code** произвёл: 6 080 параметров
- **Codex** произвёл: 1 644 параметра

Сообщество с тех пор **драматически улучшило** результат до **36 параметров** (ручные) и **311 параметров** (обученные).

## Структура кода

```
AdderBoard/
├── README.md              # Описание челленджа и leaderboard
├── verify.py              # Скрипт верификации (10 edge cases + 10K random tests)
├── submission_template.py # Шаблон для сабмишенов
├── adderboard.png         # Визуальный актив
└── .github/ISSUE_TEMPLATE # Шаблон Issue для сабмишенов
```

### Верификация (`verify.py`)

Запускает:
- 10 edge cases (граничные значения, максимальные цепочки переноса)
- 10 000 случайных пар (seed=2025)
- Отчитывается о точности, pass/fail, и времени

```bash
python verify.py submissions/your_submission.py
```
