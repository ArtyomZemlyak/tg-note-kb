# Muon Optimizer: Оптимизация через ортогонализацию Ньютона-Шульца

## Описание

Muon - это оптимизатор для 2D параметров скрытых слоев нейронных сетей, созданный в рамках проекта modded-nanogpt. Он достигает значительных улучшений в скорости обучения за счет сочетания SGD-момента с последующей ортогонализацией обновлений с помощью итерации Ньютона-Шульца.

## Алгоритм работы

Muon определяется следующим образом:

1. **SGD-момент**: Сначала генерируется обновление параметров с помощью стандартного SGD-момента
2. **Ортогонализация**: Затем к обновлению применяется итерация Ньютона-Шульца для ортогонализации матрицы обновления
3. **Нестеровский момент**: Используется нестеровский момент внутри обновления с ортогонализацией после момента

### Итерация Ньютона-Шульца

```python
@torch.compile
def zeroth_power_via_newtonschulz5(G, steps=5, eps=1e-7):
    assert len(G.shape) == 2
    a, b, c = (3.4445, -4.7750,  2.0315)
    X = G.bfloat16() / (G.norm() + eps)
    if G.size(0) > G.size(1):
        X = X.T 
    for _ in range(steps):
        A = X @ X.T
        B = b * A + c * A @ A
        X = a * X + B @ X
    if G.size(0) > G.size(1):
        X = X.T 
    return X.to(G.dtype)
```

## Основные принципы

### Зачем ортогонализовать обновления?

1. **Эмпирическое наблюдение**: Обновления от SGD-момента и Adam для 2D параметров в трансформерах обычно имеют очень высокие числа обусловленности (почти низкоранговые матрицы)
2. **Редкие направления**: Ортогонализация эффективно увеличивает масштаб "редких направлений", которые имеют малую величину в обновлениях, но важны для обучения
3. **Теоретическая связь**: Связан с анализом Shampoo optimizer (Bernstein & Newhouse, 2024)

### Почему Ньютон-Шульц, а не альтернативы?

1. **SVD слишком медленно**: Вычисление полного SVD было бы вычислительно prohibitive
2. **Связанная итерация Ньютона требует float32**: Это делает его медленным на современных GPU
3. **Итерация Ньютон-Шульца работает в bfloat16**: Это делает его эффективным на современном железе

## Преимущества

### Эмпирические результаты

- **CIFAR-10**: Улучшение рекорда с 3.3 до 2.6 A100-секунд (для 94% точности)
- **NanoGPT спидран**: 1.35x улучшение скорости обучения до 3.28 val loss
- **Масштабирование**: Показывает улучшения при масштабировании до 774M и 1.5B параметров
- **Крупное обучение моделей**: Обучение 1.5B параметровой трансформерной модели до уровня GPT-2 XL за 10 8xH100-часов вместо 13.3 часов с AdamW

### Вычислительная эффективность

- **Низкие накладные расходы**: Расходы на FLOP рассчитываются как T×m/B где T=5 (шаги NS), m=размер модели, B=размер батча
  - NanoGPT: 0.7% накладных расходов
  - Llama 405B масштаб: 0.5% накладных расходов
- **Потребление памяти**: Такое же как SGD-момент (без дополнительной памяти для ортогонализации)

### Взаимосвязь с другими оптимизаторами

1. **Связь с Shampoo**: Muon можно рассматривать как "мгновенный" или "без накопления" Shampoo с более эффективной ортогонализацией
2. **Отличие от Orthogonal-SGDM**: В отличие от Tuddenham et al. (2022), который применяет момент после ортогонализации, Muon применяет момент до ортогонализации (что эмпирически работает лучше)

## Практические замечания по реализации

- **Только для 2D параметров**: Используется для весов скрытых слоев; скаляры/векторы используют стандартные оптимизаторы вроде AdamW
- **Сверточные слои**: Применяется путем сглаживания последних 3 измерений
- **Входные/выходные слои**: Следует использовать AdamW, а не Muon
- **QKV параметры**: Лучшая производительность при применении раздельно, а не совместно
- **Nesterov момент**: Работает лучше, чем стандартный SGD-момент

## Ключевые инновации

1. **Эффективная ортогонализация**: Использует итерацию Ньютона-Шульца вместо дорогостоящего SVD
2. **Момент до ортогонализации**: Эмпирически лучше, чем ортогонализация до момента
3. **Настроенные коэффициенты**: Оптимизированные полиномиальные коэффициенты (3.4445, -4.7750, 2.0315) для более быстрой сходимости
4. **Совместимость с bfloat16**: Эффективное выполнение на современном GPU железе
