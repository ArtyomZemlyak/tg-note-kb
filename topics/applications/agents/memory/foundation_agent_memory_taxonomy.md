# Таксономия памяти фундаментальных агентов (Foundation Agent Memory Taxonomy)

## Краткое описание

Единый фреймворк для классификации механизмов памяти в агентах на базе фундаментальных моделей (LLM, VLM). Предложен в масштабном обзоре "Rethinking Memory Mechanisms of Foundation Agents in the Second Half: A Survey" (Huang et al., 2026), обобщающем более 200 статей. Таксономия категоризирует память по трём ортогональным измерениям: субстрат, когнитивный механизм и субъект памяти.

## Контекст: переход ко «второй половине» ИИ

ИИ переживает сдвиг парадигмы от «первой половины» развития (статичные бенчмарки, законы масштабирования, гонка за проценты на MMLU) ко «второй», где важна **реальная полезность в долгоживущих средах**.

В таких условиях главным бутылочным горлышком становится не способность к рассуждениям (reasoning), а **управление контекстом**. Агенты сталкиваются с «контекстным взрывом»: история взаимодействий и выводы инструментов быстро превышают лимиты фиксированного окна. Память — это не просто склад данных, а когнитивный субстрат для непрерывности и персонализации.

> **Ключевая проблема:** Без нормальной памяти агенты остаются stateless-предикторами, обречёнными на одни и те же ошибки и неспособными подстроиться под пользователя.

## Три измерения таксономии

### 1. Субстрат памяти (Memory Substrate)

**Вопрос:** В какой форме представлена память?

| Тип | Описание | Преимущества | Недостатки | Примеры |
|-----|----------|--------------|------------|---------|
| **Внутренняя память** | Параметрическое знание θ, скрытые состояния h_t, KV-кэши | Быстрая, тесно интегрирована в reasoning | Страдает от катастрофического забывания при обновлении | Веса модели, attention cache |
| **Внешняя память** | Векторные БД, графы знаний, логи | Масштабируемая, редактируемая | Вносит задержки (latency) и шум при поиске | RAG, vector stores, knowledge graphs |

### 2. Когнитивный механизм (Memory Cognitive Mechanism)

**Вопрос:** Как память функционирует?

Функциональное деление по аналогии с человеческой памятью:

#### Долговременная память

| Тип | Описание | Функциональная роль | Примеры работ |
|-----|----------|---------------------|---------------|
| **Эпизодическая** | Хранит конкретные траектории (что, где, когда) | Сохранение последовательностей событий и действий | Sarin et al. (2025) - триггеры сессионного уровня |
| **Семантическая** | Факты и знания о мире, дистиллированные из эпизодов | Организация знаний в структурированном виде | Terranova et al. (2025) - self-evolving semantic networks |
| **Процедурная** | Хранилище навыков и эвристик | Улучшение того, *как* агент выполняет задачи | Кэширование успешных цепочек рассуждений |

#### Краткосрочная память

| Тип | Описание | Функциональная роль |
|-----|----------|---------------------|
| **Сенсорная** | Буфер для входных данных | Временное хранение минимально обработанных наблюдений |
| **Рабочая** | Текущие состояния задач | Онлайн-манипуляция информацией, reasoning и control |

### 3. Субъект памяти (Memory Subject)

**Вопрос:** Чью информацию память моделирует и для кого служит?

| Тип | Описание | Оптимизационная цель |
|-----|----------|---------------------|
| **User-Centric** | Моделирование персоны пользователя | Лучший alignment, персонализация, детекция дрейфа предпочтений |
| **Agent-Centric** | Накопление модели мира и навыков | Генерализация задач, накопление экспертизы |

> **Важно:** Это измерение ортогонально субстрату и когнитивному механизму. Working memory, procedural memory и sensory memory преимущественно agent-centric, тогда как semantic и episodic могут быть как user-, так и agent-centric.

## Жизненный цикл памяти

Память — это **динамический процесс**, а не статичный архив. Цикл включает:

1. **Хранение (Storage)** — запись новой информации
2. **Индексация (Indexing)** — организация для эффективного поиска
3. **Извлечение (Retrieval)** — поиск релевантной информации
4. **Обновление (Update)** — модификация устаревших записей
5. **Забывание (Forgetting)** — удаление нерелевантного

### Пример: агент-разработчик

Представьте агента, который чинит баг в легаси-коде:
- **Retrieval** ищет похожие прошлые ошибки (эпизодическая) и документацию (семантическая)
- Если контекст слишком «жирный», модуль суммаризации сжимает его в «динамическую шпаргалку» (Dynamic Cheatsheet)
- После задачи механизм **Update** обязан явно удалить старую запись, если библиотека обновилась
- В мультиагентных системах нужны протоколы «Write Control» для избежания race conditions

## Стратегии управления памятью

### Эволюция подходов

| Поколение | Подход | Описание |
|-----------|--------|----------|
| **Первое** | Статические промпты | «Суммаризируй последние 10 ходов» |
| **Второе** | Dynamic Prompt-based Control | Агент рефлексирует над ошибками и меняет стратегию поиска |
| **Третье** | Fine-tuning + RL | Агент учится воспринимать операции с памятью как действия |

### RL для управления памятью

В **Memory-R1** (arxiv:2508.19828) агент выучивает политику π(a_t|s_t), где действия — это **ADD, UPDATE, DELETE или NOOP**. Награда выдаётся за долгосрочный успех задачи. Так агент сам понимает, *что* помнить, а *что* забыть, чтобы максимизировать полезность при ограниченном бюджете токенов.

## Проблемы оценки

Текущие метрики (Exact Match, F1, Recall@K) смотрят на краткосрочную точность. Для агентов «второй волны» этого мало. Нужны **лонгитюдные бенчмарки**, измеряющие:

| Метрика | Описание |
|---------|----------|
| **Целостность (Integrity)** | Устойчивость к порче данных |
| **Ложные воспоминания** | Устойчивость к инъекциям галлюцинаций |
| **Эффективность** | Перформанс на один сохранённый токен |

### Существующие бенчмарки

- **LongMemEval** (arxiv:2410.10813) — тестирование долговременной памяти в диалогах
- **SWE-bench** (arxiv:2310.06770) — оценка агентов на задачах разработки ПО

Но нужны тесты на **операционные** способности: поймёт ли агент, что его память протухла? Справится ли с противоречивыми апдейтами от юзера за месяц общения?

## Будущие направления

### 1. Память для непрерывного обучения (Continual Learning)

Нужно уходить от простого RAG к системам, которые консолидируют внешний опыт во внутренние веса **без полного переобучения модели**. Это предполагает будущее, где память и базовая модель обучаются совместно (co-trained).

### 2. Доверенная память (Trustworthy Memory)

Для медицины и права нужны архитектуры, которые не только помнят всё, но и:
- Верифицируемы
- Приватны
- Поддаются аудиту

### 3. Инфраструктура и эффективность

- Оптимизация latency при retrieval
- Сжатие памяти без потерь
- Распределённые системы памяти для мультиагентных систем
