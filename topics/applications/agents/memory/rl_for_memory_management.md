# Обучение с подкреплением для управления памятью агентов (RL for Memory Management)

## Краткое описание

Применение reinforcement learning (RL) для обучения агентов управлению памятью: что запоминать, что забывать, как обновлять. Вместо статических правил (вроде «суммаризируй последние N токенов») агенты учатся оптимальным политикам управления памятью через взаимодействие со средой и получение наград за долгосрочный успех задач.

## Мотивация: почему RL для памяти?

### Проблема статических подходов

Традиционные системы памяти используют фиксированные правила:
- FIFO (first-in, first-out) для удаления старых записей
- Статические промпты для суммаризации
- Ручные пороги для сжатия контекста

**Недостатки:**
- Не адаптируются к специфике задачи
- Не учитывают долгосрочные последствия решений о памяти
- Требуют ручной настройки гиперпараметров

### RL-подход

Агент учится воспринимать **операции с памятью как действия**:
- **ADD** — добавить новую запись
- **UPDATE** — обновить существующую запись
- **DELETE** — удалить устаревшую запись
- **NOOP** — ничего не делать (сохранить как есть)

Награда выдаётся за **долгосрочный успех задачи**, а не за краткосрочную точность retrieval.

## Memory-R1: RL для управления памятью

### Архитектура

**Memory-R1** (arxiv:2508.19828) — фреймворк, который обучает LLM-агентов активно управлять и использовать внешнюю память через reinforcement learning.

| Компонент | Описание |
|-----------|----------|
| **Memory Manager** | Решает, когда и что записывать в память |
| **Memory User** | Решает, как использовать память для генерации ответа |
| **Reward Signal** | Награда за качество финального ответа |

### Политика управления

Агент выучивает политику π(a_t|s_t), где:
- **a_t ∈ {ADD, UPDATE, DELETE, NOOP}** — действия с памятью
- **s_t** — текущее состояние (контекст, история, задача)

Правило обновления следует алгоритму **REINFORCE**:

```
∇_θ = E[(Γ(answer) - baseline) · ∇_θ log π(a_t|s_t)]
```

где Γ(answer) — награда за качество ответа.

### Ключевые результаты

| Метрика | Значение |
|---------|----------|
| **Обучающих примеров** | ~152问答对 (вопрос-ответ пар) |
| **Улучшение производительности** | +48% по сравнению с базовыми методами |
| **Эффективность** | 2.4k training samples для превосходства над baseline с 70× больше данных |

## Динамическое управление памятью через RL

### Уровни управления

| Уровень | Что оптимизируется | Пример действий |
|---------|-------------------|-----------------|
| **Token-level** | Какие токены сохранить | Сжатие, прунинг, квантование |
| **Episode-level** | Какие эпизоды запомнить | ADD/DELETE сессий |
| **Knowledge-level** | Какие знания консолидировать | Дистилляция в семантическую память |

### Функция награды

Функция награды должна учитывать:

1. **Качество ответа** — точность, релевантность, полнота
2. **Эффективность памяти** — использование бюджета токенов
3. **Целостность памяти** — отсутствие противоречий
4. **Долгосрочную согласованность** — consistency across sessions

Пример многокомпонентной награды:

```
R = α·R_quality + β·R_efficiency + γ·R_consistency - δ·R_cost
```

## Стратегии обучения

### 1. Multi-Agent Reinforcement Learning

В **GAM (General Agentic Memory)** используется multi-agent RL для оптимизации двух агентов:

| Агент | Роль | Обучение |
|-------|------|----------|
| **Memorizer** | Структурирует сырую историю в страницы | Учится подсвечивать важное в заголовках |
| **Researcher** | Выполняет deep research в рантайме | Учится искать эффективнее и останавливаться |

Весь пайплайн дифференцируем, веса обновляются через награду за финальный ответ.

### 2. Self-Distillation для памяти

**SDFT (Self-Distillation Fine-Tuning)** и **SDPO (Self-Distillation Policy Optimization)** используют self-distillation для:
- Сжатия контекста в модельные веса
- Улучшения policy без внешнего супервизора

### 3. Continual RL для памяти

Агент постоянно обновляет политику управления памятью на основе нового опыта, используя:
- **Experience replay** — воспроизведение прошлых эпизодов
- **Regularization** — предотвращение катастрофического забывания
- **Meta-learning** — обучение тому, как учиться

## Проблемы и вызовы

### 1. Разрешение кредитного присвоения (Credit Assignment)

Сложность определения, какие действия с памятью привели к успеху/неудаче:
- Задержка между действием (ADD/DELETE) и результатом
- Множество промежуточных шагов

**Решения:**
- Dense reward shaping
- Counterfactual baselines
- Hierarchical RL

### 2. Исследование vs Использование (Exploration-Exploitation)

Агент должен балансировать между:
- **Исследованием** новых стратегий управления памятью
- **Использованием** известных хороших стратегий

**Решения:**
- ε-greedy с затуханием
- Thompson sampling
- Upper Confidence Bound (UCB)

### 3. Масштабируемость

Обучение RL-политик для памяти требует:
- Множества эпизодов для сходимости
- Вычислительных ресурсов для rollout'ов

**Решения:**
- Offline RL (обучение на собранных данных)
- Model-based RL (симуляция среды)
- Transfer learning (перенос политик между задачами)

## Практические рекомендации

### Когда использовать RL для памяти

| Сценарий | Рекомендация |
|----------|--------------|
| **Долгоживущие агенты** (дни/месяцы) | ✅ RL необходим для адаптации |
| **Персональные ассистенты** | ✅ RL для персонализации |
| **Короткие сессии** (<10 минут) | ❌ Статических правил достаточно |
| **Ограниченный бюджет токенов** | ✅ RL для оптимизации использования |

### Гиперпараметры для настройки

| Параметр | Типичный диапазон | Влияние |
|----------|-------------------|---------|
| Learning rate | 1e-5 — 1e-3 | Скорость сходимости |
| Discount factor (γ) | 0.9 — 0.99 | Горизонт планирования |
| Entropy bonus | 0.01 — 0.1 | Уровень исследования |
| Baseline type | Moving average / Value function | Стабильность обучения |
