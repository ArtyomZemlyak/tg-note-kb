# Подходы к выполнению задач агентами: Вызов инструментов (Tool Calling) vs Выполнение кода (Code Execution)

## Обзор

В области агентных систем ИИ существуют два основных подхода к выполнению задач, требующих взаимодействия с внешними инструментами и системами: "Вызов инструментов" (Tool Calling) и "Выполнение кода" (Code Execution). Эти подходы отличаются архитектурой, эффективностью и способом интеграции внешних возможностей в работу агентов.

## Подход Tool Calling (Вызов инструментов)

### Описание

- Модель генерирует текст с явными вызовами инструментов (в формате JSON или другом структурированном виде)
- Каждый вызов инструмента обрабатывается отдельно
- Требуется дополнительная логика для интерпретации и выполнения вызовов
- Каждый вызов инструмента приводит к паузам в выполнении и ожиданию результатов

### Применение

- API-интеграции
- Внешние инструменты и сервисы
- Системы с четко определенными интерфейсами
- Безопасные среды выполнения, где прямое выполнение кода невозможно

### Преимущества

- **Безопасность**: более безопасное исполнение, так как внешние вызовы ограничены
- **Контроль**: легче контролировать и ограничивать вызовы инструментов
- **Надежность**: меньше риск ошибок, связанных с выполнением произвольного кода
- **Прозрачность**: легче отлаживать и логировать вызовы инструментов

### Недостатки

- **Скорость**: работает медленнее из-за необходимости обрабатывать каждый вызов инструмента по отдельности
- **Передача контекста**: требует передачи контекста между вызовами
- **Сложность**: требует сложной логики для управления последовательностями вызовов
- **Потребление токенов**: увеличивает потребление токенов из-за дополнительных сообщений

## Подход Code Execution (Выполнение кода)

### Описание

- Модель генерирует блоки кода (обычно Python), которые напрямую вызывают нужные функции
- Весь блок кода выполняется за один проход
- Внутренняя логика модели может использовать сложные структуры данных и управлять потоком выполнения
- Результаты выполнения остаются в памяти агента

### Применение

- Анализ данных
- Работа с файлами
- Сложные вычисления
- Системы с внутренними ресурсами и контролируемой средой выполнения

### Преимущества

- **Эффективность**: более эффективно, выполняется за один проход
- **Скорость**: снижает время отклика за счет уменьшения round-trips
- **Потребление ресурсов**: снижает потребление токенов
- **Гибкость**: позволяет выполнять сложные логические операции в рамках одного выполнения
- **Контекст**: сохраняется весь контекст между операциями в пределах одного выполнения

### Недостатки

- **Безопасность**: требует тщательной изоляции и безопасности при выполнении кода
- **Сложность внедрения**: сложнее внедрять в существующие безопасные среды
- **Риски**: потенциальные риски безопасности при выполнении произвольного кода
- **Отладка**: сложнее диагностировать ошибки в генерируемом коде

## Сравнение эффективности

### Временные характеристики

- **Tool Calling**: требует нескольких кругов общения (round-trips) между моделью и инструментами
- **Code Execution**: уменьшает количество round-trips до минимума, часто до одного

### Потребление ресурсов

- **Tool Calling**: больше потребляет токены из-за дополнительных сообщений и форматирования
- **Code Execution**: более экономичен в потреблении токенов

### Производительность

- **Yandex DeepResearch**: выбрал подход Code Execution, что значительно увеличило эффективность системы
- **DR TULU**: использует Tool Calling через протокол MCP (Model Context Protocol), но с эффективной архитектурой

## Практические рекомендации

### Когда использовать Tool Calling

- В безопасных средах, где выполнение произвольного кода невозможно
- При интеграции с готовыми API и сервисами
- Для систем, где важна максимальная изоляция и контроль
- В случаях, когда сложность интеграции с Code Execution превышает преимущества

### Когда использовать Code Execution

- В контролируемых средах с достаточной изоляцией
- Для задач, требующих сложных вычислений или анализа данных
- Когда критична производительность и время отклика
- При наличии надежных механизмов безопасности для выполнения кода

## Примеры из практики

### Yandex DeepResearch

- Изначально использовали Tool Calling, но перешли к Code Execution
- Code Execution показал лучшую эффективность, снизил время отклика и потребление токенов
- Позволил модели более свободно использовать внутренние функции

### DR TULU

- Использует Tool Calling через MCP с поддержкой различных инструментов поиска
- Обеспечивает хорошую модульность и сменяемость инструментов
- Поддерживает три инструмента: google_search, web_browse, paper_search

### Qwen DeepResearch

- Поддерживает различные инструменты для поиска и анализа
- Вероятно, использует смешанный подход в зависимости от типа задачи

## Будущие тенденции

### Гибридные подходы

- Сочетание обоих подходов в зависимости от типа задачи
- Динамическое переключение между подходами
- Унификация интерфейсов для обоих подходов

### Безопасность

- Развитие безопасных песочниц для выполнения кода
- Улучшение систем изоляции и контроля доступа
- Разработка специализированных языков программирования для агентов
