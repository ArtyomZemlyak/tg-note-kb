# Корпоративный ИИ-агент DeepResearch от Яндекса

## Описание

DeepResearch - внутренний ИИ-агент компании Яндекс, созданный для поиска информации в корпоративных данных и кодовой базе. Предназначен для экономии времени сотрудников и предоставления подробных ответов на сложные вопросы. Внутренняя версия называется Deep Agent Yandex Team Ru и доступна только сотрудникам компании.

## Отличия от классических подходов

В отличие от обычной системы RAG (Retrieval-Augmented Generation), которая ограничивается "запрос - результаты - ответ", DeepResearch не ограничивает себя рамками простого поиска. Он:

- Анализирует несколько страниц одновременно
- Выполняет дополнительные поисковые запросы при недостатке информации
- Выполняет серию промежуточных шагов, проверок и уточнений
- Полезен для сложных вопросов, требующих нескольких поисков и синтеза информации

## Архитектура и реализация

### Техническая архитектура

- Backend DeepAgent, обращающийся к локально развернутому поиску
- Сознательно избегали жестко определенных рабочих процессов, предоставив агенту значительную свободу действий
- Использовали системные подсказки для руководства лучшими практиками
- Рекомендация: не начинать с архитектуры мультиагентов, сосредоточиться сначала на одном агенте

### Методология разработки

1. **Простой старт**: первая версия была создана за пару дней с помощью скрипта, делающего запросы к внутренней вики, читающего страницы и пытающегося формировать ответы.
2. **Итеративное развитие**: постепенное улучшение функций и возможностей агента
3. **Оценка производительности**: постоянная оценка с помощью тестовых наборов ("корзин") вопросов с ожидаемыми ответами

## Методы оценки и тестирования

### Тестовые наборы (баскеты)

Использовались два уровня тестовых наборов:

- **Простые**: ответы на первой странице вики, быстрое выполнение
- **Сложные**: требуют ручного поиска 20-60 минут от человека

### Оценка с помощью LLM-as-a-judge

- Подход, при котором мощная LLM используется как система оценки качества
- Сравнение результатов агента с эталонными ответами
- Позволяет масштабировать оценку без необходимости ручной разметки

## Повышение качества DeepAgent

### Источники данных

- Внутренние чаты поддержки
- Корпоративный Stack Overflow
- Вики-документация
- README-файлы
- Открытые фрагменты чатов Telegram (без частных данных)

### Основные принципы

- Оценка каждого изменения с помощью проверок качества и журналирования
- Добавление примеров few-shot в системную подсказку для улучшения
- Комплексное журналирование всех запросов, вызовов инструментов и ошибок

### Методы улучшения

#### Подходы к выполнению задач

##### Tool Calling (Вызов инструментов)
- Модель генерирует текст с явными вызовами инструментов
- Работает, но медленно
- Отдельные вызовы инструментов обрабатываются пошагово

##### Code Execution (Выполнение кода)
- Модель записывает блок Python, вызывающий необходимые функции внутренне
- Более эффективно, выполняется за один проход
- Снижает время отклика и потребление токенов

### Дообучение (Fine-tuning)

- Выполнялось после достижения предела улучшений через инструменты и примеры
- Собирались траектории через разные LLM, оценивались правильные решения, создавался датасет для дообучения
- Главное достижение: DeepAgent научился читать код, осуществлять поиск через регулярные выражения и семантические методы, отвечая примерно на половину самых сложных вопросов о коде

## Результаты и метрики

### Основные достижения

- Сокращение времени поиска информации с 20 минут до 1 минуты (95% сокращение)
- Более 240 рабочих часов, сэкономленных ежедневно по всей компании
- Достижение ~50% успеха на сложных вопросах о коде
- Масштабируемость для обработки сотен или тысяч ежедневных операций

## Перспективы развития

### Будущие функции

- Чтение всей внутренней инфраструктуры: Kubernetes, дашборды, графики, логи сервисов, графы Nirvana
- Способности к самостоятельной корректировке: перезапуск сервисов или откат изменений самим агентом
- Обработка долгих сценариев: анализ сотен тикетов, графиков или документов
- Создание единого интерфейса для всех вопросов сотрудников вместо прерывания тимлидов или общих каналов

## Основные выводы

- Корпоративный DeepResearch становится необходимым, когда внешние модели не имеют доступа к внутренним корпоративным знаниям, распространенным по вики, документации, электронной почте, чатам
- Рекомендуется подход с одним агентом, а не архитектура мультиагентов изначально
- Комплексное журналирование и оценка критически важны для улучшения качества
- Подход с выполнением кода более эффективен, чем вызов инструментов для производительности агента
