# RL3DEdit: RL для 3D-редактирования сцен без парных данных

**RL3DEdit** — это фреймворк для многовидового согласованного 3D-редактирования сцен на основе обучения с подкреплением (RL), разработанный исследователями из AMAP Alibaba Group, BJTU и NTU.

## Основная проблема

Главная проблема 3D-редактирования: необходима **мультивью-консистентность** (согласованность между различными ракурсами), но собрать парные данные для обучения практически нереально. Традиционные методы сталкиваются со следующими ограничениями:

- **Геометрически-обусловленные методы** используют карты глубины исходного изображения, не справляясь с геометрическими изменениями
- **Итеративные подходы** страдают от низкой эффективности и размытых артефактов из-за неконсистентных сигналов
- **Манипуляции с вниманием** не гарантируют мелкомасштабную геометрическую согласованность

## Ключевая идея

Авторы решили проблему через **обучение с подкреплением** — аналогично тому, как это делается в LLM, только вместо «правильного ответа» используют **3D-верификатор** на основе foundation-модели.

### Архитектура решения

```
┌─────────────────────────────────────────────────────────────────┐
│                    RL3DEdit Pipeline                            │
├─────────────────────────────────────────────────────────────────┤
│  1. Рендеринг 3D-сцены с M ракурсов → {I_m}                     │
│  2. FLUX-Kontext (2D-редактор) → совместное редактирование      │
│  3. GRPO исследует G вариантов редактирования                   │
│  4. VGGT (3D-верификатор) → reward signals:                     │
│     - r_D: геометрическая консистентность (depth confidence)    │
│     - r_P: геометрическая консистентность (point confidence)    │
│     - r_T: согласованность поз камер                            │
│     - r_a: anchor reward (качество редактирования)              │
│  5. Оптимизация через GRPO objective                            │
│  6. 3DGS реконструкция → финальная 3D-сцена                     │
└─────────────────────────────────────────────────────────────────┘
```

## Компоненты системы

### 1. 2D-редактор: FLUX-Kontext

Мощный 2D-редактор на архитектуре **DiT (Diffusion Transformer)**, способный к **совместному редактированию нескольких изображений** благодаря механизму глобального внимания между всеми входными изображениями.

**Почему не InstructPix2Pix:**
- Низкое разрешение обработки
- Локальные свёрточные операции ограничивают межизображное взаимодействие
- Не способен выполнять инструкции типа «поменять цвета шерсти двух котов местами»

### 2. 3D-верификатор: VGGT

**VGGT** — замороженная 3D foundation-модель, обученная на миллионах реальных 3D-данных. Выполняет роль верификатора мультивью-консистентности.

**Аналогия с SDS (Score Distillation Sampling):**
- SDS использует замороженную 2D-диффузионную модель (Stable Diffusion) как оракула качества изображений
- RL3DEdit использует замороженную 3D-модель (VGGT) как оракула консистентности

**Выходные данные VGGT:**
- Карты уверенности (confidence maps) для глубины и точек
- Предсказания камерных поз
- Карты глубины и точечные карты

### 3. Reward-функции

#### Геометрические rewards (r_D, r_P)
Средняя уверенность карт глубины и точек как индикатор мультивью-консистентности:
- Высокая уверенность → хорошая консистентность
- Низкая уверенность → геометрические противоречия (ghosting-артефакты)

#### Reward относительных поз (r_T)
Согласованность относительных трансформаций между соседними ракурсами:
```
T_rel_m = T_{m+1} * T_m^{-1}
```

#### Anchor reward (r_a)
Сохраняет качество 2D-редактирования FLUX-Kontext:
- Предварительно вычисляются single-image результаты редактирования офлайн
- Используется как эталон для оценки семантической корректности
- Случайный выбор anchor view для каждого тренировочного шага

### 4. Алгоритм оптимизации: GRPO

**Group Relative Policy Optimization** — алгоритм RL, устраняющий необходимость в отдельной value-модели за счёт групповой оценки преимуществ:

```
A_i = (R_i - mean({R_j})) / std({R_j})
```

где R_i — композитный reward для i-го образца в группе.

**Objective:**
```
J_clip(θ) = E[min(r_i(θ) * A_i, clip(r_i(θ), 1-ε, 1+ε) * A_i)]
```

## Результаты

### Эффективность данных
- **Обучается на 5% данных** по сравнению с конкурентами (всего ~1,319 сэмплов)
- Не требует парных 3D-данных для редактирования

### Производительность
- **Работает за один проход** (single-pass inference)
- **В 2× быстрее** предыдущих методов
- Не требует fine-tuning на сцену или промпт

### Качество редактирования
- Справляется с **геометрическими изменениями**:
  - «надень капюшон»
  - «поклонись»
  - замена объектов
  - изменение фона
  - перенос стиля
- **Сохраняет качество 2D-редактирования** FLUX-Kontext после RL-оптимизации

### Поддерживаемые сценарии редактирования
1. Редактирование движений (motion edits)
2. Замена объектов (subject replacement)
3. Перенос стиля (style transfer)
4. Изменение фона (background changes)
5. Добавление сложных элементов сцены (challenging scene addition)

## Технические детали реализации

- **LoRA**: rank=32, alpha=32
- **Количество видов (M)**: 9
- **Размер группы GRPO**: 16
- **Шаги денoising для исследования**: 12 (требует более высокой точности для 3D)
- **SDE noise level**: 0.8
- **Веса rewards**: w_D = w_P = w_T = w_a = 0.25
- **Время обучения**: 42 часа на NVIDIA RTX A6000

## Научная значимость

RL3DEdit — **первая работа**, применяющая обучение с подкреплением к задаче 3D-редактирования сцен. Метод демонстрирует, что:

1. **Верификация проще генерации**: проверка мультивью-консистентности значительно проще, чем генерация консистентных изображений
2. **Foundation-модели как reward-модели**: замороженные 3D foundation-модели могут служить надёжными верификаторами без дообучения
3. **Перенос 2D-приоров в 3D**: RL позволяет «перенести» мощные 2D-приоры в 3D-домен без парных данных
