# LLM2VEC-GEN: Генеративные эмбеддинги от больших языковых моделей

## Описание

**LLM2VEC-GEN** — это самообучаемый фреймворк для создания текстовых эмбеддингов на основе LLM, который кодирует не сам входной запрос, а **потенциальный ответ модели** на этот запрос. Этот подход позволяет преодолеть разрыв между входом и выходом (input-output gap) и перенести способности LLM (безопасность, рассуждение) в пространство эмбеддингов.

**Ключевая инновация**: Вместо кодирования семантического содержания входа, модель учится представлять свой потенциальный ответ в виде фиксированного набора латентных токенов сжатия.

## Основная проблема

Традиционные LLM-based эмбеддеры работают по **input-centric парадигме** — кодируют семантическое содержание входного текста. Это создаёт проблемы:

- **Разнообразные входы → одинаковые выходы**: В задачах кластеризации статьи об одном событии с разных перспектив должны группироваться вместе, но input-centric подходы размещают их далеко друг от друга
- **Требуется контрастивное обучение**: Для преодоления разрыва необходимы размеченные пары данных
- **Отсутствие переноса способностей LLM**: Безопасность и рассуждения, проявляющиеся в ответах LLM, не передаются эмбеддингам

**Пример**: Для вредоносного запроса традиционные эмбеддеры представляют злонамеренное намерение самого запроса, тогда как LLM2VEC-GEN кодирует безопасный отказ модели («Я не могу помочь с этим»).

## Архитектура и методология

### Обзор подхода

LLM2VEC-GEN состоит из следующих шагов:

1. **Генерация данных**: Для неразмеченных запросов LLM генерирует ответы
2. **Эмбеддинг учителя**: Готовая unsupervised модель создаёт эмбеддинги сгенерированных ответов
3. **Специальные токены**: В словарь добавляются обучаемые токены двух типов
4. **Двойная оптимизация**: Два комплементарных лосса обучают токены сжатия

### Специальные токены

Вводятся два типа специальных токенов в словарь LLM:

| Тип токенов | Обозначение | Количество | Назначение |
|-------------|-------------|------------|------------|
| **Thought токены** | t₁, …, tₘ | 10 | Промежуточный вычислительный буфер |
| **Compression токены** | c₁, …, cₙ | 10 | Захват семантического содержания ответа |

Для запроса qᵢ токены добавляются как: `xᵢ = qᵢ ⊕ t₁:ₘ ⊕ c₁:ₙ`

### Функции потерь

#### 1. Reconstruction Objective (L_recon)

**Цель**: Compression токены должны сохранять достаточно информации для восстановления целевого ответа.

**Механизм**:
- Скрытые представления compression токенов `[h₁ᵢ, …, hₙᵢ] = LLM(xᵢ)` пропускаются через проекционный слой: `p₁ᵢ, …, pₙᵢ = MLP_recon(h₁ᵢ, …, hₙᵢ)`
- Полученные представления используются как **soft prompts** для второго прохода LLM
- Модель обучается восстанавливать ответ rᵢ через next-token prediction

**Эффект**: p₁ᵢ, …, pₙᵢ служат информационным бутылочным горлышком, сжимая содержание rᵢ

#### 2. Embedding Alignment Objective (L_align)

**Цель**: Предотвратить кодирование запроса qᵢ вместо сжатой версии целевого ответа.

**Механизм**:
- Используется teacher-энкодер E для создания целевого эмбеддинга: `eᵢ = E(rᵢ)`
- Спроецированные представления обрабатываются вторым MLP и mean pooling: `êᵢ = Pool(MLP_align(p₁ᵢ, …, pₙᵢ))`
- Минимизируется расстояние между êᵢ и eᵢ

**Связь с JEPA**: Концептуально похоже на Joint Embedding Predictive Architecture — предсказание в пространстве представлений, а не реконструкция сырых входов

### Итоговая функция потерь

```
L = L_recon + L_align
```

**Обучаемые параметры**: Только специальные токены и два MLP слоя  
**Заморожено**: Весь backbone LLM

### Инференс

В отличие от HyDE, LLM2VEC-GEN требует **только один прямой проход**:
1. Добавляем специальные токены ко входу
2. Извлекаем скрытые состояния compression токенов
3. Применяем MLP_recon и MLP_align для получения финального эмбеддинга ê

## Экспериментальная оценка

### Настройка экспериментов

**Модели**: Qwen-3 (0.6B–8B), Qwen-2.5 (0.5B–7B), Llama-3.2 (1B, 3B), Llama-3.1 (8B)

**Teacher-энкодер**: Unsupervised LLM2Vec модели (требования: same underlying LLM + unsupervised objective)

**Данные для обучения**: 160K одноходовых вопросов из Tulu dataset (ground-truth ответы **не используются**, модель обучается на своих собственных генерациях)

**Вычислительные требования**: Обучение 8B модели ≈ 3.5 часа на 2×H100 GPU, batch size=32, 1 эпоха

### Бенчмарки

| Бенчмарк | Назначение | Метрика |
|----------|------------|---------|
| **MTEB(eng, v2)** | Общие текстовые эмбеддинги (41 задача, 7 категорий) | Average score |
| **MTEB-Lite** | Подмножество из 10 задач для абляций | Average score |
| **AdvBench-IR** | Уязвимость retriever к вредоносным запросам (520 запросов, 5 категорий вреда) | Top-5 accuracy (ниже = безопаснее) |
| **BRIGHT** | Reasoning-intensive retrieval (биология, код, математика, физика) | nDCG@10 |

### Ключевые результаты

#### MTEB: State-of-the-art self-supervised производительность

**LLM2VEC-GEN с Qwen-3-8B**: **62.1** — новый SOTA для self-supervised подходов на MTEB

| Модель | MTEB Score | Улучшение vs LLM2Vec teacher |
|--------|------------|------------------------------|
| Qwen-3-1.7B | ~57.5 | +3.8% |
| Qwen-3-4B | ~59.9 | +4.2% |
| Qwen-3-8B | **62.1** | **+9.3%** |

**Наибольший прирост по категориям**:
- **Кластеризация**: +23.9%
- **Классификация**: +9.2%
- **Semantic Textual Similarity (STS)**: +10.5%

**Сравнение с supervised baseline**: LLM2VEC-GEN (62.1) сокращает разрыв до LLM2Vec-supervised (65.7) до **3.6 пунктов**

#### Безопасность: AdvBench-IR

| Модель | Harmful Retrieval (Top-5) |
|--------|---------------------------|
| LLM2Vec-Qwen-3-8B | Базовый уровень |
| **LLM2VEC-GEN-Qwen-3-8B** | **-9.8 пунктов** (улучшение безопасности) |

**Результат**: До **43.2% снижение** извлечения вредоносного контента

#### Reasoning: BRIGHT benchmark

| Модель | nDCG@10 |
|--------|---------|
| Input-centric baselines | Базовый уровень |
| **LLM2VEC-GEN** | **+29.3%** улучшение |

**Вывод**: Способности к рассуждению действительно переносятся в пространство эмбеддингов

### Обобщаемость на разные семейства моделей

LLM2VEC-GEN действует как **выравниватель производительности**:
- На масштабе 3–4B teacher показывают разброс 56.3–58.0, LLM2VEC-GEN консолидирует вокруг **59.9–60.9**
- На масштабе 8B достигает **62.1**, сокращая gap до supervised метода

**Диапазон улучшений vs teacher**: от +1.1 (Llama-3.1-8B) до +5.3 пунктов (Qwen-3-8B)

## Сравнение с базовыми подходами

| Метод | Обучение | Обновление LLM | Инференс | Ключевое отличие |
|-------|----------|----------------|----------|------------------|
| **Echo Embeddings** | Нет | Нет | Один проход | Повторение входа для bidirectional context |
| **HyDE** | Нет | Нет | **Генерация + кодирование** | Генерирует гипотетические ответы, затем кодирует (высокая задержка) |
| **InBedder** | Да (LoRA) | LoRA (r=32, α=64) | Один проход | Embedding из первого сгенерированного токена |
| **GIRCSE** | Да (контрастивный) | Stepwise contrastive | Один проход | Авторегрессивная генерация soft tokens |
| **LLM2Vec** | Да (SimCSE) | Bidirectional + MNP | Один проход | Unsupervised teacher для LLM2VEC-GEN |
| **LLM2VEC-GEN** | Да (recon + align) | **Только токены + MLP** | **Один проход** | **Кодирует потенциальный ответ через compression токены** |

### Позиционирование по адаптации модели

```
No Training          ←→ Full Fine-tuning
     │                        │
  Echo, HyDE           InBedder, GIRCSE
     │                        │
  LLM2VEC-GEN (middle ground: frozen LLM, trainable tokens+MLPs)
```

## Интерпретируемость эмбеддингов

**Уникальное свойство**: Special token embeddings можно **декодировать обратно в текст**, раскрывая их семантическое содержание.

Это достигается благодаря reconstruction objective, который «заземляет» представления в естественном языке и делает их декодируемыми.

## Практическое применение

### Преимущества LLM2VEC-GEN

✅ **Self-supervised**: Требует только неразмеченные запросы  
✅ **Frozen LLM**: Минимальное количество обучаемых параметров  
✅ **Single-pass inference**: Эффективнее HyDE (не требует генерации при инференсе)  
✅ **Перенос способностей LLM**: Безопасность и рассуждения в эмбеддингах  
✅ **Интерпретируемость**: Возможность декодирования в текст  
✅ **SOTA производительность**: Закрывает >60% разрыва до supervised методов

### Ограничения

⚠️ **Retrieval performance**: Для Qwen-3-4B/8B наблюдается небольшое снижение vs teacher (неполное сжатие нюансов генерации)  
⚠️ **Несовместимость с supervised teacher**: При использовании supervised encoder не превосходит teacher без LoRA (разные оптимизационные цели: relative relevance vs absolute semantic)

### Рекомендации по использованию

1. **Выбор teacher**: Использовать unsupervised LLM2Vec с тем же underlying LLM
2. **Размер модели**: Наибольшие улучшения на масштабе 3–8B
3. **Домены**: Особенно эффективно для кластеризации, классификации, STS
4. **Безопасность**: Критично для retrieval-систем, работающих с потенциально вредоносными запросами
