# Сравнение архитектур поиска: Single-vector vs Multi-vector vs Sparse

## Краткое описание

Сравнение различных архитектур информационного поиска с точки зрения их способности преодолевать теоретические ограничения векторных эмбеддингов. Исследование Google DeepMind показало, что одиночные векторные представления имеют фундаментальные ограничения, в то время как много-векторные и разреженные архитектуры показывают лучшую способность к представлению сложных комбинаций релевантных документов.

## Single-vector (плотные) эмбеддинги

### Принцип работы
- Каждый документ и запрос представляется одним вектором фиксированной размерности
- Релевантность определяется скалярным произведением (или косинусным сходством) векторов
- Используется для "плотного поиска" (dense retrieval)

### Преимущества
- Высокая скорость поиска при масштабировании
- Эффективное хранение и индексация
- Универсальность - одинаковая архитектура для разных доменов
- Возможность обучения на больших корпусах данных

### Ограничения
- **Фундаментальный лимит на количество представимых комбинаций** - ограничен размерностью эмбеддинга
- Не может точно представлять все возможные комбинации релевантных документов
- Проблемы с инструкционным поиском и сложными определениями релевантности
- На датасете LIMIT показывает менее 20% точности @100

### Примеры моделей
- GritLM
- Qwen3 Embeddings
- Gemini Embeddings
- E5-Mistral
- Snowflake Arctic

## Multi-vector (ColBERT-style) модели

### Принцип работы
- Использует множество векторов для представления одного документа или запроса
- Применяет оператор MaxSim (максимальное сходство) между векторами запроса и документа
- Позволяет более точно сравнивать сложные тексты

### Преимущества
- **Более высокая выразительность** по сравнению с single-vector моделями
- Лучшая способность к точному сопоставлению терминов
- Показывает лучшие результаты на датасете LIMIT (62% против <20%)
- Позволяет более гибкое сопоставление на уровне фраз и предложений

### Ограничения
- Более высокие требования к памяти и вычислениям
- Сложнее масштабировать до веб-размеров
- Пока не так широко используется для задач инструкционного поиска
- Меньше исследований в контексте инструкционного следования

### Примеры моделей
- GTE-ModernColBERT
- MXBAI Edge ColBERT v0 17M
- ColBERT (классическая архитектура)
- Late interaction модели

## Sparse (лексические) модели

### Принцип работы
- Использует высокоразмерные разреженные представления (векторы с большим количеством нулей)
- Может быть как традиционной (BM25) так и нейросетевой (SPLADE)
- Основана на совпадении терминов и статистических мерах

### Преимущества
- **Высокая эффективность для задач с лексическим сходством**
- Практически безошибочное сопоставление терминов
- **Наивысшая производительность на датасете LIMIT (93%)** благодаря эффективно более высокой размерности
- Хорошо работает для задач, где точное сопоставление терминов важно

### Ограничения
- Проблемы с синонимией и семантическим сходством
- Сложнее применять к задачам инструкционного поиска и рассуждения
- Ограниченная способность к обобщению на новые концепции
- Не всегда применима к задачам вне текстового домена

### Примеры моделей
- BM25 (классический алгоритм)
- SPLADE (нейросетевая разреженная модель)
- TF-IDF (традиционная статистическая модель)

## Cross-encoder архитектуры

### Принцип работы
- Оценивает пару запрос-документ непосредственно, а не использует предварительно вычисленные эмбеддинги
- Может учитывать полное взаимодействие между запросом и документом
- Обычно используется для переоценки (reranking) результатов первоначального поиска

### Преимущества
- **Максимальная точность** при оценке релевантности
- **100% точность на датасете LIMIT** в переоценке
- Может учитывать сложные взаимодействия между запросом и документом
- Не ограничена фиксированной размерностью эмбеддинга

### Ограничения
- **Высокая вычислительная стоимость** - не подходит для масштабного первоначального поиска
- Не может использоваться как первый этап поиска при большом количестве документов
- Требует больше времени для обработки каждого запроса

### Примеры моделей
- Gemini 2.5 Pro (в переоценке)
- BERT-based cross-encoders
- MonoT5, DuoT5

## Сравнительный анализ производительности

### Результаты на датасете LIMIT (Recall@100)

| Модель | Размерность | Тип архитектуры | Результат LIMIT | Результат LIMIT (small) |
|--------|-------------|------------------|------------------|--------------------------|
| BM25 | - | Sparse | 93.0% | 100.0% |
| ModernColBERT | default | Multi-vector | 61.8% | 99.1% |
| GritLM 7B | 4096 | Single-vector | 12.9% | 90.5% |
| Qwen3 Embed | 4096 | Single-vector | 4.8% | 73.8% |
| E5-Mistral 7B | 4096 | Single-vector | 8.3% | 85.2% |
| Gemini Embed | 3072 | Single-vector | 10.0% | 87.9% |

### Зависимость от размерности эмбеддингов

Для single-vector моделей наблюдается положительная корреляция между размерностью и производительностью:
- 32-128 размерности: <2% точности
- 256-512 размерности: 1-5% точности
- 1024-2048 размерности: 5-15% точности
- 3072-4096 размерности: 8-20% точности

## Рекомендации по выбору архитектуры

### Для высокой точности с небольшим корпусом документов
- **Cross-encoder** архитектуры обеспечивают максимальную точность
- Приемлемо для переоценки топ-K результатов из первоначального поиска

### Для масштабного первоначального поиска
- **Multi-vector** (ColBERT-style) модели как компромисс между точностью и масштабируемостью
- **Sparse** модели для задач с высокой важностью лексического сопоставления

### Для максимальной скорости и масштабируемости
- **Single-vector** модели, но с пониманием их теоретических ограничений
- Использование с переоценкой через cross-encoder

## Перспективы развития

### Гибридные подходы
- Комбинация sparse и dense методов
- Использование single-vector для грубого поиска, multi-vector или cross-encoder для точной оценки
- Динамический выбор архитектуры в зависимости от типа запроса

### Архитектуры нового поколения
- Модели с переменной размерностью эмбеддингов
- Адаптивные архитектуры, выбирающие оптимальный метод в зависимости от запроса
- Интеграция с системами агентов для более сложного поиска

## Новые концепции и термины

- **Dense retrieval**: поисковые системы, использующие плотные векторные эмбеддинги
- **Sparse retrieval**: поисковые системы, использующие разреженные (обычно лексические) представления
- **Multi-vector models**: модели, использующие множество векторов для представления одного документа
- **MaxSim operator**: оператор максимального сходства, используемый в ColBERT-style моделях
- **Cross-encoder**: модель, которая оценивает пару запрос-документ непосредственно
- **Reranking**: переоценка результатов первоначального поиска с более точной моделью
