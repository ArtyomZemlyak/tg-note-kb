# Оценка качества поиска: комплексный подход

## Краткое описание

Статья описывает комплексный подход к оценке качества поиска в e-commerce компании Lamoda, включающий количественные метрики, LLM-разметку и пользовательский фидбэк. Подход направлен на постоянное улучшение поисковой системы для более релевантного отображения товаров пользователям.

## Введение

Поиск — это важнейшая часть любого e-commerce проекта, Lamoda не исключение. Качество поиска влияет на опыт пользователей и бизнес-результаты. Основные причины, для которых важно работать над качеством поиска товаров:

1. **Пользовательская ценность**: Каждый день более 1 млн пользователей открывают сайт или приложение и формулируют поисковые запросы. Команда собрала более 25 миллионов уникальных поисковых запросов за последний год.

2. **Бизнес-влияние**: Около 25% всей выручки Lamoda приходит с поиска. Это означает, что его улучшения могут превратиться в доход для компании: будь то обработка синонимов, умение распознать бренд при ошибочном вводе или корректная сортировка результатов.

3. **Улучшение бизнес-процессов**: Оценка качества поиска помогает развивать не только сам пайплайн поиска, но и смежные процессы — работу с ассортиментом и селлерами платформы.

## Архитектура поисковой системы

Чтобы по текстовому запросу пользователя появился отранжированный по релевантности список товаров, система проходит через несколько этапов:

1. **Нормализация текста**. Запрос приводится к единому виду: убираются лишние символы, исправляются частые ошибки, текст переводится в стандартную форму. Например, запрос «ботильонов» превратится в «ботильоны».

2. **Исправление опечаток**. Отдельный модуль (опечаточник) отвечает за то, чтобы система одинаково понимала «reebok», «рибок» и «reeboc». Этот этап можно улучшать: добавлять новые правила, корректировать частотные ошибки и развивать алгоритм, исходя из реального поведения пользователей.

3. **Работа со словарями сущностей и связей**. На этом этапе запрос обогащается дополнительной информацией о токенах, например, определяется сущность — бренд, цвет, категория. Также происходит обогащение синонимами, брендами-аналогами и другими экспертными связями.

Примеры связей, которые могут храниться в словарях:
- Синонимы и похожие по смыслу слова: «штаны» и «брюки», «свитер» и «джемпер».
- Названия брендов их варианты написания, включая транслиты, сокращения и связи между собой. Например, можно связать бренды Jordan и Nike, Yeezy и Adidas.
- Для некоторых категорий фиксируются неформальные названия, которые пользователи часто используют, например, «изики».

4. **Формирование поискового запроса к ElasticSearch**. На этом этапе нормализованный текст превращается в AND/OR-дерево, которое подбирает товары в каталоге.

5. **Нейронный семантический поиск**. Для запросов, к которым подобрали малое количество «органических» кандидатов по текстовому индексу ElasticSearch, используется семантический поиск. На основе векторных представлений запроса и товара он ищет наиболее релевантных кандидатов.

6. **Онлайн переранжирование кандидатов (персонализация)** — топ-400 товаров переранжируются ML-моделью на основе предпочтений пользователя и других факторов.

## Критерии идеального поиска

Идеальный поиск для fashion e-commerce платформы — это сочетание нескольких ключевых свойств:

- **Точность и релевантность**. Поиск должен выдавать релевантные товары как по простым запросам, так и по сложным, и даже по не строгим формулировкам, например, «одежда для отпуска на пляже». Система должна уметь понимать синонимы, опечатки, транслитерации и разговорные выражения, которые пользователи используют в жизни.

- **Полнота**. Поиск находит все релевантные товары, которые есть на стоке, при этом не показывая лишнего.

- **Трендовость**. Появляются новые коллекции, бренды, лимитированные товары, выстреливают новые тренды — и поиск должен подстраиваться под изменения в fashion-индустрии.

- **Персональность**. Даже при одинаковом запросе разным пользователям нужны разные товары. Поиск должен учитывать такие предпочтения, как бренды, размеры, цвета, цены, стилистика.

## Методы оценки качества поиска

Оценить сразу все аспекты сложно. Поэтому команда формирует картину качества поиска по нескольким независимым источникам данных — каждый из них подсвечивает разные стороны пользовательского опыта:

1. **Количественные метрики поиска** - анализ кликов, добавлений в корзину и покупок из поисковых запросов
2. **Фидбэк от пользователей** - прямые вопросы пользователю о релевантности выдачи
3. **Асессорская и LLM-разметка поисковых запросов** - ручная и автоматизированная разметка релевантности
4. **Поиск проблемных запросов с помощью эмбеддингов** - сравнительный анализ похожих запросов с разной конверсией

## Примеры улучшений

Примеры того, как улучшение поиска влияет на другие бизнес-процессы:

- Если по запросу «форма для падела» в выдаче появляется нижнее белье, команда сигнализирует об этом коллегам из контента или коммерции. Они корректируют категории, атрибуты или сток, и поиск становится точнее.

- Если по какой-то теме стабильно нет релевантных товаров, команда передает этот инсайт коллегам из коммерции, чтобы скорректировать закупки на будущее.

- Ранее «балетки-кроссовки» или «лабубу» не были известны, а теперь это важная часть образов пользователей, которую они ищут в приложении.

## Заключение

Поиск - сложная многофакторная система, а поток запросов постоянно меняется. Из-за этого оценка качества поиска становится нетривиальной задачей, а команде нужно регулярно его мониторить. Каждую неделю команда проводит оценку качества поиска, где с помощью различных инструментов находятся проблемы и исправляются. Это непрерывный процесс, который помогает поддерживать поиск релевантным, персональным и полезным.
