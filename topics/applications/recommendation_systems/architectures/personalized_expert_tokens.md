# Сжатие истории с помощью персонализированных экспертных токенов

## Описание

**Сжатие истории с помощью персонализированных экспертных токенов (Personalized Expert Tokens)** — это фреймворк от Meta для эффективного сжатия long-term истории пользователя в sequential рекомендательных моделях. Этот подход позволяет обрабатывать длинные последовательности взаимодействий на инференсе без потери качества, используя выучиваемые токены-«эксперты» для сжатия исторических сегментов.

**Ключевая идея:** Длинную историю разбивают на сегменты (например, по сессиям, дням или фиксированному числу событий), затем каждый сегмент сжимают в несколько токенов-«экспертов», которые используются для дальнейших предсказаний. Последний сегмент истории на момент предсказания не сжимается — модель видит его полностью.

## Контекст

Sequential recommender системы обычно строятся на трансформерной архитектуре, которая страдает от **квадратичной сложности механизма attention** по длине последовательности. Из-за этого обрабатывать длинные последовательности вычислительно дорого, хотя они и приносят стабильный профит в качестве рекомендаций.

### Существующие подходы к решению проблемы

В релевантных работах эту проблему решают в два этапа:
1. Сначала long-term-историю сокращают (например, семплируют или кластеризуют события)
2. Затем объединяют с последними событиями и прогоняют через модель

Примеры подходов:
- **KuaiFormer**
- **SIM** (Search-based Interest Model)
- **TWIN V2**

Этот фреймворк предлагает альтернативный подход — сжатие через выучиваемые токены вместо эвристического сокращения.

## Архитектура

### Основная концепция

```
Long-term история → [Сегмент 1] [Сегмент 2] ... [Сегмент N] [Текущий сегмент]
                          ↓           ↓              ↓           ↓
                    [Эксперты 1] [Эксперты 2] ... [Эксперты N] [Полный]
                          ↓           ↓              ↓           ↓
                    └─────────────── Attention ──────────────────┘
```

### Ключевые компоненты

1. **Сегментация истории**
   - Длинная история разбивается на сегменты
   - Сегменты могут быть по сессиям, дням или фиксированному числу событий
   - Последний сегмент (текущий) остаётся несжатым

2. **Персонализированные эксперты (Personalized Experts)**
   - Выучиваемые токены для сжатия каждого сегмента
   - Каждый сегмент сжимается в несколько токенов-экспертов
   - Эксперты содержат информацию о релевантных айтемах из истории

3. **Специальная attention-маска**
   - Каждый токен может смотреть на:
     - Предыдущие токены своего сегмента
     - «Экспертов» из предыдущих сегментов
   - Сами токены предыдущих сегментов скрыты маской

## Обучение

### Авторегрессивное обучение

Модель обучается авторегрессивно со специальной attention-маской:

- **Для токенов внутри сегмента:**
  - Могут attend на предыдущие токены своего сегмента
  - Могут attend на экспертов из предыдущих сегментов
  - Не могут attend на сами токены предыдущих сегментов (скрыты маской)

- **Для экспертов:**
  - Лосс не считается (вспомогательные токены)
  - Служат только для сжатия и передачи информации

### Функция потерь

Стандартная next item prediction loss:
```
L = Σ log P(item_t | context)
```
где context включает:
- Токены текущего (несжатого) сегмента
- Экспертов из всех предыдущих сегментов

## Инференс

### Процесс предсказания

На инференсе сегменты обрабатываются последовательно:

1. **Предобработка истории:**
   - Сегменты обрабатываются последовательно
   - Key и Value эмбеддинги сжимающих токенов сохраняются в кэше

2. **Предсказание следующего айтема:**
   - Используется только текущий сегмент
   - Плюс сохранённые K и V экспертов с предыдущих сегментов
   - Нет необходимости обрабатывать всю long-term-историю как одну длинную последовательность

### Вычислительная эффективность

- **На обучении:** Небольшой оверхед из-за добавленных токенов-экспертов
- **На инференсе:** Существенный выигрыш
  - В экспериментальном сетапе: ~25% от исходной вычислительной стоимости
  - Устраняется необходимость обработки всей истории как единой последовательности

## Эксперименты

### Датасеты

Эксперименты проводились на двух датасетах:

| Датасет | Тип | Описание |
|---------|-----|----------|
| **MerRec** | E-commerce | Датасет из Mercari (торговая площадка) |
| **EB-NeRD** | Новости | Новостной датасет из газеты Ekstra Bladet |

### Результаты

#### Качество рекомендаций

- Метод **почти полностью сохраняет качество** моделей на полной истории
- **Заметно превосходит** варианты, где используется только recent-история
- На **MerRec метрики даже немного лучше** бейзлайна с полной историей

#### Влияние количества экспертов

- Количество экспертов **почти не влияет на качество**
   - Можно использовать фиксированное число экспертов для всех сегментов
   - Гибкость в выборе баланса эффективность/качество

#### Переиспользование сжатого представления

- Сжатое представление long-term-истории можно **переиспользовать довольно долго** без заметной деградации
- **Лучшая схема:** вставить всех экспертов после одного большого претрейн-сегмента

### Анализ работы экспертов

Анализ показал, что эксперты содержат информацию по **небольшому набору айтемов из истории, релевантных таргетному**:

**Пример:** Для айтема "LEGO" среди наиболее важных элементов из истории оказываются другие LEGO-товары.

Это означает, что эксперты эффективно выявляют и сохраняют семантически релевантные паттерны в истории пользователя.

## Применение к различным моделям

Этот фреймворк является **методом сжатия истории**, который можно применять к разным моделям:

- **HSTU** (Hierarchical Semantic Transformer for User Behavior Modeling)
- **HLLM** (Hierarchical Large Language Models)
- Другие трансформерные sequential recommendation модели

## Преимущества

| Аспект | Преимущество |
|--------|--------------|
| **Вычислительная эффективность** | ~75% экономии вычислений на инференсе |
| **Качество** | Сохранение качества полной истории |
| **Масштабируемость** | Обработка очень длинных историй |
| **Гибкость** | Применим к различным архитектурам |
| **Переиспользование** | Кэш экспертов можно использовать多次 |

## Ограничения

- **Небольшой оверхед на обучении** из-за дополнительных токенов
- **Требует сегментации истории** (нужно выбирать стратегию сегментации)
- **Дополнительная память** для хранения K/V экспертов

## Связь с другими подходами

### Отличия от существующих методов

| Метод | Подход | Основное отличие |
|-------|--------|------------------|
| **KuaiFormer** | Семплирование/кластеризация | Эвристическое сокращение vs. выучиваемое сжатие |
| **SIM** | Search-based | Поиск релевантных vs. сжатие в эксперты |
| **TWIN V2** | Двухэтапный | Раздельная обработка vs. единый фреймворк |
| **Personalized Experts** | Выучиваемые токены | **Сжатие с сохранением релевантной информации** |
