# Рекомендательная система Phoenix (xAI)

## Описание

Phoenix - это рекомендательная система, разработанная xAI, которая используется для поиска и ранжирования контента в ленте "For You" на платформе X (бывший Twitter). Эта система была названа "Феникс", что любопытно совпадает с названием аналогичного проекта в Яндексе.

## Архитектура

Phoenix использует двухступенчатый рекомендательный пайплайн:

### 1. Поиск (Retrieval Stage)
- **Цель**: эффективно сузить миллионы кандидатов до тысяч
- **Используемая модель**: двухбашенная архитектура (two-tower)
- **User Tower**: кодирует особенности пользователя и историю взаимодействий через трансформер для производства нормализованного эмбеддинга пользователя [B, D]
- **Candidate Tower**: вычисляет нормализованные эмбеддинги для всех элементов в корпусе [N, D]
- **Поиск по схожести**: извлекает топ-K кандидатов, используя скалярное произведение схожести

Это позволяет эффективно искать схожие объекты в масштабе, путем сужения миллионов кандидатов до тысяч.

### 2. Ранжирование (Ranking Stage)
- **Цель**: оценка и упорядочивание извлеченных кандидатов
- **Используемая модель**: трансформерная архитектура, адаптированная из Grok-1
- **Выход logits**: [B, num_candidates, num_actions]
- **Multi-action предсказание**: одновременно предсказывает несколько типов взаимодействия (Like, Repost, Reply, Click и т.д.)

## Изоляция кандидатов

Модель ранжирования реализует **изоляцию кандидатов** с помощью специальной маски внимания, которая предотвращает обращение кандидатов друг к другу во время вывода. Это гарантирует, что оценка для кандидата не зависит от того, какие другие кандидаты находятся в пакете.

## Особенности реализации

### Хэш-базированные эмбеддинги
- Обе модели используют несколько функций хэширования для поиска по эмбеддингам
- Используется multi-hash lookup: делают что-то типа linear(concat(embedding(hash1), embedding(hash2)))
- В конфигах везде указаны num_hashes=2, то есть по два лукапа на сущность

### Совместимая архитектура
- User tower для поиска использует ту же трансформерную архитектуру, что и модель ранжирования
- Одинаковая архитектура трансформера используется как для поиска, так и для ранжирования

### Входная структура
- Пользовательские эмбеддинги [B, 1]
- Эмбеддинги истории [B, S, D]
- Эмбеддинги кандидатов [B, C, D]
- Эмбеддинг события в истории пользователя формируется на основе поста, автора, рекомендательной поверхности и действия пользователя
- Берут мультихэши от айдишника пользователя и подают в трансформер вместе с историей пользователя

## Технические детали

### Архитектура трансформера
- Реализация трансформера портирована из открытой версии Grok-1 от xAI
- Адаптирована для случаев использования рекомендательной системы с кастомными входными эмбеддингами и маской внимания для изоляции кандидатов
- Архитектура трансформера по умолчанию (видны роторные эмбеддинги, rmsnorm)
- В тестах и конфигах указаны очень маленькие размеры трансформера (вроде два слоя и скрытый размер 128)
- Длина используемой истории пользователя в конфигах - то ли 128, то ли 32

### Multi-action предсказание
- Трансформер предсказывает вероятности сразу для кучи разных сигналов (like, reply, click, repost и другие)
- Для финального ранжирования эти вероятности суммируются с весами в единый скор
- Положительные действия имеют положительные веса, отрицательные действия - отрицательные веса

## Применение

Phoenix используется в составе более крупной системы рекомендаций xAI, в частности:

1. Как компонент внешнесетевого контента (out-of-network content) для ленты "For You"
2. Для поиска и ранжирования контента, обнаруженного из глобального корпуса
3. В комбинации с внутрисетевым контентом (Thunder) для формирования окончательной ленты

## Значение и отличия

1. **Без ручных признаков**: полагается полностью на трансформерную модель Grok для изучения релевантности из последовательностей взаимодействий пользователя
2. **Изоляция кандидатов**: во время вывода трансформера кандидаты не могут обращаться друг к другу - только к контексту пользователя, что обеспечивает постоянные и кешируемые оценки
3. **Единая нейросетевая архитектура**: предпринята попытка упростить ранжирование в единую нейросеть с трансформером, что делает архитектуру более понятной и единообразной
