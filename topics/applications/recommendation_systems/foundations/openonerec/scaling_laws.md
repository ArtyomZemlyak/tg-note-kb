# Законы масштабирования в рекомендательных системах (OpenOneRec)

## Общее описание

Работа OpenOneRec впервые эмпирически валидирует законы масштабирования в контексте рекомендательных систем. Используя методологию Hoffman et al. (2022), исследование анализирует, как распределяется вычислительный бюджет между параметрами модели (N) и количеством токенов (D) для оптимальной производительности в задачах рекомендаций.

## Методология исследования

### Объем исследования
- Спектр параметров: N ∈ {0.6, 1.7, 4, 8, 14} × 10^9
- Стадия 2 предобучения: варьирование бюджета токенов D
- Приближение вычислительного бюджета: C ≈ 6ND
- Использование архитектуры Qwen3 как основы

### Критерии оптимизации
- Построение выпуклой оболочки (convex hull) финальных значений лосса для всех размеров моделей
- Интерполяция минимального лосса L_min(C) на непрерывной сетке FLOPs
- Извлечение оптимального размера модели N_opt и кол-ва токенов D_opt для заданного бюджета

## Основные результаты

### Эмпирические коэффициенты масштабирования
- **N_opt ∝ C^0.44** (размер модели)
- **D_opt ∝ C^0.56** (кол-во токенов)

### Сравнение с текстовыми законами масштабирования
В отличие от законов масштабирования для текста (Chinchilla), которые предполагают равное распределение (a ≈ 0.5, b ≈ 0.5), рекомендательные задачи демонстрируют:
- **a = 0.44, b = 0.56** (a < b)
- **Данные-насыщенный режим (data-intensive regime)**: оптимальное распределение требует более агрессивного масштабирования объема данных по сравнению с параметрами модели по мере увеличения бюджета

## Теоретическая модель

Используемая параметрическая функция:
```
L(N,D) = E + A*N^α + B*D^β
```
где:
- E: непреодолимая энтропия распределения данных
- A*N^α: отклонения из-за конечной емкости модели
- B*D^β: отклонения из-за конечного размера данных

### Полученные коэффициенты
- **α ≈ 0.33** (емкость модели) - согласуется с литературой по общим LLM
- **β ≈ 0.19** (объем данных) - значительно ниже, чем в текстовом домене (β_text ≈ 0.28)
- **E = 0.42** (непреодолимая энтропия) - значительно ниже, чем у текста (E ≈ 1.69)
- **A = 502.32** (коэффициент емкости) - высокий из-за влияния предобучения
- **B = 7.02** (коэффициент данных) - низкий благодаря эффективности transfer learning

## Интерпретация результатов

### 1. Данные-голодное масштабирование (Data-Hungry Scaling)
- α > β означает, что математически необходимо b > 0.5
- Так как возвращаемость от количества данных снижается быстрее (ниже β), для поддержания оптимальности требуется масштабировать объем данных агрессивнее, чем размер модели

### 2. Влияние warm-starting
- Ярко выраженный дисбаланс между коэффициентами A (502.32) и B (7.02)
- Крайне низкое значение B объясняется эффективностью transfer learning из Qwen3 backbone
- Высокое значение A отражает смешивание емкости модели и качества предобучения

### 3. Низкая энтропия рекомендательных задач
- E = 0.42 значительно ниже, чем у текста (E ≈ 1.69)
- Рекомендательные задачи, обогащенные структурированными фичами (Itemic Dense Captions), обладают более низкой внутренней энтропией по сравнению с открытым текстом
- Подчеркивает важность курирования рекомендательных корпусов с большей вариативностью и качеством

## Практические рекомендации

### Для выделенного бюджета C:
1. **Распределите** C^0.44 на параметры модели и C^0.56 на токены данных
2. **Приоритетнее масштабировать** объем данных по сравнению с размером модели
3. **Используйте** warm-start из предобученных моделей для снижения требований к данным

### Для стратегии обучения:
1. **Сохраняйте баланс** между рекомендательными и общими данными
2. **Избегайте катастрофического забывания** общих знаний
3. **Оптимизируйте** соотношение доменных и общих данных на основе целей

## Влияние на архитектуру OpenOneRec

### На предобучение:
- Обоснование стратегии смешивания данных (62.34% общедоменные + 37.66% рекомендательные)
- Поддержка необходимости масштабирования объема обучающих данных
- Подтверждение эффективности подхода с warm-start

### На пост-обучение:
- Обоснование необходимости восстановления общих возможностей
- Поддержка стратегии on-policy distillation
- Обоснование баланса между рекомендательной точностью и общими знаниями

## Сравнение с другими доменами

| Домен | α | β | Основной вывод |
|-------|---|---|----------------|
| Текст | 0.39 | 0.28 | Сбалансированное масштабирование |
| Рекомендации | 0.33 | 0.19 | Данные-голодное масштабирование |
| | | | (a=0.44, b=0.56) |

## Ограничения исследования

- Ограниченный масштаб экспериментов может вводить некоторый шум подгонки
- Модели не обучены с нуля, что не позволяет полностью отделить вклад предобученного backbone
- Не все аспекты рекомендательных задач могут масштабироваться по одним и тем же законам

## Значение и влияние

Открытие законов масштабирования в рекомендательных системах имеет важное значение:
- **Руководство по архитектуре**: Как распределять вычислительный бюджет
- **Руководство по обучению**: Как масштабировать данные и модели
- **Обоснование подхода OpenOneRec**: Подтверждение эффективности выбранной стратегии
- **Основа для будущих исследований**: Стандарт для сравнения подходов к масштабированию
