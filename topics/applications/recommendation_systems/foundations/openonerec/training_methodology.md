# Методология обучения OpenOneRec: Предобучение и пост-обучение

## Общее описание

OpenOneRec использует сложную двухэтапную методологию обучения, сочетающую предобучение на смешанных данных с комплексным пост-обучением, направленным на восстановление общих возможностей и уточнение рекомендательных способностей.

## Архитектура

### Основа модели
- **Backbone**: Qwen3 архитектура
- **Параметры**: 1.7B и 8B параметров для стандартной версии
- **Продвинутая версия**: OneRec-Pro с до 14B параметров
- **Расширение словаря**: Добавление itemic токенов к оригинальному токенизатору

## Этап 1: Предобучение (Pre-Training)

### 1.1. Данные предобучения

#### Рекомендательные корпуса:
- **Itemic Dense Caption Data**: Обучение модели сопоставлять itemic токены с текстовыми описаниями айтемов
- **Sequential User Behavior Data**: Данные последовательных пользовательских взаимодействий для next-item prediction
- **Interleaved User Persona Grounding Data**: Интервальные пользовательские портреты, состоящие из естественного языка и itemic токенов

#### Общедоменные корпуса:
- **Математические данные**: Данные для поддержания математических рассуждений
- **Научные данные**: STEM (наука, технологии, инженерия, математика)
- **Кодовые данные**: Повышение способностей к программированию
- **Медицинские данные**: Многоязычные медицинские корпуса
- **Данные рассуждений**: Логические головоломки, математические доказательства

### 1.2. Методика обучения

#### Стадия 1: Itemic-Text выравнивание
- **Задача**: Установление предварительного выравнивания между itemic токенами и текстовыми токенами
- **Метод**: Расширение словаря добавлением itemic специальных токенов
- **Инициализация**: Параметры эмбеддингов инициализируются из многомерного нормального распределения
- **Обучение**: Только параметры эмбеддингов для itemic токенов (остальные заморожены)
- **LR**: 1 × 10^-3, косинусное затухание с линейным прогревом

#### Стадия 2: Полно-параметрическое совместное предобучение
- **Задача**: Инъекция рекомендательных знаний в модель
- **Метод**: Разморозка всех параметров и полно-параметрическое обучение
- **Цель**: Обучение модели захватывать сложные паттерны в пользовательском поведении, семантике айтемов и пользователь-айтем взаимодействиях
- **LR**: 1 × 10^-4, косинусное затухание с линейным прогревом
- **Макс. длина контекста**: 32K токенов для моделирования длинных историй

### 1.3. Стратегия смешивания данных
- **Соотношение**: 62.34% общедоменные + 37.66% рекомендательные (для OneRec)
- **Для OneRec-Pro**: 19% общедоменные + 81% рекомендательные (увеличенный доменный фокус)
- **Профилактика катастрофического забывания**: Сохранение значительной доли общедоменных данных

## Этап 2: Пост-обучение (Post-Training)

### 2.1. Много-задачное контролируемое дообучение (Multi-task SFT)

#### Цель
- Восстановление и усиление способностей следовать инструкциям
- Восстановление рассуждений через взаимодействие общедоменных и рекомендательных задач

#### Данные
- **Общедоменные инструкции**: Задачи рассуждений, математики, кодирования
- **Рекомендательные инструкции**: 8 задач RecIF-Bench в формате инструкций и ответов
- **Формат**: Чат-диалоги с использованием шаблона Qwen3

#### Процесс
- **LR**: Уменьшенный (от 2 × 10^-5 до 5 × 10^-6)
- **Результат**: Возрождение способностей следовать инструкциям

### 2.2. On-policy Distillation для общих возможностей

#### Методология
- **Цель**: Восстановление способностей к общему рассуждению, потерянных после предобучения
- **Стратегия**: On-policy distillation через Policy Gradient
- **Формула**: Минимизация reverse KL дивергенции между политикой студента π_θ и политики учителя π_teacher

```
L = E_{o~π_θ}[RKLDivergence(o|x)]
```

#### Решение проблемы словаря
- **Проблема**: Учитель не может распознать itemic токены
- **Решение 1**: Выбор только общедоменных промтов (без itemic токенов в выходах)
- **Решение 2**: Пенализация и усечение при генерации itemic токенов (установка log π_teacher(x_t|x_<t) = -1e9)
- **Решение 3**: Клиппинг вознаграждений и высокая температура для исследования

#### Процесс
- **200K вопросов** из общедоменного SFT датасета
- **Префиксы /think, /no_think, ""** для управления мышлением (auto-thinking)
- **Результат**: Восстановление общих интеллектуальных возможностей

### 2.3. Обучение с подкреплением для рекомендаций (Rec-RL)

#### Цель
- Прямая оптимизация дискретных метрик ранжирования (Recall, NDCG)
- Преодоление проблемы exposure bias в SFT

#### Методология
- **Framework**: Group Relative Policy Optimization (GRPO)
- **Преимущество**: Без отдельного critic модели, вычислительно эффективно
- **Формула оптимизации**:
```
J(θ) = E[(Adv_i)*log π_θ(R_i|q)]
```

#### Функция вознаграждения
- **Тип**: Sparse, rule-based, ориентирована на "hit" события
- **Формула**: r(R_i) = 1, если R_i содержит целевой айтем, 0 иначе
- **Задачи**: 5 основных рекомендательных задач (короткие видео, реклама, продукты, интерактивная, условная по метке)

#### Процесс
- **KL-пени за ref-модель**: Поддержание баланса между специфичностью домена и общими возможностями
- **Soft Ranking**: Присвоение более высокой вероятности itemic токенам, результирующим в успешные хиты

## Результаты методологии

### Эффективность подхода
- **Преемственность знаний**: Успешный перенос общих способностей из Qwen3
- **Баланс возможностей**: Сохранение общих рассуждений при усилении рекомендательных способностей
- **Масштабируемость**: Подтверждение законов масштабирования в рекомендациях

### Сравнение с одностадийными подходами
- **Преимущество двухэтапности**: Лучшее разделение ответственности между выравниванием и уточнением
- **Предотвращение забывания**: Поддержание баланса между доменными и общими знаниями
- **Адаптивность**: Возможность тонкой настройки каждой стадии отдельно

## Практические соображения

### Оборудование
- **Требования**: Значительные вычислительные ресурсы для полного пайплайна
- **Разделение фаз**: Возможность параллельной разработки разных стадий

### Гиперпараметры
- **AdamW optimizer**: β1=0.9, β2=0.95, вес декей 0.1
- **LR schedule**: Косинусное затухание с линейным прогревом
- **Прогрев**: Первые 10% шагов обучения

## Сравнение с альтернативами

### С простым fine-tuning
- OpenOneRec: Комплексное двухэтапное обучение с явным выравниванием
- Simple fine-tuning: Прямое дообучение на рекомендательных данных (риски забывания)

### С обучением с нуля
- OpenOneRec: Warm-start из предобученной Qwen3 (эффективнее)
- Обучение с нуля: Требует больше данных и вычислений

## Значение и влияние

Методология обучения OpenOneRec устанавливает новый стандарт для:
- **Фундаментальных рекомендательных моделей**: Комплексный подход к обучению
- **Балансировки доменных и общих возможностей**: Эффективные стратегии сохранения знаний
- **Масштабируемости**: Подтвержденные стратегии для обучения больших рекомендательных моделей
- **Интеграции с LLM**: Методы успешного адаптирования LLM для рекомендаций
