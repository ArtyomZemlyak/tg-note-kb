# Fast-Slow Thinking в OxygenREC

## Описание

Fast-Slow Thinking - это ключевая архитектурная концепция в OxygenREC, которая позволяет интегрировать возможности дедуктивных рассуждений и знаний о мире без введения онлайн задержек LLM. Архитектура разделяет процесс на два компонента: "медленное" мышление, выполняемое в близко-линейном режиме, и "быстрое" мышление, выполняемое в режиме реального времени.

## Архитектура

### Slow Thinking (Медленное мышление)
- **Назначение**: Выполняет медленное рассуждение о намерениях пользователя и синтезирует высокоточные инструкции контекстных рассуждений
- **Компоненты**:
  - LLM-ориентированный пайплайн для анализа пользовательского поведения и контекста
  - Генерация инструкций контекстных рассуждений (Contextual Reasoning Instructions)
  - Сохранение результатов в иерархическом порядке на основе триплета "время-локация-персона"
- **Режим работы**: Близко-линейный, а не полностью онлайн
- **Преимущества**: Позволяет использовать мощные LLM для дедуктивных рассуждений без влияния на время отклика системы

### Fast Thinking (Быстрое мышление)
- **Назначение**: Проводит генерацию в реальном времени на основе инструкций, сгенерированных медленным компонентом
- **Компоненты**:
  - Высокопроизводительная энкодер-декодер backbone сеть
  - Авто-регрессивная генерация рекомендательных последовательностей
- **Особенности**: Обеспечивает строгие ограничения по задержке и высокую пропускную способность

## Компоненты Fast-Slow Thinking

### Контекстные рассуждающие инструкции
Система использует три параллельные ветки для преобразования сложных сигналов рекомендаций в процесс рассуждения на основе многомерных контекстов:
1. **Spatiotemporal and profile Reasoning (STP)**: Фокусируется на инференсе явных потребностей пользователя при определенных ограничениях окружающей среды
2. **User Query Rewrite**: Выполняет семантическое завершение и нормализацию поисковых запросов
3. **User Intent Reasoning**: Генерирует инструкции, соответствующие намерениям, и их логические обоснования

### Spatiotemporal and profile Reasoning (STP)
Тип инструкции, который фокусируется на инференсе явных потребностей пользователя в конкретных условиях окружающей среды:
- **Event-driven reasoning**: идентифицирует важные праздники или сезонные особенности во времени и месте, и инферирует связанные с ними покупательские намерения
- **Profile-driven reasoning**: использует статические черты пользователя (пол, возраст, платежеспособность) для формирования персонализованных выводов о предпочтениях продуктов
- **STP Fusion reasoning**: комбинирует местную культуру с данными о погоде/времени для инференса локализованных потребностей

### User Query Rewrite
Реальные поисковые запросы могут иметь неполные намерения или семантический сдвиг из-за языкового шума или усечения ввода. OxygenREC использует LLMQR (LLM Query Rewriter) для семантического завершения и нормализации:
- Обучение на данных самокоррекции сессий
- Использование данных с заголовками, выровненными по клик-фидбеку
- Генерация синтетических ошибочных образцов

### User Intent Reasoning
Генерирует как инструкции, соответствующие намерениям, так и их обоснования одновременно. Добавление рационала объясняет логику за рекомендацией и помогает модели находить более глубокие мотивации из зашумленного поведения.

## Преимущества подхода

1. **Избегание онлайн задержек LLM**: Вся тяжелая LLM-обработка выполняется вне основного пути инференса
2. **Контролируемая генерация**: Инструкции обеспечивают точное управление процессом генерации
3. **Интерпретируемость**: Процесс построения рекомендаций становится более понятным
4. **Масштабируемость**: Архитектура позволяет эффективно масштабироваться до промышленных сценариев

## Механизм развертывания инструкций рассуждений

Система использует близко-линейный механизм обновления для баланса между своевременностью сигналов рекомендаций и общими накладными расходами системы:
- **Ежедневное полное обновление**: Оффлайн задание регенерирует пространственно-временные и поведенческие инструкции для всех ежедневно активных пользователей
- **Близко-линейное инкрементное обновление**: При выполнении пользователем высокозначимых действий (поиск, просмотр, добавление в корзину или покупка) система запускает близко-реальное обновление инструкций
- **Стратегия агрегации по временным окнам**: Для предотвращения чрезмерного давления на запись и нестабильности системы, взаимодействия, происходящие в коротком скользящем окне (например, 5 минут), объединяются в единое резюме намерений
