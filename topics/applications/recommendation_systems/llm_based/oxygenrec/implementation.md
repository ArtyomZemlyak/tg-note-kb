# Реализация и оптимизация OxygenREC

## Описание

OxygenREC представляет собой уникальный инженерный вызов, требующий одновременной обработки терабайтных разреженных эмбеддингов (характерных для рекомендательных систем) и миллиардных плотных параметров (характерных для LLM). Реализация включает в себя унифицированный тренировочный фреймворк, оптимизации инференса и эффективные методы развертывания инструкций рассуждений.

## Унифицированный тренировочный фреймворк

### Общая архитектура
OxygenREC использует тренировочный фреймворк, построенный на PyTorch, который интегрирует промышленные разреженные и плотные движки. В системе используется кластер из 128 NVIDIA H800 GPU с использованием 400 Гб/с NVLink и 8×200 Гб/с RoCEv2 RDMA для высокопроизводительных интерконнектов. Удалось достичь общей эффективности Model FLOPs Utilization (MFU) 40% за счет следующих ключевых оптимизаций.

### Распределенная оптимизация разреженных данных
- **Неразделяющаяся стратегия**: Реализация неразделяющейся стратегии разделения эмбеддингов по воркерам
- **Иерархический HBM-MEM кэш**: Использование иерархического кэша с высокоскоростной памятью
- **Многоступенчатый пайплайн**: Установка многоступенчатого пайплайна для скрытия задержки доступа к эмбеддингам
- **Механизм двойного буфера**: Для избежания застаривания эмбеддингов и обеспечения гарантий строгой консистентности
- **Снижение времени**: Снижение времени операций с разреженными данными с 15% до 5%
- **Ускорение**: 1.1-2.4× ускорение по сравнению с современными open-source решениями для эмбеддингов

### Оптимизация на уровне операторов
- **BF16 mixed-precision обучение**: Использование BF16 mixed-precision обучения для эффективности памяти
- **ZeRO**: Использование ZeRO для эффективности памяти
- **Продвинутые механизмы внимания**: Использование продвинутых механизмов внимания и эффективных архитектур
- **Кастомная библиотека ускорения внимания**: Разработка специализированной библиотеки ускорения внимания для гибридных паттернов маскировки
- **CUTLASS и TileLang**: Использование CUTLASS и TileLang для кастомной компиляции кернелов
- **Ускорение**: 1.7× и 3.0× ускорение по сравнению с FlexAttention и torch.compile соответственно

### Сценарно-ориентированное обучение с подкреплением
- **Ray**: Построение кастомного RL пайплайна поверх Ray
- **Совместное размещение**: Включение доступа к разделяемой памяти для разреженных таблиц
- **Эффективная синхронизация**: Обеспечение эффективной синхронизации во время фазы генерации сэмплов с высокой пропускной способностью

## Оптимизация инференса на основе xLLM

### Проблемы традиционного инференса
GR интегрирует LLM для улучшения понимания последовательностей, но его инференс нагрузка значительно отличается от стандартного LLM сервиса. GR обычно обрабатывает длинные промпты истории пользователя при генерации относительно коротких выводов при большом beam width (например, размер beam = 256-512). Такая настройка делает декодирование основным узким местом.

### xGR: Специализированная система сервиса
- **Трехуровневая архитектура**: Сильно связанная трехуровневая архитектура для максимизации эффективности оборудования
  - **xSchedule (System Level)**: Совершенный планировщик, управляющий параллелизмом задач
  - **xAttention (Operator Level)**: Построен на основе xLLM's PagedAttention с дополнительной настройкой для паттернов внимания GR
  - **xBeam (Algorithm Level)**: Специализированный модуль для обработки массивного сортировочного оверхеда при большом beam декодировании

### Специализированный Beam Search и семплинг
- **Сочетание top-k и nucleus/мультиномиального семплинга**: Высоко оптимизированный Beam Sample кернел
- **Операторный фьюжн**: Использование операторного фьюжна для обработки стохастичности без ухудшения производительности
- **Снижение задержки декодирования**: Значительное снижение задержки декодирования по сравнению с ванильными реализациями

### Prefixed-Constrained декодирование
- **Trie Index механизм**: Интеграция Trie Index механизма в инференс цикл
- **Логит маски**: Динамическая генерация логит масок на каждом шаге
- **Гарантия 100%**: Гарантия 100% легальности генерации в пределах назначенных пулов айтемов
- **Незначительный оверхед**: Незначительный runtime оверхед

## Развертывание инструкций рассуждений

### Близко-линейная архитектура
- **Баланс между свежестью и оверхедом**: Использование близко-линейного обновления для баланса между своевременностью сигналов рекомендаций и общим оверхедом системы
- **Два каскадных компонента**: 
  1. LLM-базированный сервис генерации инструкций
  2. Adapter-базированный сервис текстового энкодинга

### Архитектура развертывания
- **Оффлайн генерация**: Инструкции не генерируются на лету во время пользовательских запросов, а производятся батчами
- **Adapter энкодер**: Преобразование текстовых инструкций в плотный эмбеддинг вектор
- **Низколатентный KV-стор**: Индексация эмбеддинга по ID пользователя и хранение в низколатентном KV-сторе (например, Redis кластер)
- **Нулевые онлайн LLM вызовы**: Возможность получения предвычисленного эмбеддинга инструкции просто по ID пользователя

### Гибридная стратегия обновления
1. **Ежедневное полное обновление**:
   - Оффлайн задание регенерирует пространственно-временные и поведенческие инструкции для всех ежедневно активных пользователей
   - Включение последних контекстных сигналов (например, сезон, локация) и накопленных взаимодействий

2. **Близко-линейное инкрементное обновление**:
   - При выполнении пользователем высокозначимых действий (поиск, просмотр, добавление в корзину, покупка) запускается близко-реальное обновление инструкций
   - Использование стратегии агрегации по временным окнам: несколько поведенческих событий от одного пользователя объединяются в единое резюме намерений
   - Выполняется только одна генерация инструкции и запись в хранилище в конце окна

### Преимущества архитектуры
- **Нулевые онлайн LLM вызовы**: Обеспечение низкой задержки сервиса
- **Высокая семантическая точность**: Сохранение высокой семантической достоверности в финальных рекомендациях
- **Снижение нагрузки**: Значительное снижение нагрузки на бэкенд за счет стратегии агрегации

## Оценка производительности

### Метрики модели
- **HitRate@K (HR@K)**: Квантификация точности генеративного процесса, измеряющая долю тестовых инстансов, где сгенерированный кандидат строго совпадает с истинной последовательностью семантических ID на всех уровнях иерархического кода в топ-K гипотезах beam search
- **Recall@K**: Оценка способности модели покрывать релевантные интересы пользователя

### Метрики семантических ID
- **Покрытие Codebook**: Оценка эффективности использования иерархического семантического пространства
- **Чистота семантического кластера**: Оценка совмещения изученных семантических кластеров с человеко-определенной таксономией
- **Коллизия семантических ID**: Квантификация дискриминативной силы семантических идентификаторов в различении индивидуальных айтемов
- **Баланс нагрузки Codebook**: Измерение равномерности распределения айтемов по квантовому codebook
