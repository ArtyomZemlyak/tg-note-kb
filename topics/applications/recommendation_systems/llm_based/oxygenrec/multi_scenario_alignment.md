# Мульти-сценарная адаптация в OxygenREC

## Описание

Мульти-сценарная адаптация - это ключевая способность OxygenREC, позволяющая одной модели обслуживать различные сценарии рекомендаций одновременно. Подход реализует парадигму "обучай один раз - разворачивай везде" (train-once-deploy-everywhere), преодолевая ограничения традиционных методов, требующих отдельных моделей для каждого сценария.

## Проблематика

Традиционные подходы к мульти-сценарным рекомендательным системам сталкиваются с рядом проблем:
- **Высокие операционные и вычислительные затраты**: Обучение отдельных моделей для каждого сценария
- **Отрицательный перенос (negative transfer)**: Использование сложных маршрутизационных/шлюзовых механизмов для смягчения проблемы
- **Высокие затраты на обслуживание**: Поддержка отдельных инстансов моделей или сложной логики маршрутизации

## Подход OxygenREC

### Сценарные инструкции
Вместо раздельных моделей OxygenREC использует единый фреймворк для всех сценариев:
- **Сценарные инструкции (Is)**: Преобразование информации о сценариях в контролируемые инструкции
- **Единая модель**: Одна backbone сеть для всех сценариев
- **Преобразование данных**: Сценарная информация преобразуется в инструкции, которые управляют поведением модели

### Unified Reward Mapping Service
- **Центральный сервис вознаграждений**: Единая модель ранжирования как центральный сервис вознаграждений
- **Сценарно-специфичные цели**: Перевод различных сценарных целей (например, разнообразие, формат) в унифицированные сигналы вознаграждения
- **Снижение затрат**: Значительное снижение вычислительных затрат на обучение и онлайн-деплой

## Архитектура мульти-сценарной адаптации

### Scenario-Aware Reward Mapping
Общая оценка вознаграждения является взвешенной комбинацией различных компонентов:

1. **Форматное вознаграждение (Format Reward)**: Наказывает структурные ошибки для обеспечения корректного вывода семантических ID айтемов
2. **Относительное вознаграждение (Relative Reward)**: Награждает айтемы, релевантные немедленному контексту и запросу пользователя
3. **Ранжирующее вознаграждение (Ranking Reward)**: Награждает последовательности, максимизирующие бизнес-объективы (например, GMV или коэффициент конверсии)
4. **Вознаграждение разнообразию (Diversity Reward)**: Оценивает разнообразие группы айтемов, сгенерированных моделью

### Единая модель ранжирования
- **Общий подход**: Объединенный списочный (list-wise) подход как для оффлайн обучения, так и для онлайн-обучения
- **Единое представление**: Объединенные токены представлений из гетерогенных пользовательских признаков
- **Общий блок извлечения признаков**: Общий Transformer-базированный блок извлечения признаков для кросс-сценарного взаимодействия признаков
- **Адаптивный механизм моделирования**: Для решения проблемы гетерогенности входных признаков

### SA-GCPO: Soft Adaptive Group Clip Policy Optimization
Особое внимание уделяется оптимизации политики (policy optimization) для мульти-сценарной адаптации:
- **Soft Adaptive функция**: Вычисление весов importance sampling через адаптивную функцию
- **Пороги на основе реального пользовательского поведения**: Использование оценок вознаграждения из реального поведения пользователей как порога для различения позитивных и негативных сэмплов
- **Асимметричный температурный контроль**: Разные температурные коэффициенты для позитивных и негативных сэмплов

## Сценарии развертывания

OxygenREC была развернута в трех последовательно зависимых сценариях на платформе JD App:

### Phase 1: Инициация интереса (Homepage Floor)
- **Сценарии 1 и 2**: Высокий трафик, строгие ограничения по задержке
- **Назначение**: Рекомендация визуально привлекательных айтемов, релевантных интересам пользователя
- **Цель**: Привлечение кликов, направляющих пользователей в downstream фиды

### Phase 2: Глубокая эксплорация (Feeds Recommendation)
- **Сценарии 3 и 4**: Рекомендации на основе "триггерного айтема" (кликнутого айтема)
- **Механизм**: Бесконечный скролл для долгого удержания внимания
- **Цель**: Содействие добавлению в корзину или покупке

### Phase 3: Немедленная конверсия (Checkout Path Recommendations)
- **Сценарии 5 и 6**: Рекомендации во время процесса транзакции
- **Add-to-Cart Overlay**: Немедленные рекомендации при добавлении айтема в корзину
- **Checkout Add-on**: Рекомендации во время процесса оплаты
- **Цель**: Использование сильного намерения пользователя для дополнительных конверсий

## Преимущества мульти-сценарной адаптации

1. **Экономия ресурсов**: Значительное снижение вычислительных и операционных затрат
2. **Единая модель**: Упрощение обслуживания и развертывания
3. **Синергетический перенос знаний**: Высокоресурсные сценарии улучшают обучение для низкоресурсных сценариев
4. **Универсальное моделирование пользователей**: Голистическое понимание интересов пользователей
5. **Повышенная эффективность операций**: Снижение GPU и сопутствующих затрат на обслуживание

## Сравнение с другими подходами

В отличие от традиционных подходов к мульти-сценарным рекомендациям:
- **STAR [51]**: Использует сложные специализированные структуры и требует отдельных инстансов моделей
- **PEPNet [9]**: Использует сложную логику маршрутизации для смягчения отрицательного переноса
- **OneRec series**: Ограниченная поддержка мульти-сценарной адаптации

OxygenREC предлагает более унифицированный и эффективный подход, основанный на:
- Сценарных инструкциях
- Едином сервисе вознаграждений
- SA-GCPO для оптимизации политики

## Интеграция с другими компонентами

- **Instruction Following**: Сценарные инструкции используются как часть общего фреймворка следования инструкциям
- **Fast-Slow Thinking**: Инструкции объединяются с инструкциями контекстных рассуждений
- **Semantic Alignment**: Используется для обеспечения согласованности между сценарными инструкциями и айтемами

## Будущие направления

- **Latency Optimization**: Переход к Non-Autoregressive (NAR) парадигме для минимизации задержки сервиса
- **Multi-Scenario User Trajectory Modeling**: Интеграция и анализ кросс-сценарных последовательностей для раскрытия глубоких целей пользователей
