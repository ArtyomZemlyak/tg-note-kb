# Revisiting Neural Retrieval on Accelerators: Mixture-of-Logits и революция в ретривале

## Описание

Revisiting Neural Retrieval on Accelerators - статья от Meta, в которой показано, что retrieval можно делать на GPU без индекса. Также вводится модель mixture-of-logits (MoL), которая является более выразительной, но всё ещё относительно дешевой в вычислениях функцией. Для многих исследователей это была первая статья, показавшая, что retrieval можно делать лучше, чем всем привычным HNSW.

## Контекст проблемы

Традиционные подходы к ретривалу в рекомендательных системах сталкиваются с рядом ограничений:

- **Индексация**: необходимость создания и поддержки сложных индексов (например, HNSW)
- **Точность**: ограничения в expressiveness при использовании простых метрик (например, dot product)
- **Масштабируемость**: сложности с обработкой миллиардных каталогов айтемов
- **Задержки**: значительные латентности при работе с индексами

## Архитектурное решение: Mixture-of-Logits (MoL)

### Основные компоненты:

#### 1. Direct Retrieval на GPU
- Непосредственное вычисление схожести на GPU без использования индексов
- Возможность масштабирования до миллиардных словарей
- Обход традиционных подходов к индексации

#### 2. Mixture-of-Logits (MoL)
- Вместо простого dot product использует более сложную функцию схожести
- Комбинирует несколько функций схожести с помощью нейронных весов
- Более выразительная, но вычислительно эффективная архитектура

#### 3. Non-dot-product retrieval
- Выход за рамки простых скалярных произведений
- Моделирование более сложных отношений между пользователями и айтемами
- Адаптивное определение схожести на основе контекста

## Архитектура Mixture-of-Logits

Mixture-of-Logits реализует взвешенную комбинацию косинусных схожестей с использованием нейронных сетей для вычисления весов:

1. **Multiple similarity functions**: Несколько различных функций схожести между векторами
2. **Neural gates**: Нейронные сети, определяющие веса для каждой функции схожести
3. **Adaptive combination**: Адаптивное объединение результатов различных функций

## Преимущества

### 1. Отказ от сложной индексации
- Возможность прямого поиска на GPU без предварительных индексов
- Упрощение архитектуры рекомендательной системы
- Снижение требований к инфраструктуре индексации

### 2. Повышенная выразительность
- MoL более выразительна по сравнению с простыми dot product
- Возможность моделирования сложных отношений
- Лучшие метрики качества по сравнению с HNSW

### 3. Скаляряемость на GPU
- Эффективное использование GPU для ретривала
- Масштабируемость до миллиардных каталогов
- Более высокая производительность по сравнению с CPU-ориентированными индексами

## Сравнение с HNSW

| Аспект | HNSW (традиционный подход) | MoL на акселераторах |
|--------|---------------------------|----------------------|
| Индексация | Требуется сложный индекс | Нет необходимости в индексе |
| Выразительность | Ограниченная (dot product) | Высокая (MoL) |
| Скаляряемость | Ограничена структурой индекса | Масштабируется на GPU |
| Точность | Стандарт для индустрии | Превосходит HNSW |
| Инфраструктура | Сложная индексация | Простая архитектура |

## Последующие улучшения

В последующей статье Meta показала, что можно совмещать преимущества обоих подходов:
- Использование индексов с прямым поиском по MoL
- Сохранение точности MoL без необходимости полного перебора
- Компромисс между выразительностью и эффективностью

## Значение для индустрии

Revisiting Neural Retrieval on Accelerators стало поворотной точкой в подходах к ретривалу:

- **Альтернатива HNSW**: Предложена реальная альтернатива доминирующей архитектуре
- **GPU-ориентированный ретривал**: Сдвиг в сторону использования GPU для поиска
- **Выразительные модели**: Возможность использования более сложных функций схожести
- **Упрощение архитектуры**: Снижение сложности за счёт отказа от индексов
