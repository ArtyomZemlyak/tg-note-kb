# CDN (Cross Decoupling Network): Архитектура для рекомендации длинного хвоста айтемов

## Описание

**Cross Decoupling Network (CDN)** — архитектура рекомендательных систем, разработанная исследователями Google для решения проблемы long-tail распределения айтемов. Основная идея заключается в двойном разделении (dual decoupling): разделение признаков айтемов на меморизующие и генерализующие, а также разделение пользовательских представлений через регуляризованную Bilateral-Branch Network (BBN).

Работа опубликована на конференции **KDD 2023**.

## Проблема

В рекомендательных системах существует проблема **long-tail распределения**: популярные айтемы (head items) получают много взаимодействий и хорошо обучаются, в то время как непопулярные айтемы (tail items) имеют мало данных и их эмбеддинги становятся зашумленными из-за недостатка градиентных обновлений.

CDN решает эту проблему через:
1. **Разделение признаков айтемов** на меморизующие и генерализующие
2. **Разделение пользовательских представлений** через BBN
3. **Взвешивание по популярности** для балансировки вклада разных типов признаков

## Архитектура CDN

### 1. Разделение признаков айтемов (Item Feature Decoupling)

CDN разделяет признаки айтемов на два типа:

| Тип признаков | Назначение | Примеры | Характеристики |
|---------------|------------|---------|----------------|
| **Меморизующие (Memorizing)** | Запоминание пользовательско-айтемных взаимодействий (коллаборативная информация) | Item ID | Уникальность: разные для каждого айтема; Независимость: признаки не влияют друг на друга |
| **Генерализующие (Generalizing)** | Обучение корреляций между предпочтениями пользователя и характеристиками айтема | Категория айтема, теги, непрерывные признаки | Общие для разных айтемов; Возможность обобщения на новые айтемы |

**Проблема меморизующих признаков:** Head items получают частые обновления эмбеддингов (сильная меморизация), в то время как tail items страдают от зашумленных эмбеддингов из-за недостатка градиентных обновлений.

### 2. Архитектура Mixture of Experts (MoE)

Для обработки разделенных признаков используется архитектура MoE:

```
Для обучающей выборки (u, i), эмбеддинг айтема вычисляется как:

y = Σ(k=1 to n₁) G(i)ₖ · Eₖᵐᵐ(i_mm) + Σ(k=n₁+1 to n₁+n₂) G(i)ₖ · Eₖᵍᵉⁿ(i_gen)

Где:
- Eₖᵐᵐ: Меморизующие экспертные подсети (вход: меморизующие признаки, например item ID)
- Eₖᵍᵉⁿ: Генерализующие экспертные подсети (вход: генерализующие признаки, например категория айтема)
- G: Gating network (сеть ворот) с ΣG(i) = 1
```

**Структура:**
- Меморизующие признаки → Меморизующие экспертные подсети
- Контентные/генерализующие признаки → Генерализующие экспертные подсети
- Gating механизм: Обучаемая функция, взвешивающая представления

### 3. Взвешивание на основе популярности (Popularity-Based Weighting)

**Дизайн Gating Network:**
```
g(i) = softmax(W · i_freq)
```

- Использует частоту айтема (item frequency) как вход gating функции
- Производит взвешенные значения для балансировки меморизующих и генерализующих признаков
- Гарантирует `Σ(k=1 to n₁+n₂) G(i) = 1`

**Зависимость от популярности:**
- Для head items (популярных): больший вес на меморизующие признаки
- Для tail items (непопулярных): больший вес на генерализующие признаки

### 4. BBN регуляризация (разделение пользовательских представлений)

**Regularized Bilateral-Branch Network:**

| Ветка | Распределение обучения | Назначение |
|-------|------------------------|------------|
| **Основная ветка (Main Branch)** | Исходное сильно перекошенное long-tail распределение (Ωₘ) | Обучение высококачественных пользовательских представлений с сохранением характеристик исходного распределения; learns optimal and most generalizable representations |
| **Ветка регуляризации (Regularization Branch)** | Относительно сбалансированное распределение (Ωᵣ) | Добавление информации о tail items в модель; предотвращение переобучения на tail items |

**Построение Ωᵣ:**
- Включает все пользовательские фидбеки для tail items
- Downsamples пользовательские фидбеки для head items до частоты самого популярного tail item

**Формула представлений:**
```
xₘ = hₘ(f(uₘ))  [Основная ветка]
xᵣ = hᵣ(f(uᵣ))  [Ветка регуляризации]
```
Где `f` — общая (shared) сеть.

### 5. Адаптер и агрегация

- Новый **адаптер** агрегирует разделенные векторы
- Смещает внимание обучения в сторону long-tail айтемов

## Ключевые инновации

1. **Двойное разделение (Dual Decoupling):**
   - Разделение признаков айтемов (меморизующие vs генерализующие)
   - Разделение пользовательских представлений (BBN)

2. **MoE с gating по популярности:**
   - Динамическое взвешивание экспертов на основе популярности айтема
   - Балансировка между запоминанием и обобщением

3. **Регуляризация через BBN:**
   - Сбалансированное распределение для tail items
   - Предотвращение переобучения

## Преимущества CDN

| Аспект | Преимущество |
|--------|--------------|
| **Long-tail рекомендация** | Улучшенная рекомендация непопулярных айтемов через генерализующие признаки |
| **Баланс memorization/generalization** | Динамическая балансировка через gating network |
| **Устойчивость к переобучению** | BBN регуляризация предотвращает overfitting на tail items |
| **Гибкость архитектуры** | Возможность масштабирования через добавление экспертов |

## Сравнение с другими подходами

| Характеристика | CDN | Традиционные двухбашенные архитектуры |
|----------------|-----|---------------------------------------|
| Разделение признаков | Меморизующие + Генерализующие | Единое представление |
| Взвешивание признаков | popularity-based gating | Статическое или обучаемое без явного разделения |
| Обработка long-tail | BBN регуляризация + MoE | Стандартные техники (oversampling, reweighting) |
| Экспертная архитектура | MoE с popularity gating | Обычно без MoE |

## Применение

- **E-commerce рекомендации**: Работа с большим каталогом товаров с long-tail распределением
- **Контентные рекомендации**: Балансировка между популярным и нишевым контентом
- **Промышленные системы**: Масштабируемая архитектура для больших каталогов

## Ключевые термины

- **Cross Decoupling Network (CDN)**: Архитектура для long-tail рекомендации через разделение признаков
- **Memorizing Features**: Меморизующие признаки (например, item ID) для запоминания взаимодействий
- **Generalizing Features**: Генерализующие признаки (например, категория, теги) для обобщения
- **Mixture of Experts (MoE)**: Архитектура с несколькими экспертными подсетями
- **Gating Network**: Сеть ворот для динамического взвешивания экспертов
- **Bilateral-Branch Network (BBN)**: Двухветочная сеть для регуляризации пользовательских представлений
- **Long-tail Distribution**: Распределение с большим количеством непопулярных айтемов
