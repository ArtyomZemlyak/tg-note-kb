# RankMixer: Масштабируемая архитектура ранжирования для индустриальных рекомендательных систем

## Описание

**RankMixer** — это масштабируемая архитектура ранжирования, разработанная компанией ByteDance для промышленных рекомендательных систем. Основная цель архитектуры — повышение эффективности использования GPU (MFU — Model FLOPs Utilization) при сохранении высокого качества рекомендаций.

RankMixer позиционируется как продолжение линейки работ по deep learning в рекомендациях, включая Wide&Deep, DeepFM, DCNv2 и других моделей, развивающих feature interactions.

## Проблема

Современные ранжирующие модели часто плохо используют GPU. Многие подходы исторически оптимизировались под CPU, из-за чего GPU-утилизация остаётся низкой. RankMixer решает эту проблему через новую архитектуру, позволяющую эффективно масштабировать модели ранжирования.

## Архитектура

### Входные данные

На вход подаются **гетерогенные признаки**:
- Профиль пользователя
- Профиль видео
- Видеофичи
- Сигналы взаимодействий

Все признаки переводятся в **token-based представление** — токены одинаковой размерности. На входе получается матрица `T×D`, где:
- `T` — число токенов
- `D` — их размерность

### RankMixer Block

Основной блок архитектуры состоит из двух частей:

#### 1. Multi-head Token Mixing

Каждый токен разбивается на `H` голов, чтобы смешивать разные семантические фрагменты и лучше учитывать гетерогенность признаков.

Смешивание происходит через **конкатенацию**: для каждой головы берётся соответствующая часть всех токенов и собирается новая матрица. Так учитываются взаимодействия:
- Внутри токенов
- Между разными группами признаков

#### 2. Per-token FFN (PFFN)

Каждый токен обрабатывается индивидуально через feed-forward-слой, применяемый отдельно для каждого токена.

В PFFN используется **Sparse Mixture-of-Experts (MoE)**:
- Позволяет увеличивать capacity модели без такого же роста флопсов
- Вместо одного FFN берётся набор экспертов
- Для каждого токена активируется только часть экспертов

### Проблема Dying Experts

В статье отдельно обсуждается проблема **dying experts**, когда работают только несколько доминирующих экспертов. Для борьбы с этим используются:

1. **Routing-стратегия**: роутер выбирает несколько экспертов для каждого токена
2. **Load balancing losses**: дополнительные функции потерь для равномерного использования экспертов

### Выходной слой

После нескольких блоков выход агрегируется через **pooling**, и дальше модель предсказывает таргетные сигналы:
- Skip
- Like
- Completion
- Другие пользовательские действия

## Эксперименты

### Офлайн-оценка

Для офлайн-оценки использовались стандартные метрики:
- **AUC** — площадь под ROC-кривой
- **UAUC** — пользовательско-нормализованная AUC

Эксперименты проводились на:
- Рекомендациях видео
- Рекламных рекомендациях

### Бейзлайны

В качестве бейзлайнов сравнивали RankMixer с:
- MLP + feature crossing
- DCNv2
- AutoInt
- HiFormer

### Онлайн A/B-тестирование

Долгий A/B-эксперимент проводился в **Douyin** и **Douyin Lite**. По итогам эксперимента:
- Заменили в проде 16M модель на **RankMixer 1B**
- Без существенного увеличения времени на инференс

## Результаты

1. **Качество**: RankMixer выигрывает у бейзлайнов как в варианте около 100M параметров, так и в варианте около 1B параметров. Полученные улучшения статистически значимы.

2. **Скейлинг**: RankMixer показывает более выгодное соотношение между качеством (AUC) и масштабом модели.

3. **Абляции** показали главный вклад компонентов:
   - Удаление **Multi-head Token Mixing** сильно снижает качество
   - Замена **Per-token FFN** на shared FFN тоже ухудшает метрики

## Ключевые преимущества

1. **Эффективное использование GPU** — повышенный MFU по сравнению с традиционными архитектурами
2. **Масштабируемость** — возможность увеличения модели до 1B параметров
3. **Гетерогенность признаков** — эффективное взаимодействие разнородных фичей через token-based подход
4. **Sparse MoE** — увеличение capacity без пропорционального роста вычислений
