# DeepConf: Офлайн и онлайн режимы

## Обзор

DeepConf (Deep Think with Confidence) реализует два основных режима работы: **офлайн-мышление** и **онлайн-мышление**. Оба режима используют внутренние сигналы уверенности модели для повышения эффективности и точности рассуждений, но отличаются по времени и способу применения этих сигналов.

## Офлайн-мышление (Offline Thinking)

### Определение
Офлайн-мышление использует уверенность для повышения производительности рассуждений за счет оценки и агрегации информации из уже завершенных трасс рассуждений.

### Характеристики
- Все трассы рассуждений сгенерированы до начала анализа уверенности
- Позволяет использовать полную информацию о каждой трассе
- Подходит для сценариев, где все трассы уже доступны
- Позволяет провести более точный анализ уверенности на основе полной трассы

### Применение методов уверенности
1. **Взвешенное голосование по большинству**:
   - Вместо равного веса для каждого голоса, каждый финальный ответ взвешивается по уверенности связанной трассы
   - Формула: V(a) = Σ C_t, где C_t - уверенность трассы t, отвечающей a

2. **Фильтрация уверенности**:
   - Выбирает верхний η процент трасс на основе оценок уверенности трассы
   - Обеспечивает, что только самые надежные пути вносят вклад в финальный ответ
   - Два варианта: η = 10% (фокус на самых высоконадежных трассах) и η = 90% (более сбалансированный подход)

3. **Типы фильтрации**:
   - **Консервативная (η = 90%)**: сохраняет больше трасс, уменьшает риск потери полезной информации
   - **Агрессивная (η = 10%)**: сохраняет только самые уверенные трассы, может дать больший прирост точности

### Алгоритм (Офлайн-мышление с уверенностью)
```
Входы: Подсказка P, количество трасс N, порог фильтрации η, измерение уверенности C(t)
Инициализация набора трасс T ← ∅, набора уверенности C ← ∅
для i = 1 до N:
    Генерировать трассу t_i для подсказки P
    Рассчитать уверенность трассы C_i = C(t_i)
    Добавить (t_i, C_i) в (T, C)
Выбрать верхние η процентов трасс на основе уверенности C_i
Вычислить V(a) для всех ответов a
Вернуть финальный ответ â с наиболее взвешенным голосованием: â = arg max_a V(a)
```

### Экспериментальные результаты (оффлайн)
- **DeepConf с фильтрацией 10%**: значительные улучшения по сравнению со стандартным majority voting (например, DeepSeek-8B на AIME25: 82.3% → 87.4%)
- **GPT-OSS-120B на AIME25**: достижение 99.9% точности с использованием DeepConf@512
- **Консервативная фильтрация (90%)**: безопасный вариант с минимальным риском ухудшения точности

## Онлайн-мышление (Online Thinking)

### Определение
Онлайн-мышление интегрирует уверенность во время генерации токенов для повышения производительности рассуждений и/или вычислительной эффективности в реальном времени.

### Характеристики
- Оценка уверенности в процессе генерации трассы
- Возможность ранней остановки неперспективных трасс
- Позволяет экономить вычислительные ресурсы в реальном времени
- Подходит для сценариев с ограниченными ресурсами или временем

### Компоненты онлайн-мышления
1. **Оффлайн разогрев (Offline Warmup)**:
   - Генерация N_init начальных трасс (например, N_init = 16)
   - Установка порога остановки s на основе статистики разогрева
   - Порог определяется как перцентиль от уверенности трасс разогрева

2. **Адаптивная выборка (Adaptive Sampling)**:
   - Динамическая оценка сложности задачи по консенсусу среди сгенерированных трасс
   - Формула: β = V(â) / Σ_a V(a), где τ - заданный порог консенсуса
   - Если β < τ, генерация продолжается до достижения бюджета B

3. **Динамическая остановка**:
   - Остановка генерации трассы, когда уверенность падает ниже порога
   - Использует метрику Lowest Group Confidence

### Алгоритм (Онлайн-мышление с уверенностью)
```
Входы: Подсказка P, бюджет трасс B, начальные трассы N_init, порог фильтрации η, порог консенсуса τ

Оффлайн разогрев:
    Выполнить Алгоритм 1 с N = N_init трассами с использованием Lowest Group Confidence
    Рассчитать порог s = Percentile_100-η(C_0, C_1, ..., C_N_init-1)
    Инициализировать набор трасс T ← (t_0, t_1, ..., t_k)
    Рассчитать значения голосов V(a) для всех ответов a и основной ответ â

Онлайн генерация:
    пока (V(â) / Σ_a V(a)) < τ и |T| < B:
        пока генерируется трасса t:
            Генерировать следующий токен i и рассчитать групповую уверенность C_G_i
            Если C_G_i < s: остановить генерацию трассы t
            Иначе: добавить токен i к трассе t
        Добавить трассу t к T
        Рассчитать уверенность трассы C_t
        Обновить подсчет голосов V(a) и основной ответ â
    Вернуть â и остановить генерацию
```

### Два варианта DeepConf в онлайн-режиме
1. **DeepConf-low**:
   - Использует η = 10% (соответствует 90-му перцентилю)
   - Более агрессивная стратегия остановки
   - Достигает большей экономии токенов, но может сопровождаться небольшим риском снижения точности

2. **DeepConf-high**:
   - Использует η = 90% (соответствует 10-му перцентилю)
   - Более консервативная стратегия
   - Сохраняет больше трасс, обеспечивая стабильность точности

### Экспериментальные результаты (онлайн)
- **DeepConf-low**: снижение токенов на 43-79% при сохранении или улучшении точности
- **DeepConf-high**: снижение токенов на 18-59% с почти неизменной точностью
- **Пример**: на GPT-OSS-120B с AIME25 DeepConf-low снижает генерацию токенов на 84.7% при сохранении точности

## Сравнение режимов

### Сходства
- Оба режима используют внутренние сигналы уверенности для повышения эффективности
- Оба применяют фильтрацию трасс на основе уверенности
- Оба направлены на повышение точности и/или снижение вычислительных затрат

### Отличия
| Аспект | Офлайн-мышление | Онлайн-мышление |
|--------|----------------|-----------------|
| **Время оценки уверенности** | После завершения трассы | В процессе генерации |
| **Возможность ранней остановки** | Нет | Да |
| **Экономия ресурсов** | За счет фильтрации | За счет ранней остановки |
| **Сложность реализации** | Проще | Более сложная |
| **Требования к памяти** | Хранение всех трасс | Меньше (прерванные трассы не завершаются) |
| **Применимость** | Когда все трассы доступны | В ресурсоограниченных условиях |

### Выбор между режимами
- **Офлайн-режим** лучше подходит для ситуаций, где все трассы уже сгенерированы и нужно максимизировать точность из существующего пула
- **Онлайн-режим** идеален для ситуаций, где важна вычислительная эффективность и нужно экономить ресурсы во время генерации

## Практические соображения

### Оптимальные параметры
- **N_init (разогрев)**: 16 трасс показали хорошее соотношение точности и накладных расходов
- **τ (порог консенсуса)**: 0.95 обеспечивает лучший баланс между экономией и точностью
- **η (фильтрация)**: выбор зависит от баланса между риском и потенциальным улучшением точности

### Рекомендации по применению
- Для максимального улучшения точности: использовать офлайн-режим с агрессивной фильтрацией (10%)
- Для стабильности точности с экономией ресурсов: использовать онлайн-режим с консервативной стратегией (DeepConf-high)
- Для максимальной экономии ресурсов: использовать онлайн-режим с агрессивной стратегией (DeepConf-low) с мониторингом точности
