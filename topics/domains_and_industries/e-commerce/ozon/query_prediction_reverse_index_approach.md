# Query Prediction в Ozon: Отказ от ANN в пользу обратного индекса

## Обзор

Статья описывает технологию Query Prediction (QP), применяемую в Ozon, где компания отказывается от традиционных ANN (Approximate Nearest Neighbor) в пользу подхода с обратным индексом. Это радикальное изменение подхода к предсказанию поисковых запросов, позволяющее достичь значительного улучшения в производительности и качестве.

## Контекст проблемы

Традиционно задача поиска ближайших соседей решается с помощью ANN (Approximate Nearest Neighbor). В контексте Query Prediction для эмбеддинга запроса пользователя находятся k ближайших соседей из истории запросов, чтобы предложить релевантные альтернативы или предложения. Однако эта задача может быть сформулирована как задача текстового поиска, что позволяет использовать более эффективные подходы.

## Подходы к решению

### Text Search History (TSH)

Первый подход, использованный в Ozon, состоял в том, чтобы рассматривать историю поисковых запросов как корпус документов (аналогично Wikipedia), а текущий запрос пользователя - как поисковый запрос (аналогично запросам пользователей Google). 

Для этого:
- История запросов токенизируется с использованием WordPiece
- Создается TF-IDF представление для запросов
- Используется BM25 для определения релевантных запросов из истории

TSH показал хорошее качество, но имел ограничения:
- Качество было ограничено качеством токенизации
- Не учитывал семантическую близость
- Не поддерживал zero-shot сценарии

### Обратный индекс

Второй подход, который стал основным, основан на обратном индексе. Вместо векторного поиска, Ozon строит обратный индекс для каждого слова в истории запросов. Это позволяет находить релевантные запросы, даже если они используют немного другую лексику.

#### Преимущества обратного индекса:

1. **Качество**:
   - Дает релевантные результаты даже по частичному совпадению
   - Работает в zero-shot сценариях
   - Лучше справляется с опечатками и орфографическими ошибками
   - Более стабильное качество для разных языков

2. **Производительность**:
   - Скорость поиска не зависит от размера корпуса
   - Скорость поиска зависит только от длины запроса пользователя
   - Возможность эффективной индексации с использованием posting lists

### ANN vs GPU KNN

Также рассмотрен подход с использованием ANN (Approximate Nearest Neighbor), где запросы эмбеддятся в векторное пространство с помощью Siamese BERT модели, и затем происходит поиск ближайших соседей. 

Плюсы:
- Позволяет находить семантически близкие запросы
- Обрабатывает опечатки при использовании словарных эмбеддингов

Минусы:
- Требует больших вычислительных ресурсов
- Зависит от размера корпуса
- Не работает в zero-shot сценариях для новых слов

## Архитектура Query Prediction

В Query Prediction (QP) используется:
1. История запросов пользователей
2. Модель для агрегации поведения пользователей
3. Модель для генерации кандидатов и их ранжирования

### Модель агрегации

Модель агрегации принимает на вход:
- Историю запросов
- Кандидаты, сгенерированные на этапе поиска

Функция агрегации определяет, насколько часто пользователь переходит на тот или иной товар/категорию после определенного запроса:
$$agg(candidate, history) = \sum_{h_i, h_{i+1} \in history} f(h_i, h_{i+1}, candidate)$$

Где $f$ - это:
$$f(h_i, h_{i+1}, candidate) = \frac{exp(\alpha \cdot sim(h_{i+1}, candidate))}{exp(\alpha \cdot sim(h_{i+1}, candidate)) + exp(\alpha \cdot sim(h_{i+1}, h_i))}$$

Alpha - гиперпараметр, контролирующий "агрессивность" агрегации.

### Визуализации и анализ

Статья содержит несколько визуализаций:
- t-SNE визуализация эмбеддингов запросов (показывает, что похожие запросы группируются)
- Визуализация обратного индекса (иллюстрирует, как строится индекс и как происходят поисковые запросы)
- Сравнение результатов разных подходов

## Метрики и оценка

Для оценки качества QP используются метрики:
- Memory consumption (количество памяти, необходимое для хранения модели)
- Hit rate@N (доля запросов, для которых хотя бы один топ-N продукт был посещен пользователем)

Результаты показали, что обратный индекс превосходит другие методы по соотношению качества и производительности.

## Результаты экспериментов

### Память
- ANN: O(N) - линейно зависит от количества запросов
- GPU KNN: O(N) - требует хранения всех эмбеддингов
- Обратный индекс: O(N) - но с гораздо меньшей константой

### Время инференса
- ANN: O(log N) - логарифмически зависит от размера корпуса
- GPU KNN: O(N) - линейно зависит от размера корпуса
- Обратный индекс: O(L) - зависит от длины запроса (L), не зависит от размера корпуса

## Заключение

Подход с использованием обратного индекса в Query Prediction показал превосходство по сравнению с традиционными ANN методами. Он обеспечивает:
- Более стабильное качество
- Лучшую производительность
- Возможности для zero-shot сценариев
- Более простую интерпретацию результатов
