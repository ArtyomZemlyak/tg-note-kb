# Управление движением гуманоидных роботов (Humanoid Motion Control)

## Краткое описание

**Управление движением гуманоидных роботов** — это область робототехники, фокусирующаяся на создании алгоритмов и систем управления, позволяющих гуманоидным роботам выполнять разнообразные динамические движения с высокой точностью отслеживания референсных траекторий. Ключевая проблема — преодоление компромисса между разнообразием движений и точностью их выполнения, особенно для высокодинамичных движений (прыжки, сальто, акробатика).

## Основная проблема: Барьер общности (Generality Barrier)

Современные системы управления гуманоидными роботами сталкиваются с фундаментальной проблемой: при масштабировании библиотеки движений (бег, прыжки, акробатика, восстановление после падений) точность отслеживания любого отдельного движения неизбежно снижается. Этот компромисс между **разнообразием движений** (motion diversity) и **точностью отслеживания** (tracking fidelity) особенно выражен для высокодинамичных движений, где даже небольшие ошибки могут быстро привести к катастрофическим сбоям.

### Причины проблемы

1. **Бутылочное горлышко обучения (Learning Bottleneck)**:
   - **Ограничения представления**: Большинство подходов используют простые параметризации политик (MLP), которые имеют ограниченную масштабируемость при росте разнообразия данных
   - **Интерференция градиентов**: Совместное обучение единой политики на множестве движений с помощью RL усиливает интерференцию градиентов, приводя к консервативному «усреднённому» поведению и сбоям на высокодинамичных движениях

2. **Бутылочное горлышко физической исполнимости (Physical Executability Bottleneck)**:
   - Даже при достижении высокой точности в симуляции, перенос на физических роботов остаётся сложным
   - Упрощённые модели актуаторов (только ограничения по позиции и усилию) недостаточны для высокодинамичных движений
   - Немоделируемые нелинейности актуаторов: характеристики крутящий момент-скорость, потери крутящего момента в зависимости от скорости, регенеративные эффекты мощности

## OmniXtreme: Прорыв в управлении гуманоидными роботами

**OmniXtreme** — это масштабируемый фреймворк для высококачественного отслеживания движений гуманоидных роботов, явно решающий проблему компромисса между разнообразием и точностью.

### Ключевые инновации

1. **Двухэтапная архитектура обучения**:
   - Разделение общего обучения моторным навыкам и физического уточнения навыков для sim-to-real переноса
   - Использование flow-matching политики с высокоёмкими архитектурами для масштабирования без интерференции
   - Actuation-aware фаза уточнения для обеспечения робастной работы на физических роботах

2. **Специалист-к-унифицированному генеративное предобучение**:
   - Дистилляция разнообразных экспертных поведений из коллекции motion-specific экспертных политик в единую базовую политику
   - Использование flow matching с DAgger для агрегации motion priors от разных экспертов
   - Избегание interference-heavy multi-motion RL оптимизации

3. **Actuation-aware пост-обучение**:
   - Residual RL уточнение замороженной базовой политики
   - Реалистичные ограничения актуаторов: агрессивная domain randomization, penalties на негативную механическую мощность
   - Power-Safe Actuation Regularization: явный penalty на чрезмерную негативную мощность для предотвращения агрессивного моторного торможения

### Архитектура OmniXtreme

```
┌─────────────────────────────────────────────────────────────┐
│  ЭТАП 1: Scalable Flow-based Pretraining                    │
│  ─────────────────────────────────────────────────────────  │
│  • Коллекция экспертных политик π_expert для каждого движения│
│  • Flow-matching политика π_θ обучается через DAgger        │
│  • Агрегация motion priors от разных экспертов              │
│  • Conservative domain randomization                        │
└─────────────────────────────────────────────────────────────┘
                            ↓
                    (Замороженная базовая политика)
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  ЭТАП 2: Actuation-Aware Post-training                      │
│  ─────────────────────────────────────────────────────────  │
│  • Residual политика π_φ обучается поверх замороженной π_θ │
│  • Действие: a = a_flow + a_res                             │
│  • Aggressive domain randomization (до 50% увеличение)      │
│  • Power-Safe regularization: penalty на P = τ·ω < 0       │
│  • Terrain randomization, relaxed termination thresholds    │
└─────────────────────────────────────────────────────────────┘
                            ↓
              Real-time onboard deployment
```

### Технические детали

#### Пространство наблюдений
- **Проприоцепция (p)**: позиции и скорости суставов, угловые скорости базы, предыдущие действия
- **Команды (c)**: 6D разница ориентации торса, целевые позиции и скорости суставов из референсного движения
- **История (h)**: прошлые проприоцептивные состояния

#### Источники данных для обучения
- Unitree-retargeted LAFAN1 dataset
- AMASS (motion capture dataset)
- MimicKit
- Reallusion motion library

### Демонстрируемые поведения

OmniXtreme успешно выполняет на реальном роботе Unitree G1:

- **Акробатика**: сальто (back handspring, Webster flips), aerial cartwheel
- **Брейк-данс**: Thomas flare, backspin, freeze позиции
- **Боевые искусства**: butterfly kicks, spin kicks, bicycle kick flips
- **Баланс**: pistol squats, handstand walk
- **Восстановление**: knock out recovery, roll-flip combos
- **Другие**: push-ups, crawl forward/backward, pivot через hand-to-headstand

### Результаты

- **Высокая точность отслеживания** на разнообразных высокодинамичных датасетах
- **Физическая исполнимость** на реальном роботе Unitree G1
- **Единая унифицированная политика** для всего спектра движений
- **Преодоление fidelity-scalability trade-off**: точность не снижается при масштабировании разнообразия

## Методы обучения

### Flow Matching для робототехники

Flow matching — это генеративный подход, который обучает velocity field для трансформации шума в целевое распределение действий.

**Формулировка**:
- Noised action: `a_t = (1-t) * a_expert + t * ε`, где `ε ~ N(0, I)`, `t ∈ [0, 1]`
- Objective: обучение velocity field `v_θ(a_t, t, o)` для предсказания target velocity `u = ε - a_expert`
- Timestep sampling: `t ~ Beta(α, β)` для фокусировки на специфических регионах probability path
- Inference: интеграция `v_θ` от `t=1` до `t=0` через forward Euler rule с `D` шагами

### DAgger (Dataset Aggregation)

Итеративный алгоритм для дистилляции экспертных политик:
1. Rollout текущей политики в симуляторе
2. Сбор траекторий посещённых состояний
3. Query экспертной политики для получения действий
4. Обучение политики на агрегированных данных
5. Повторение для новой итерации

### Residual Policy Learning

- **Базовая политика** (π_θ): замороженная flow-matching политика из предобучения
- **Residual политика** (π_φ): lightweight MLP, обучаемая через PPO
- **Итоговое действие**: `a = a_flow + a_res`
- **Observation для residual**: проприоцепция, команды, текущее базовое действие `a_flow`
