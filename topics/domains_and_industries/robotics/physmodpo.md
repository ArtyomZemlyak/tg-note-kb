# PhysMoDPO: Физически-правдоподобное движение гуманоидов с оптимизацией предпочтений

## Краткое описание

**PhysMoDPO** (Physically-Plausible Humanoid Motion with Preference Optimization) — это фреймворк прямой оптимизации предпочтений (Direct Preference Optimization, DPO) для генерации физически-правдоподобного движения гуманоидных роботов на основе текстовых инструкций. PhysMoDPO решает проблему разрыва между диффузионной генерацией движений и исполняемыми траекториями роботов, интегрируя контроллер всего тела (Whole-Body Controller, WBC) непосредственно в процесс обучения.

**Ключевая идея**: Вместо использования ручных эвристик для физики (например, штрафов за скольжение ног), PhysMoDPO интегрирует WBC в конвейер обучения и оптимизирует диффузионную модель так, чтобы выход WBC соответствовал как физическим ограничениям, так и исходным текстовым инструкциям.

## Основная проблема

### Разрыв между кинематической и физической исполнимостью

Современные модели генерации движения на основе диффузионных моделей обучаются и оцениваются в **кинематическом пространстве**, где производительность оценивается по:
- Распределительному сходству с данными
- Выравниванию с условным сигналом (текстом)

Однако для робототехники требуются движения, которые остаются **исполнимыми в физических симуляторах**:
- Стопы не должны скользить
- Центр масс должен оставаться в зоне поддержки
- Движения должны удовлетворять ограничениям динамики и контактов

### Проблема Whole-Body Controller (WBC)

Когда сгенерированное движение выполняется через WBC в симуляции (стандартная стратегия в управлении гуманоидами), контроллер может **значительно изменить** неправдоподобное движение для удовлетворения физических ограничений. Это создаёт расхождение между тем, что генерирует модель, и тем, что фактически реализуется в симуляции.

**Результат**: Модель, которая хорошо работает по кинематическим метрикам, может быть ненадёжной для воплощённого развёртывания.

## Решение PhysMoDPO

### Архитектура и методология

PhysMoDPO — это физически-ориентированный пост-тренировочный фреймворк для диффузионных генераторов движений.

```
┌─────────────────────────────────────────────────────────────────┐
│  Конвейер PhysMoDPO                                             │
│  ─────────────────────────────────────────────────────────────  │
│                                                                  │
│  1. Генерация кандидатов:                                       │
│     Для условия C (текст + опционально пространственные цели)   │
│     Сэмплируем K кинематических движений X₁...Xₖ из G_θ        │
│                                                                  │
│  2. Физическая проекция (WBC):                                  │
│     T: Xₖ → X'ₖ (симулированная траектория)                     │
│     Фиксированная физическая политика (DeepMimic)               │
│                                                                  │
│  3. Вычисление наград:                                          │
│     • Физические награды: R_track, R_slide                      │
│     • Задачные награды: R_M2T, R_control                        │
│                                                                  │
│  4. Построение пар предпочтений:                                │
│     (X_win, X_lose) где R(X'_win) > R(X'_lose)                 │
│                                                                  │
│  5. DPO дообучение:                                             │
│     L = L_DPO(X_win, X_lose) + λ_SFT * L_SFT(X_win)            │
│                                                                  │
│  6. Итеративное повторение (опционально)                        │
└─────────────────────────────────────────────────────────────────┘
```

### Физически-осознанное пост-обучение

**Цель**: Дообучить генератор G для создания кинематических движений, которые хорошо переносятся в симуляцию после применения T.

Поскольку дифференцирование через T сложно, используется **пост-обучение на основе предпочтений** с DPO:

1. **Генерация кандидатов**: Для каждого условия C сэмплируется K кандидатов
2. **Реализация в симуляции**: Каждый кандидат реализуется через WBC
3. **Оценка**: Вычисляется физически-осознанная награда R
4. **Пары предпочтений**: Выбирается пара (X_win, X_lose) где X_win лучше по R
5. **DPO оптимизация**: Стандартный DPO objective + SFT стабилизация

**Формулировка**:
```
L_total = L_DPO(X_win, X_lose) + λ_SFT * L_SFT(X_win)
```

где:
- `L_DPO` — стандартный DPO loss для обучения генерации движений как X_win чаще и как X_lose реже
- `L_SFT` — supervised fine-tuning на выигрышных сэмплах для сохранения генеративных способностей
- `λ_SFT` — баланс между обучением предпочтениям и стабилизацией

### Стратегия наград

PhysMoDPO использует **комбинацию наград** для достижения оптимальной производительности:

#### Физические награды

1. **R_track (награда отслеживания)**:
   - Минимизирует разницу между X и X'
   - Обеспечивает минимальную коррекцию от WBC

2. **R_slide (анти-скольжение)**:
   - Штрафует микро-скольжение стоп
   - Вычисляется через высоту стопы h_feet и горизонтальную скорость v_xy_feet
   - Предотвращает нереалистичные паттерны контактов

#### Задачные награды

3. **R_M2T (Motion-to-Text alignment)**:
   - Использует TMR (Text-Motion Retrieval)
   - Минимизирует косинусную разницу между закодированным движением и текстовым описанием
   - Сохраняет выравнивание с текстовой инструкцией

4. **R_control (пространственный контроль)**:
   - Для задач с пространственными целями C_s
   - Награждает соответствие целевым траекториям суставов

#### Правило доминирования

Комбинирование наград происходит через **правило доминирования**:
- Движение X'_k предпочитается X'_l если оно улучшает **каждый** член награды
- Это сохраняет сигнал предпочтений согласованным без чувствительных весов наград

## Технические детали

### Представление движений

- **SMPL-based формат**: Используется для избежания дорогостоящего inverse kinematics
- **Joint rotations**: Вращения суставов SMPL и соответствующие кинематические признаки
- **WBC реализация**: Фиксированный предобученный трекер DeepMimic

### Датасеты

- **HumanML3D**: Основной датасет для генерации пар предпочтений DPO
- **OMOMO**: Out-of-distribution тест (human-object interaction)
- **Фильтрация**: Исключаются движения, требующие поддержки объектов (например, "подняться по лестнице")

### Метрики оценки

Оценка производится **после WBC трекинга** в симуляции:

| Метрика | Описание | Направление |
|---------|----------|-------------|
| **MM-Dist** | Multi-Modal Distance (текст-движение) | ↓ меньше лучше |
| **R@1, R@2, R@3** | Top-k retrieved accuracy | ↑ больше лучше |
| **FID** | Frechet Inception Distance (распределение) | ↓ меньше лучше |
| **Jerk** | Плавность движения | ↓ меньше лучше |
| **Err.** | Ошибка отслеживания (для spatial control) | ↓ меньше лучше |

## Результаты экспериментов

### Text-to-Motion (HumanML3D)

| Метод | M2T ↑ | R@1 ↑ | R@2 ↑ | R@3 ↑ | FID ↓ | Jerk ↓ |
|-------|-------|-------|-------|-------|-------|--------|
| Real after simulation | 16.02 | 0.6682 | 0.8326 | 0.8952 | 34.07 | 35.87 |
| MaskedMimic | 19.73 | 0.4134 | 0.5568 | 0.6305 | 73.79 | 66.08 |
| MotionStreamer | 17.17 | 0.5829 | 0.7510 | 0.8310 | 49.14 | 46.75 |
| SFT | 17.23 | 0.5779 | 0.7651 | 0.8355 | 49.22 | 48.30 |
| **PhysMoDPO** | **16.95** | **0.5853** | **0.7726** | **0.8517** | **48.29** | **43.60** |

### Spatial-Text Control (HumanML3D и OMOMO)

PhysMoDPO превосходит OmniControl и MaskedMimic по всем метрикам на обоих датасетах, демонстрируя **универсальность** и **способность к обобщению**.

### Zero-Shot перенос на реальных роботов

- **Unitree G1**: Успешное выполнение боксёрских движений и работы ног
- **Unitree H1**: Демонстрация физически-правдоподобных движений
- **Без дополнительной доработки**: Движения развёртываются напрямую

| Категория | Метод | Подход | Без test-time opt. | Без доп. модулей | Dynamics-aware reward |
|-----------|-------|--------|-------------------|------------------|----------------------|
| **Constraints/Projection** | Li et al., PhysPT, PhysDiff | Optimization/Projection | ✗/✓ | ✓/✗ | - |
| **Rewards/Finetune** | ReinDiffuse, HY-Motion 1.0 | PPO/GRPO | ✓ | ✓ | ✗ |
| **Rewards/Finetune** | Morph | Data refinement | ✓ | ✗ | - |
| **PhysMoDPO** | **Наш метод** | **DPO** | **✓** | **✓** | **✓** |

**Ключевые преимущества PhysMoDPO**:
- ✅ Не требует test-time оптимизации
- ✅ Не требует дополнительных обучаемых модулей
- ✅ Использует dynamics-aware награды через WBC
- ✅ Прямая оптимизация через DPO вместо RL (PPO/GRPO)
