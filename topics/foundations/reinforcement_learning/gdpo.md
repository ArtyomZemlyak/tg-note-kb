# GDPO: Group Reward-Decoupled Normalization Policy Optimization

## Общее описание

GDPO (Group reward-Decoupled Normalization Policy Optimization) - это новый метод оптимизации политики в многонаградном обучении с подкреплением (multi-reward reinforcement learning), разработанный для решения проблем с нормализацией в существующих подходах, таких как Group Relative Policy Optimization (GRPO). GDPO был предложен исследователями из NVIDIA и продемонстрировал превосходную производительность в задачах вызова инструментов, математического и кодового мышления по сравнению с традиционным GRPO.

## Проблема с GRPO в многонаградном обучении

В многонаградном обучении с подкреплением возникает проблема коллапса нормализации награды при использовании GRPO. GRPO выполняет групповую нормализацию по суммированным общим наградам, что приводит к схлопыванию различных комбинаций наград в одинаковые значения преимущества после нормализации. Это приводит к следующим проблемам:

- **Потеря информации**: Различные конфигурации наград отображаются в одинаковый сигнал преимущества, теряя разрешение обучающего сигнала
- **Субоптимальная сходимость**: Результатом являются неточные обновления политики и субоптимальная сходимость
- **Преждевременный сбой обучения**: В некоторых случаях может возникнуть преждевременный сбой обучения
- **Проблема "сжатия сигнала награды"**: GRPO сжимает сигнал награды, вызывая потерю информации в оценках преимущества

## Методология GDPO

### Основной принцип

GDPO решает указанные проблемы за счет **декомпозиции нормализации** отдельных наград. В отличие от GRPO, который сначала суммирует все компоненты награды, а затем применяет нормализацию, GDPO:

1. **Выполняет групповую нормализацию для каждой награды отдельно**:
   ```
   Advantage_i = (reward_i - mean(rewards_i)) / std(rewards_i)
   ```

2. **Агрегирует нормализованные преимущества**:
   ```
   Total_Advantage = sum(Advantage_i) для всех i
   ```

3. **Применяет пакетную нормализацию преимуществ**:
   ```
   Final_Advantage = (Total_Advantage - batch_mean) / batch_std
   ```

### Ключевая инновация

- **Изменение порядка**: GDPO нормализует сначала, затем агрегирует (в отличие от GRPO, который агрегирует сначала, затем нормализует)
- **Сохранение информации**: Каждое измерение награды сохраняет информацию о своем относительном распределении
- **Раздельная нормализация**: Каждый компонент награды подвергается нормализации отдельно, что позволяет лучше сохранить различия между различными комбинациями наград

## Преимущества GDPO

### 1. Повышенная информационная точность
- Отличает ситуации "удовлетворение всех целей" и "удовлетворение частичных целей"
- Обеспечивает более дробные градиентные сигналы по сравнению с GRPO
- Более различимые группы значений преимущества по мере увеличения количества роллов или измерений награды

### 2. Численная стабильность
- Пакетная нормализация сохраняет значения окончательных преимуществ в диапазоне около 0±1
- Делает гиперпараметры нечувствительными к количеству добавляемых наград
- Предотвращает взрыв градиентов/исчезновение из-за больших значений диапазона

### 3. Сопротивляемость "хакингу наград"
- Решает проблему дисбаланса сложности между различными компонентами награды
- Рекомендуемый механизм условных наград: награды за простые задачи предоставляются только при достижении сложных задач

## Экспериментальные результаты

### Задача вызова инструментов
- Улучшение формальной точности до ~82% по сравнению с ~81% для GRPO (Qwen2.5-3B)
- Лучшее соблюдение форматных ограничений

### Математическое мышление
- Повышение точности на 2.9% на наборе данных AIME (DeepSeek-R1-7B)
- Снижение процента нарушения ограничения по длине с 2.1% до 0.2%
- Избегание коллапса обучения GRPO после ~400 шагов

### Кодовое мышление (три объекта)
- Сохранение аналогичных коэффициентов прохождения при снижении процента ошибок (30.0%→28.0%)
- Значительно улучшено соблюдение ограничения длины (14.7%→10.6%)

## Реализация и применение

GDPO является заменой GRPO в существующих фреймворках RL (verl, TRL, NeMo-RL) с минимальными изменениями кода. Метод позволяет проводить быструю проверку на задачах вызова инструментов и математического мышления.

## Сравнение с альтернативными методами

### GRPO без нормализации стандартного отклонения
Хотя удаление нормализации стандартного отклонения в GRPO немного увеличивает количество различных групп преимуществ, эксперименты показывают, что этот подход может привести к нестабильности обучения, которая в конечном итоге может предотвратить успешную сходимость в многонаградном обучении с подкреплением.

### DRPO и другие варианты
DRPO (Decoupled Reward Policy Optimization) и другие методы также стремятся решить проблемы с нормализацией наград, но GDPO предлагает более фундаментальный подход к раздельной нормализации, который лучше сохраняет информацию о различиях между наградами.

## Влияние на настройку приоритетов наград

GDPO также позволяет более эффективно работать с различными приоритетами наград:

- **Условные награды**: Простые награды предоставляются только при достижении сложных задач
- **Более предсказуемое поведение**: После смягчения дисбаланса сложности изменение весов награды приводит к более предсказуемым результатам
- **Лучшая настройка предпочтений**: Позволяет более точно отражать тонкие корректировки предпочтений
