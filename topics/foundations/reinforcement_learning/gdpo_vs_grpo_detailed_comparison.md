# GDPO vs GRPO: Глубокое сравнение для многонаградного RL

## Введение

GDPO (Group reward-Decoupled Normalization Policy Optimization) представляет собой новаторский подход к решению проблемы "схлопывания сигнала награды" в популярном методе GRPO (Group Relative Policy Optimization) при обучении с несколькими наградами. В то время как GRPO был эффективен для одиночной скалярной награды, авторы из NVIDIA выявили критический недостаток в его работе при многокомпонентных задачах, что привело к разработке GDPO.

## Проблема с GRPO в многонаградном обучении

### Суть проблемы

GRPO был разработан как эффективная альтернатива PPO, исключив потребность в модели ценности за счет использования оценки относительного преимущества группы для обновления политики. Однако при экстраполяции GRPO на многонаградное обучение возникает фундаментальная проблема.

### Математическая основа проблемы

Формально, для заданной пары вопрос-ответ (q_i, o_j), где политика поведения π_θ_old генерирует группу из G ответов {o_j}_G^{j=1}, и при наличии n целей, агрегированная награда для j-го ответа вычисляется как сумма всех компонентов награды:

r_sum = w_1*r_1 + w_2*r_2 + ... + w_n*r_n

Групповое относительное преимущество для j-го ответа затем получается путем нормализации совокупных наград группы:

A_{sum}^{(i,j)} = (r_{sum}^{(i,j)} - mean({r_{sum}^{(i,k)}}))/std({r_{sum}^{(i,k)}})

### Проблема "схлопывания"

Этот подход приводит к критическому явлению схлопывания награды, при котором различные комбинации наград отображаются в идентичные значения преимущества. Например, в сценарии с двумя бинарными наградами r_1, r_2 ∈ {0, 1}, где всего может быть от 0 до 2 общей награды за каждый ролл, GRPO создает только 2 уникальные группы преимуществ:
- (0,1), (0,2) и (1,2) дают одинаковые нормализованные преимущества (-0.7071, 0.7071)
- (0,0), (1,1) и (2,2) все приводят к (0, 0)

## Методология GDPO

### Основной принцип

GDPO решает указанную проблему за счет **декомпозиции нормализации** отдельных наград. В отличие от GRPO, который сначала суммирует все компоненты награды, а затем применяет нормализацию, GDPO:

1. **Выполняет групповую нормализацию для каждой награды отдельно**:
   ```
   A_i^{(k)} = (r_i^{(k)} - mean({r_j^{(k)}})) / std({r_j^{(k)}})
   ```
   
2. **Агрегирует нормализованные преимущества**:
   ```
   A_sum = sum_k A_i^{(k)}
   ```

3. **Применяет пакетную нормализацию преимуществ**:
   ```
   A_final = (A_sum - batch_mean) / batch_std
   ```

### Ключевая инновация

- **Изменение порядка**: GDPO нормализует сначала, затем агрегирует (в отличие от GRPO, который агрегирует сначала, затем нормализует)
- **Сохранение информации**: Каждое измерение награды сохраняет информацию о своем относительном распределении
- **Раздельная нормализация**: Каждый компонент награды подвергается нормализации отдельно, что позволяет лучше сохранить различия между различными комбинациями наград

## Стабильность обучения

### Проблемы GRPO
1. **Ранний коллапс обучения**: GRPO показывает признаки нестабильности после ~400 шагов тренировки
2. **Снижение точности**: GRPO показывает постепенное снижение оценки корректности
3. **Нарушение ограничений**: GRPO начинает нарушать ограничения по длине ответа

### Преимущества GDPO
1. **Стабильность**: GDPO продолжает улучшать оценку корректности на протяжении всего процесса обучения
2. **Контроль длины**: GDPO лучше контролирует максимальную длину ответа
3. **Устойчивость к коллапсу**: GDPO избегает коллапса обучения, наблюдаемого у GRPO

## Количество различных групп преимуществ

GDPO значительно превосходит GRPO по количеству различных групп преимуществ:
- **При увеличении числа роллов**: GDPO сохраняет значительно большее количество различных групп преимуществ по сравнению с GRPO
- **При увеличении числа наград**: GDPO демонстрирует прогрессивно более высокую детализацию преимущества по мере роста количества целей

## Влияние на настройку приоритетов наград

### Проблемы с весами наград для GRPO
- При использовании GRPO простая настройка весов наград часто неэффективна
- Если одна цель гораздо сложнее других, модель часто фокусируется на легкой цели независимо от назначенных весов
- Для компенсации разницы в сложности требуется чрезмерно большое различие в весах

### Решение с условными наградами в GDPO
- **Условные награды**: Более сложные награды становятся доступны только при достижении более простых целей
- **Формула**: r_len = 1 тогда и только тогда, когда len <= L И r_acc = 1
- **Более предсказуемое поведение**: После смягчения дисбаланса сложности изменение весов награды приводит к более предсказуемым результатам
- **Лучшая настройка предпочтений**: Позволяет более точно отражать тонкие корректировки предпочтений

## Выводы

GDPO выглядит как необходимое взросление фреймворка GRPO. Для перехода от простого SFT к сложной многомерной настройке ("рассуждай верно, будь краток, используй JSON и соблюдай безопасность") - математические упрощения стандартного GRPO становятся опасными. Строгое разделение нормализации гарантирует, что богатая информация из разных сигналов не потеряется при обновлении весов. Для тех, кто обучает рассуждающие модели со строгими ограничениями, GDPO - новый дефолтный выбор.
