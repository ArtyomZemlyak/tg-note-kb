# Использование эмбеддингов для поиска проблемных запросов

## Краткое описание

Статья описывает метод поиска проблемных поисковых запросов с помощью векторных эмбеддингов и косинусного сходства. Подход позволяет находить пары похожих по смыслу запросов с разной конверсией, что указывает на потенциальные проблемы в работе поисковой системы.

## Обоснование подхода

Если по двум похожим запросам (например, «свадебное платье» и «платье на роспись») сильно отличается конверсия в клик или корзину — это явный сигнал о проблеме. Такой сравнительный анализ помогает выявлять ошибки ранжирования, поломки правил словаря и перекосы в ассортименте.

## Техническая реализация

Для каждого из проблемных запросов с помощью близости в пространстве эмбеддингов находятся топ-N ближайших соседей по косинусному расстоянию, то есть запросы с почти одинаковым смыслом, но при этом с высокой конверсией.

Для получения эмбеддингов используется та же модель, что отвечает за семантический поиск на сайте — дообученный би-энкодер. Идея в том, что если два запроса очень похожи по смыслу, но один работает хорошо, а другой нет, значит, возможно, где-то возникла проблема — в нормализации, подборе синонимов или в работе опечаточника.

## Основные задачи, решаемые подходом

### 1. Нахождение частых опечаток и транслитераций

С помощью этого подхода были найдены случаи, которые текущий опечаточник еще не умеет детектировать:
- victoria vicci -> vittoria vicci
- канцлер -> kanzler
- асиксы -> asics и другие

Эти кейсы были добавлены в словари вручную, улучшив качество поиска по брендам.

### 2. Обогащение словарей синонимов и коллекций

Были найдены слова и признаки, которых раньше не было в базе знаний. Примеры:
- Пользователи часто ищут вещи изумрудного и молочного цвета, которые не работали в поиске до этого.
- Сумка the tote bag — это конкретная коллекция бренда Marc Jacobs.

## Преимущества метода

1. **Без инвестиций в разметку** - метод работает на основе имеющихся данных о конверсии и векторного сходства
2. **Масштабируемость** - способен обрабатывать большой объем запросов
3. **Автоматизация потенциально возможна** - подход поддается автоматизации и может стать частью регулярной рутины
4. **Выявление скрытых проблем** - позволяет находить проблемы, которые не очевидны при анализе отдельных метрик

## Примеры выявленных проблем

Подход помогает находить следующие типы проблем:
- Проблемы в нормализации запросов
- Недостатки в модуле опечаточника
- Проблемы с подбором синонимов
- Ошибки в атрибуции товаров
- Недостатки в семантическом поиске

## Интеграция в процесс улучшения поиска

Раз в неделю команда проводит оценку качества поиска, где с помощью всех описанных инструментов (включая эмбеддинги) находятся проблемы и исправляются. Изменения могут включать:
- Добавление новых брендов и их вариантов написания
- Расширение списка синонимов
- Настройка модуля-опечаточника
- Дебаг проблемных запросов
- Добавление новых атрибутов товарам
- Улучшение ранжирования
- Улучшение модели семантического поиска

## Сравнение с другими методами

По сравнению с:
- Количественными метриками: позволяет увидеть контекстуальные проблемы, где один запрос работает, а похожий - нет
- Фидбэком пользователей: охватывает все запросы, а не только те, где пользователи оставили отзыв
- LLM-разметкой: работает на основе реального поведения пользователей, а не теоретической релевантности

## Потенциальные ограничения

1. **Требует качественной модели эмбеддингов** - если модель плохо определяет сходство запросов, результаты будут неэффективны
2. **Зависит от данных поведения** - необходима достаточная статистика по конверсиям и взаимодействиям
3. **Возможны ложные срабатывания** - не каждый схожий запрос должен вести себя одинаково

## Перспективы автоматизации

Команда активно работает над тем, чтобы максимально автоматизировать этот процесс и сделать его частью стандартной рутины по улучшению поиска. Это включает:
- Регулярный анализ похожих запросов
- Автоматическое выявление аномалий
- Интеграцию с системой приоритизации задач

## Связь с общей архитектурой поиска

Метод встраивается в общую архитектуру оценки качества поиска, которая включает:
- Количественные метрики
- Пользовательский фидбэк
- LLM-разметку
- Сравнение похожих запросов (наша тема)
