# KernelBench: Бенчмарк для оценки способности LLM писать эффективные GPU-ядра

## Краткое описание

KernelBench - это фреймворк с открытым исходным кодом для оценки способности языковых моделей (LM) генерировать быстрые и корректные GPU-ядра на наборе из 250 тщательно подобранных ML-рабочих нагрузок PyTorch. KernelBench представляет реальную инженерную среду, и прогресс в решении представленного бенчмарка напрямую переводится в более быстрые практические ядра.

## Основная информация

KernelBench был разработан для оценки способности языковых моделей автоматически генерировать эффективные GPU-ядра. Он включает широкий спектр задач машинного обучения, начиная от отдельных операций и заканчивая полными архитектурами моделей.

### Уровни сложности

#### Уровень 1 (100 задач): Отдельные примитивные операции
- Включает базовые строительные блоки ИИ (например, свертки, матрично-векторные и матрично-матричные умножения, функции потерь, активации, нормализации)
- Сложный бенчмарк, поскольку PyTorch уже использует хорошо оптимизированные и часто закрытые исходные ядра

#### Уровень 2 (100 задач): Последовательности операций
- Включает ИИ-рабочие нагрузки, содержащие несколько примитивных операций, которые можно объединить в одно ядро для улучшения производительности
- Пример: сочетание свертки, ReLU и смещения

#### Уровень 3 (50 задач): Полные архитектуры ML
- Включает архитектуры, которые используют популярные ИИ-модели
- Собраны из популярных репозиториев PyTorch на GitHub

### Метрики оценки

#### fast_p метрика
KernelBench вводит новую метрику оценки fast_p, которая измеряет процент сгенерированных ядер, которые функционально корректны и дают ускорение больше, чем заданный порог p над базовой линией.

Формула: fast_p = доля задач, которые корректны и имеют ускорение > p

Где:
- fast_0 эквивалентна уровню корректности LM, поскольку измеряет долю задач, в которых код LM функционально корректен, независимо от скорости
- p - порог ускорения (например, при p=1 измеряется доля задач, где сгенерированное ядро быстрее базовой линии PyTorch)

#### Автоматическая проверка
- Сравнение выходных тензоров с эталонной реализацией PyTorch
- Измерение времени выполнения для оценки производительности
- Оценка на 5 случайных входах на задачу

### Основные результаты исследований

#### Проблемы текущих моделей
Исследования с использованием KernelBench показали, что современные модели плохо справляются с задачами из бенчмарка:
- Модели OpenAI-o1 и DeepSeek-R1 соответствуют базовой линии PyTorch менее чем в 20% случаев
- Значительные проблемы с ошибками выполнения и функциональной корректностью
- Невозможность выполнения специфичных для платформы оптимизаций

#### Основные трудности
1. Написание функционально корректных ядер остается сложной задачей для моделей
2. CUDA - это язык с ограниченными ресурсами в открытых обучающих данных (только 0.073% в The Stack v1.2)
3. Торговля между сложными оптимизациями и корректностью кода

#### Возможности улучшения
1. Использование итеративной обратной связи значительно улучшает качество
2. Предоставление информации об оборудовании в контексте помогает модели
3. Модели показывают потенциал для создания производительных ядер через алгоритмические улучшения

## Применение в экосистеме KernelEvolve

KernelBench играет ключевую роль в системе KernelEvolve:
- Используется для проверки корректности сгенерированных Triton-ядер
- Оценка ускорения над эталонными реализациями PyTorch
- KernelEvolve достигает 100% корректности на KernelBench (все 250 задач)
- Система использует обратную связь из профайлеров и результатов выполнения для улучшения генерации ядер

### Интеграция с рабочим процессом
- Сравнение сгенерированных Triton ядер с эталонными реализациями PyTorch
- Измерение ускорения над бейзлайнами
- Автоматическая проверка точности результатов
- Интеграция с системами профилирования для получения информации о производительности
