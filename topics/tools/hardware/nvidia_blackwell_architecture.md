# Архитектура NVIDIA Blackwell

## Описание

NVIDIA Blackwell - это архитектура_GPU следующего поколения от NVIDIA, предназначенная для высокопроизводительных вычислений в области искусственного интеллекта и машинного обучения. Архитектура представляет собой значительный шаг вперед в сравнении с предыдущими архитектурами (Ampere, Hopper), особенно в контексте вычислений с низкой точностью, таких как FP4 и NVFP4.

## Ключевые особенности

### Вычислительные улучшения

1. **UMMA инструкции**: Unified Matrix Multiply-Accumulate инструкции, представляющие собой асинхронные однопоточные операции, которые устраняют давление на регистровую память в сравнении с WGMMA инструкциями Hopper.

2. **Tensor Memory (TMEM)**: Выделенная 256KB он-чип память на SM, организованная как 512 столбцов × 128 строк ячеек по 32 бита. Результаты матричного умножения хранятся непосредственно в TMEM, а не в регистрах.

3. **Двухстадийный пайплайн аккумуляторов**: Структура 512-столбцов естественным образом позволяет создать двухстадийный пайплайн аккумуляторов, где каждая стадия использует 256 столбцов.

4. **2-CTA кластеры**: Использование двух CTA (Cooperative Thread Array) для GEMM вычислений с особой координацией для обхода ограничений cp.async инструкции.

### Поддержка низкой точности

1. **Нативная поддержка NVFP4**: Прямая аппаратная поддержка 4-битных вычислений с плавающей запятой.

2. **Blackwell-специфичные CUTLASS расписания**: Такие как `KernelPtrArrayTmaWarpSpecialized1SmNvf4Sm100`, оптимизированные для NVFP4.

3. **128-байтовое выравнивание**: Требования к выравниванию тензоров для оптимальной производительности.

### Память и пропускная способность

1. **cp.async инструкции**: Используются для асинхронной загрузки данных из глобальной памяти в разделяемую память.

2. **TMA (Tensor Memory Accelerator)**: Специализированный ускоритель для работы с тензорной памятью.

3. **Оптимизация IO**: Возможность перекрытия операций ввода-вывода с вычислениями.

## Применение в MoE моделях

### Оптимизации для MoE

1. **GEMM слияние**: Возможность слияния операций GEMM с операциями загрузки/выгрузки данных.

2. **Перекрытие IO и вычислений**: Архитектура позволяет перекрывать операции ввода-вывода с вычислениями для повышения эффективности.

3. **Повышенная эффективность при малых батчах**: Архитектура особенно эффективна при работе с малыми батчами, что важно для интерактивного инференса.

### Производительность

- **Высокая TFLOPS производительность**: В тестах с NVFP4 достигается до 1262 TFLOPS в SGLang и 1225 TFLOPS в FlashInfer для MoE моделей.
- **Оптимизация для малых батчей**: Лучшая производительность по сравнению с предыдущими архитектурами при малых размерах батча.

## Сравнение с Hopper

| Характеристика | Hopper | Blackwell |
|----------------|--------|-----------|
| **Аккумуляторы** | WGMMA с давлением на регистры | UMMA асинхронные однопоточные |
| **Память для аккумуляторов** | Регистры | TMEM (512 столбцов × 128 строк) |
| **Координация MMA** | Warpgroup-уровень | Однопоточные асинхронные операции |
| **Поддержка FP4** | Ограниченная | Полноценная нативная поддержка |
| **TMA** | Присутствует | Улучшенная интеграция |

## Архитектурные ограничения и решения

### Проблема cp.async на 2-CTA кластерах

На Blackwell архитектуре cp.async инструкция, представленная с Ampere поколения, может сигнализировать о завершении только внутри одного CTA. Однако 2-CTA GEMM требует, чтобы MMA инструкция в ведущем CTA (CTA 0) ожидала завершения сбора из обоих CTA. Для обхода этого ограничения используется специальная координация между CTA.

### Пайплайн структура для слияния сборки

Особая структура пайплайна для слияния сборки с cp.async на Blackwell GPU с использованием 2-CTA кластеров позволяет достичь высокой эффективности операций.

## Применение в фреймворках

### SGLang

- Использует Blackwell-специфичные CUTLASS расписания для NVFP4
- Применяет адаптивное масштабирование сетки для максимизации загрузки SM
- Использует сливные кернелы для уменьшения количества запусков кернелов

### FlashInfer

- Использует CuteDSL для написания эффективных кернелов для Blackwell
- Применяет expert-first layout для эффективной работы с большим количеством экспертов

### vLLM

- Включает поддержку NVFP4 для оптимизации MoE инференса
- Однако менее оптимизирован по сравнению с другими фреймворками в части слияния кернелов

## Влияние на экосистему ML

### Эффективность инференса

- Значительное улучшение производительности для MoE моделей
- Повышенная эффективность при интерактивном инференсе
- Лучшее использование пропускной способности памяти

### Поддержка новых форматов

- Расширение поддержки новых форматов квантования (FP4, FP8)
- Возможность более эффективного развертывания крупных моделей

## Будущие перспективы

### Модельная архитектура Co-Design

Blackwell архитектура разработана с учетом будущих требований к модели инженерии:
- Совместная разработка архитектуры модели и GPU кернелов
- Оптимизация для архитектур MoE
- Поддержка новых форматов квантования

### Масштабирование MoE моделей

- Улучшенная поддержка для более мелкозернистых и разреженных MoE моделей
- Повышенная эффективность для моделей с большим количеством экспертов
